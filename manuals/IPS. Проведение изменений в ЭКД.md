3.3.3 Запретить пользовательские коды причины изменения
Настройка Запретить пользовательские коды причины изменения позволяет установить запрет на ввод
пользователем своего кода причины изменения, если в качестве причины выбрано значения Другое. В графе
Код будет выводиться код «-1». В графе ПРИЧИНА – причина выпуска, указанная пользователем, с
дополнительной приставкой: Другое.<Пользовательская причина>.
Настройка перечня причин и кодов, используемых в ЭИ, осуществляется через настройку допустимых
значений атрибута Причина выпуска извещения, GUID данного атрибута cad0077d-306c-11d8-b4e9-
00304f19f545.
3.3.4 Не вставлять \ в обозначение ДПИ
При активации настройки Не вставлять \ в обозначение ДПИ в значение атрибута Обозначение ДИ (ДПИ)
не будет автоматически добавляться разделитель перед указанием порядкового номера версии ДИ (ДПИ).
Например,
 Настройка активирована – «АБВ.01-2024 ДИ1».
 Настройка отключена – «АБВ.01-2024 ДИ/1».

3.3.7 Разрешить видимость всех шаблонов
Включенная настройка Разрешить видимость всех шаблонов позволяет пользователю видеть полный
перечень применяемых шаблонов бланка при создании ЭИ. По умолчанию установлено значение «Нет».
Для управления видимостью шаблонов ЭИ следует:
1. В Конфигураторе базы данных добавить атрибут Видимость объекта к типу объектов Шаблоны
извещений.
2. Для имеющихся экземпляров объектов типа Шаблон извещения настроить требуемую видимость.

10.3 Ограничения, связанные с использованием контекстов
редактирования ЭИ
Внимание! Одна и та же версия объекта может присутствовать в составе только одного контекста
редактирования ЭИ.
В составе контекста редактирования ЭИ не может присутствовать несколько версий одного и того же
объекта. При этом в состав контекста редактирования ЭИ могут быть добавлены любые версии объектов при
условии, что в любом из связанных с ним контекстов нет этих версий или других версий этих объектов.
Например, есть цепочка связанных контекстов ЭИ– К1, К2, …, Кn. Есть версии объекта – А1, А2,..., Аm.
Допускается добавлять любую из версий А (например, А1) в контексты К, если в любом из контекстов нет
другой версии А (например, А2). Указанное ограничение введено с той целью, чтобы при подборе версий в
составе не возникло неоднозначной ситуации, когда должны подобраться несколько версий одного объекта.

условий срабатывания и перечня адресатов занимается администратор системы.
В контексте процесса проведения изменений автоматические уведомления позволяют своевременно
информировать пользователя о следующих событиях:
 взятие на редактирование объектов;
 завершение редактирования объектов;
 изменение атрибутов объектов;
 перемещение на шаг ЖЦ;
 создание версии объекта;
 создание связи и др..
Внимание! Для работы автоматических уведомлений по событиям, связанным с изменением значения
атрибутов необходимо обязательно включить настройку Настройка \ Параметры IPS \ Система \ База
данных и оптимизация \ Разрешить передачу значений атрибутов в службу автоматических
уведомлений. При этом стоит учитывать, что включение данной настройки снижает производительность
системы, т.к. производятся дополнительные операции чтения атрибутов.
Подробное описание функционала автоматических уведомлений представлено в главе 7 Автоматические
уведомления в «Руководстве администратора».

16.1 Пример №1 Уведомление владельца о том, что ЭИ согласовано и
изменения по нему вступили в действие
Уведомление владельца о том, что ЭИ согласовано и изменения по нему вступили в действие, т.е.
уведомлять о переводе ЭИ на шаг ЖЦ Актуализация.
Последовательность действий:
1. Запустить процесса создания ИО типа Автоматические уведомления по команде контекстного меню
для типа объекта.
2. В открывшемся диалоге выбрать типа события Перемещение на шаг жизненного цикла для
срабатывания уведомления.

уведомления, в частности атрибут Заголовок объекта.
4. На закладке Условия срабатывания необходимо выбрать тип объекта, для которого будет срабатывать
уведомление: выбор родительского типа ИО Извещения.
5. Далее следует выбрать шага ЖЦ, перевод на который будет отслеживаться системой.

Изменяется по извещению между ЭИ и объектом типа Деталь при условии, что в атрибуте связи Цель

1. Запустить процесс создания ИО типа Автоматические уведомления.

3. На закладке Условия срабатывания необходимо ввести значений атрибутов в реквизитной части
объекта типа Автоматические уведомления, в частности атрибут Заголовок объекта.
4. Далее следует указать тип создаваемой связи, для которой будет срабатывать уведомление: выбор типа
связи Изменяется по извещению.
5. На закладке Условия срабатывания необходимо выбрать тип объекта, для которого будет срабатывать
уведомление: выбор родительского типа ИО Детали.
