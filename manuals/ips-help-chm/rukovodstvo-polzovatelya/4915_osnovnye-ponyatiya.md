# Основные понятия
В данной главе приводится описание основных терминов, которыми оперирует Intermech Professional Solutions. Знание терминологии необходимо для понимания принципов работы в системе, поэтому пользователям рекомендуется внимательно ознакомиться с данной главой. Для удобства поиска информации понятия приведены в алфавитном порядке.
| **Термин** | **Описание** |
| --- | --- |
| Архив | Архивы IPS предназначены для хранения в них объектов типа **Документы** , дошедших до определенного шага жизненного цикла или соответствующих условиям помещения в тот или иной архив. Система предоставляет возможность назначать определенные права, позволяющие ограничить доступ пользователей к документам, хранящимся в архивах. |
| Атрибуты | Атрибуты являются описательной характеристикой объекта и в своей совокупности представляют свойства объектов. Атрибуты могут быть системными, значения которых присваиваются объектам всех типов автоматически, или принадлежащими определенным типам объектов и связей, значения которых вводятся пользователями. Система позволяет вести историю значений атрибутов, записывая в журнал событий информацию об их изменениях. |
| База данных | Это объективная форма представления и организации совокупности данных, систематизированных таким образом, чтобы эти данные могли быть найдены и обработаны с помощью различных механизмов системы. |
| Версионность объектов и правила подбора версий | Это характеристика, указывающая на то, что для объекта определенного типа могут создаваться версии. Неверсионные объекты могут иметь только одну версию, которая собственно и является самим информационным объектом. Версионный объект представляет собой совокупность всех версий объекта, объединенных общим идентификатором объекта. Механизм подбора версий позволяет описать правила, которые будут использоваться для подбора в состав именно тех версий объектов, которые интересуют пользователя в данный момент. Для производства такой механизм очень важен, т.к. позволяет одновременно прорабатывать несколько вариантов изменений в конструкции, не останавливая выпуск текущей версии изделия. Подбор версий также позволяет производить поиск состава объектов на определенную дату. |
| Выборка | Это группа объектов, отобранных системой автоматически согласно определенным условиям отбора или вручную из какого-либо множества объектов. Условия отбора задаются пользователями в настройках выборки. Условия могут накладываться на любые свойства объектов. При просмотре выборки выполняются все заданные для нее условия по отбору и отображению элементов списка. |
| Журнал событий | В системе ведется журнал событий, в котором регистрируются все операции, производимые над объектами системы. Журнал событий отображается в окне **Администратор базы данных** в виде отдельного элемента. Доступ к журналу по умолчанию имеет только администратор системы, однако он может назначать права доступа и другим пользователям системы. Регистрируемые события, касающиеся определенного объекта, можно увидеть в окне **Навигатор** в карточке этого объекта на закладке **Действия над объектом**. |
| Идентификаторы | Объекты любой категории информации (информационные объекты, типы объектов, атрибуты, группы атрибутов, связи, типы связей и др.) получают при создании глобальный идентификатор, который используется системой для идентификации информации как в рамках одной базы данных, так и при синхронизации информации между различными базами данных. Это позволяет однозначно идентифицировать объект, даже если он был неоднократно перемещен из одной базы данных в другую и изменил остальные идентификационные характеристики. Кроме этого, каждый объект системы имеет локальный идентификатор. Это целочисленный идентификатор, используемый объектами различных категорий в рамках одной базы данных. При перемещении информации в другую базу данных эти идентификаторы изменяются. Именно поэтому любая информация, которая может быть перемещена между различными базами данных, имеет также и глобальный идентификатор. |
| Карточка объекта | Это метод представления объекта. Любой объект системы может быть представлен в виде карточки, на закладках которой отображается вся информация, связанная с объектом. В карточке объекта пользователь может просматривать информацию об объекте, вносить изменения в свойства объектов, просматривать файлы, прикрепленные к объектам и др. |
| Классификаторы | Это механизмы, позволяющие классифицировать, группировать и упорядочивать данные в системе по определенным тематическим признакам. Классификаторы дают возможность более эффективно работать в системе: быстро отыскивать необходимые объекты системы, облегчить и ускорить процессы создания новых объектов с присвоением им значений, указанных в формуле классификатора, осуществлять учет и стандартное обозначение объектов, используя автоматическую генерацию обозначений. |
| Конфигуратор базы данных | Это модуль расширения системы, в котором происходит создание и описание типов объектов, атрибутов, связей и т.п. По умолчанию окно конфигуратора доступно только для пользователя, входящего в систему в роли администратора, но при необходимости можно настроить доступ к конфигуратору и для других ролей. Настройка данных в конфигураторе может производиться как поставщиками IPS, так и администраторами предприятий. |
| Навигатор | Это главное окно системы, являющееся универсальным инструментом для работы с информацией и предоставляющее доступ к большинству возможностей системы. Работая в **Навигаторе** , пользователь может просматривать содержимое базы данных, совершать различные действия над объектами системы, использовать различные виды поиска, чтобы находить необходимую информацию, получать всевозможные отчеты, запускать встроенные в систему редакторы, работать с электронной почтой и многое другое. |
| Объекты и типы объектов | Система IPS позволяет представить любой материальный предмет или действие в виде информационного объекта, который характеризуется типом, набором атрибутов, содержащих характеристики этого объекта, связями с другими объектами, а также жизненным циклом. Тип объекта — основная характеристика любого информационного объекта, которая определяет его назначение, поведение, набор атрибутов, жизненный цикл. Типы объектов могут иметь иерархическое строение, где дочерние типы наследуют свойства родительских (абстрактных) типов. Это позволяет структурировать данные системы на более детальном уровне. |
| Предметные области | Предметные области позволяют разделить всю хранящуюся в системе информацию на области применения. Это позволяет упростить пользовательский интерфейс системы, ограничивая список типов объектов, связей и атрибутов той предметной областью, в которой работает пользователь. Т.е. пользователь, входя в систему в определенной роли, увидит в системе только те данные, которые относятся к предметным областям, назначенным данной роли. Например, конструктор увидит только те типы объектов, которые относятся к машиностроению (изделия, документы, материалы, проекты и т.п.). |
| Проекты | Проекты являются одной из форм организации работы в IPS. Они объединяют хранящуюся в системе информацию по определенному признаку, облегчая ее поиск и регулируя доступ к ней. Проекты позволяют полностью скрывать принадлежащие им объекты в случае, если уровень допуска вошедшего в систему пользователя не дает права их видеть. Специальный фильтр позволяет исключать из списков информацию, принадлежащую проектам, участником которых данный пользователь не является. |
| Рабочая копия объекта | Это статус, который приобретает объект, взятый на изменение пользователем. В зависимости от настроек конфигуратора объекты, находящиеся на разных шагах жизненных циклов, могут модифицироваться непосредственно в базе данных или через рабочую копию. Внесение изменений в объект через рабочую копию позволяет исключить несогласованное редактирование одного и того же объекта различными пользователями. |
| Роль | С понятием роли в IPS связаны возможности системы, к которым будет иметь доступ пользователь, зашедший в систему в определенной роли. От настроек роли зависит, какие модули расширения будут загружаться, какие закладки и команды контекстных меню будет видеть пользователь, зашедший в систему в этой роли. Кроме того, посредством ролей пользователю могут быть назначены права доступа и предметные области, в которых он работает. Роли пользователям назначает администратор системы. |
| Связи и типы связей | Это категория, устанавливающая подчиненное отношение между версией информационного объекта и другим информационным объектом, т.е. в версию объекта с идентификатором версии объекта входит объект с идентификатором объекта. Такой способ связывания позволяет оставлять без изменения связи родительского объекта при выпуске новой версии любого из дочерних объектов. Связи в IPS делятся на типы. Типы связей отличаются друг от друга допустимым набором атрибутов и способом обработки различными модулями системы. Назначаемые права доступа на различные типы связей позволяют регулировать видимость, а также возможность добавления/удаления различного рода информации к одним и тем же типам объектов. |
| Схемы поиска объектов | Схемы поиска объектов используются при поиске состава, если рассматриваются объекты со сложным составом, или применяемости, если необходимо найти объекты, в которых применяется выбранный объект. Каждая схема представляет собой набор условий, по которым формируется список искомых объектов. Схемы настраиваются разработчиками системы или администратором, однако пользователь также имеет возможность самостоятельно формировать необходимые схемы поиска. |
| Схема жизненного цикла и уровни продвижения объектов | Это графическое представление последовательности допустимых шагов жизненного цикла объектов. Каждому шагу схемы соответствует свой уровень продвижения, наделенный определенными свойствами, от настроек которых будет зависеть поведение объекта, находящегося на данном шаге жизненного цикла. Объекты системы могут иметь различные схемы жизненного цикла в зависимости от их типа. Настройка схем жизненных циклов и уровней продвижения объектов осуществляются разработчиками системы и администраторами предприятий в **Конфигураторе базы данных**. |
| Табличные отчеты | Табличные отчеты позволяют выводить на печать списки найденных объектов. Табличные отчеты — это самый простой способ получения отчетной документации. В таких отчетах пользователи могут самостоятельно настраивать набор выводимых колонок, сортировку и форматирование информации, выбирать бланк для отчета, задавать для колонок итоговые математические операции и т.д. |
| Узел информационной системы | База данных IPS предприятия или филиала предприятия, которая является частью глобальной информационной системы, обменивающихся информацией с другими базами данных через IPS WebPortal. |
| Универсальный клиент | Это клиентское приложение, в котором работает пользователь. Оно является оболочкой для всех клиентских модулей расширения информационной системы. Универсальный клиент производит подключение и авторизацию на сервере приложений, загружает в память и инициализирует модули расширения системы, производит автоматическое переподключение к серверу приложений в случае обрыва связи. Кроме того, универсальный клиент является поставщиком ряда сервисов, которые используют клиентские модули расширения: меню, панели инструментов, буфер обмена данными, панели фоновых задач и информационных сообщений, служба управления списками общих пиктограмм и т.д. |
| Формы ввода данных (пользовательские формы) | Это спроектированные и связанные с определенными пользовательскими действиями наборы компонентов ввода и отображения, которые позволяют вносить, изменять или просматривать значения связанных с ними переменных. Система IPS позволяет создавать формы для сопоставления их с различными типами объектов и связей, ролями и группами пользователей, шагами процессов документооборота, видами производства и т.п. |
| Шаблоны процессов документооборота | Шаблон процесса документооборота представляет собой схему, описывающую последовательность действий, которые должны выполнить пользователи и система для достижения цели процесса. Пользователи системы могут инициировать процессы, прикреплять к ним документы, просматривать принятые, выполненные и отправленные задания, контролировать выполнение запущенных процессов и т.д. |
| Электронная подпись | С помощью электронной подписи пользователи могут подписывать объекты системы. Каждому пользователю системы может быть назначена одна или несколько должностей, а должностям — возможность подписывать те или иные типы объектов в определенных графах. Контроль подписей в системе может производиться на нескольких уровнях: в момент присвоения объекту уровня продвижения, при переходе объекта на определенный шаг жизненного цикла и при помещении документов в архив. |
