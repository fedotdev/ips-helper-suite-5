# Диагностика системы
Страница **Настройка / Параметры IPS / Система / Диагностика системы** содержит настройки встроенной в сервер IPS службы диагностики, которая позволяет системе заблаговременно предупреждать администратора о наступлении событий, способных привести к критическим сбоям в работе IPS. Также в данном разделе размещены настройки по управлению лог-файлами серверов приложений IPS.
Уведомления службы диагностики приходят в почтовые ящики внутренней почты IPS всем пользователям, которым назначена роль Администратор. Рассылает уведомления фоновая задача **Диагностика системы** , расписание работы которой администратор должен настроить в **Планировщике задач** (см. п. ). При наличии нескольких серверов приложений задачу диагностики следует запускать только на одном из них – необходимая информация со всех серверов будет собираться данной службой через автоматические механизмы синхронизации серверов приложений IPS.
Сервера приложений IPS контролируют следующие параметры:
· **Автоматическое сохранение сведений об ошибках** – позволяет автоматически сохранять или не сохранять информацию об ошибках в системе и в безопасности. Данные об ошибках хранятся в папке ErrorsInfo, которая находится в том же месте, что и клиентский лог. 
Путь, где хранится папка ErrorsInfo, можно посмотреть в файле IMClient.exe.config по ключу LogPath.
· **Максимальное время хранения сведений об ошибках, дней** – параметр, который позволяет указать количество дней хранения файлов с информацией об ошибках.
**Внимание**! При загрузке системы происходит автоматическое удаление файлов, время хранения которых превышает заданное количество дней. А если значение параметра **Максимальное время хранения сведений об ошибках, дней** пустое или «ноль», то информационные файлы будут удалены при следующей загрузке системы IPS.
Пустое либо нулевое значение означает, что файлы с информацией об ошибках будут удалены при следующей загрузке клиента.
· **Максимальный объем физической памяти, использованной сервером приложений, МБ** – позволяет контролировать расход физической памяти сервером приложений IPS. Чрезмерный расход физической памяти может привести к выгрузке части памяти сервера на диск (т.н. свопингу), что крайне негативно скажется на производительности сервера приложений IPS, а в некоторых случаях может приводить к ошибкам Out of memory и даже падению сервера приложений. Значение задается в мегабайтах. Пустое значение говорит о том, что система не будет контролировать данный параметр. Если с базой данных работают несколько серверов приложений, то для каждого из них можно задать свой допустимый размер памяти с помощью параметра PeakMemoryUsageNotify в секции appSettings конфигурационного файла сервера. Однако этот параметр будет контролироваться только в том случае, если в общих настройках параметр имеет непустое значение. Т.е. в диалоге настройки диагностики нужно указать общее значение для всех серверов, а для отдельных серверов его затем можно переназначить с помощью конфигурационного файла.
· **Минимальный размер свободного места на диске сервера приложений, ГБ** – параметр контролирует свободное место на системном диске сервера приложений, где располагается защищенное хранилище с кэшем файлов, извлекаемых для передачи на клиентские компьютеры. Отсутствие места на данном диске приведет к отказу всех функций IPS, требующих операций чтения/записи на сервер файлов и двоичных данных. Значение задается в гигабайтах. Пустое значение говорит о том, что система не будет контролировать данный параметр.
· **Максимальный размер файлового шкафа, ГБ** – данный параметр контролирует суммарный объем файлов и двоичных данных в файловом шкафу, что позволяет администраторам заблаговременно узнать, когда необходимо расширять дисковое пространство для существующего файлового шкафа или создавать новый файловый шкаф. При задании данного параметра необходимо учесть, что реальный размер, занимаемый файловым шкафом на дисковых носителях может быть больше из-за страничной организации хранения данных в СУБД и файловой системе, а также из-за хранения различной служебной информации о файлах в шкафу. Значение параметра задается в гигабайтах. Пустое значение говорит о том, что система не будет контролировать данный параметр. При наличии нескольких файловых шкафов их предельный размер можно контролировать с помощью атрибута **Максимальный суммарный размер файлов в шкафу, ГБ** , который можно добавить файловому шкафу вручную. Однако этот атрибут будет контролироваться только в том случае, если в общих настройках параметр контроля размера файловых шкафов также имеет непустое значение.
· **Отображать подробный анализ проверки прав доступа** – параметр, включение которого позволит системе предоставить пользователю развернутый анализ проверки безопасности при возникновении ошибки.
· **Отображать технические сведения в окне сообщения об ошибке** – параметр, включение которого позволит системе предоставить пользователю развернутые технические сведения при возникновении ошибки.
Если параметр **Отображать технические сведения в окне сообщения об ошибке** отключен, то технические сведения при возникновении ошибки будут доступны посредством нажатия кнопки .
· **Сохранять дамп памяти клиента в отчеты об ошибках** – параметр, включение которого позволяет разработчикам получить больше информации о возникшей в приложении ошибке.
· **Сохранять снимки экранов в автоматические отчеты об ошибках** – параметр, включение которого позволяет создать снимки экранов мониторов пользователя в момент появления ошибки, а также автоматически добавить их в отчет об ошибке. При выключенном параметре, снимки экранов не создаются.
· **Сохранять снимки экранов в отчеты об ошибках и при создании запроса в тех.поддержку** – настройка, которая позволяет отключить режим записи скриншотов экранов в обычные отчеты об ошибках и при создании запроса в тех.поддержку. Данная настройка необходима для управления безопасностью на предприятии администратором системы IPS.
· **Тип сохраняемого дампа** – параметр, который позволяет указать тип сохраняемого дампа: **Стандартный** или **С полной памятью**.
Для контроля лог-файлов доступны следующие параметры:
· **Каталог с лог-файлами сервера приложений** – данный параметр отображает путь к каталогу с лог-файлами того сервера приложений, к которому подключен данный клиент IPS. Параметр доступен только для чтения. Изменить данное значение можно в конфигурационном файле сервера приложений (параметр LogPath в секции **< appSettings>**).
· **Количество предыдущих копий лог-файла** – задает количество предыдущих сохраненных копий каждого лог-файла после процедуры автоматического уменьшения его размера. Файлы копий архивируются и им присваиваются имена **< имя_файла.001.zip>**, **< имя_файла.002.zip>** и так далее. При этом файлы с большими номерами содержат более старые записи лог-файла, т.к. в процессе архивации производится ротация номеров архивных файлов. Если данный параметр содержит пустое значение, то при автоуменьшении лог-файла его копии не создаются.
· **Максимальный размер лог-файла** – задает максимальный размер лог-файла в мегабайтах, по достижении которого система уменьшит его размер наполовину. При этом более старые записи будут сохранены в файле **< имя_файла.001.zip>**, если задана настройка **Количество предыдущих копий лог-файла**.
