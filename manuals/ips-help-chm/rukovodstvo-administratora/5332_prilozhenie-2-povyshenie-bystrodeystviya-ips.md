# Приложение 2 Повышение быстродействия IPS
Помимо традиционных рекомендаций по повышению производительности системы (увеличение производительности сервера СУБД, повышение пропускной способности локальной сети, upgrade Ваших рабочих станций) мы рекомендуем выполнять ряд требований, которые в той или иной степени повышают общую производительность IPS как при многопользовательской работе в сети, так и на локальной машине.
1\. **Всегда** используйте **выборки** (см. в ) и фильтры объектов при работе со списками объектов! Чем меньше список объектов, возвращаемый выборкой, тем быстрее она открывается и перечитывается. При работе с десятками и сотнями тысяч объектов работать с полным списком будет очень затруднительно. Старайтесь использовать выборки для конкретных типов объектов или применять в выборках фильтрацию по типу объектов.
2\. Если с системой работают сотни пользователей, то лучше разместить системную базу данных IPS на твердотельных накопителях (SSD), а файловые шкафы с файлами документов и двоичными данными перенести на RAID-массивы жестких дисков (HDD). Это позволит значительно ускорить доступ к информационным объектам и связям, при этом стоимость хранения больших массивов двоичных данных (файлов документов, изображений, эскизов и пр.) не изменится.
3\. Если быстродействие имеет для Вас наибольший приоритет, то старайтесь уменьшить общее количество атрибутов у объектов, а также правильно настройте оптимизацию операций с атрибутами (см. п. ).
4\. При настройке отображения необходимых Вам атрибутов объектов (см. в ) учитывайте способ их оптимизации у данного типа объектов. В списке отображаемых атрибутов рекомендуется использовать только те, у которых для данного типа объектов включена оптимизация на чтение или поиск. Если атрибут используется в выборках для поиска информации, то ему следует включить оптимизацию на поиск информации. При работе с документами в архивах следует учитывать, что система ведет поиск и выборку документов для базового типа **Документы** , поэтому оптимизацию атрибутов следует проводить у этого типа объектов. Исключение составляют выборки с включенным фильтром по типу объектов – в этом случае используются настройки оптимизации у заданного в выборке типа объектов.
5\. Настройте у всех пользователей параметры оптимизации клиента IPS в диалоге **Настройка / Параметры IPS / Пользователи / Оптимизация системы** (см. в )**.**
6\. Регулярно выполняйте процедуру удаления мусора из базы данных, причем рекомендуется выполнять удаление (а также прочие административные процедуры) в то время, когда с базой данных работает минимальное количество пользователей.
7\. Отключите регистрацию событий в IPS (см. п. ) или сведите ее к минимуму. Выключите ведение персональной и общей истории значений тех атрибутов, для которых это не имеет значения.
8\. Отключите сжатие файлов в файловых шкафах для тех типов файлов, для которых сжатие не требуется (см. п. ).
9\. По возможности используйте редактирование атрибутов объектов непосредственно в базе данных (см. п. ) – создание и удаление рабочих копий может потребовать значительного времени.
10\. Не рекомендуется назначать двоичные, файловые и текстовые атрибуты на типы связей – это значительно замедляет операции создания рабочих копий и версий объектов, создания объектов по прототипу и т.д.
11\. Минимизируйте использование многозначных и текстовых атрибутов, т.к. поиск по ним может занимать длительное время.
12\. Правильно настройте антивирусное ПО на серверах и рабочих станциях. Некоторые антивирусные мониторы могут значительно замедлять сетевые операции – в этом случае данное ПО рекомендуется отключить или заменить.
13\. При создании собственных типов объектов используйте локальные типы, т.к. они не создают нагрузку на общие таблицы объектов и атрибутов.
14\. Если вы не используете систему уровней доступа проектов, то выключите режим фильтрации объектов по принадлежности их к проектам с помощью переменной SecurityFilter в конфигурационом файле сервера приложений (см. ).
