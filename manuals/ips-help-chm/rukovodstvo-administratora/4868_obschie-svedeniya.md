# Общие сведения
В отличие от обычных уведомлений, автоматические уведомления не требуют подписки. Администратор настраивает условия срабатывания и адресат уведомления – вмешательство конечного пользователя не требуется.
С помощью механизма автоматических уведомлений можно, например, уведомить владельца сборочной единицы о выпуске извещения для любого документа на эту сборку либо об изменении любого изделия, входящего в сборочную единицу. Можно также оперативно уведомлять администраторов о попытках несанкционированного доступа к информации в системе, сообщать менеджеру проекта об изменениях ключевых объектов проекта и т.п.
Данный механизм позволяет своевременно информировать о следующих событиях: 
− взятие на редактирование; 
− завершение редактирования; 
− изменение атрибутов объектов;
− отказ в правах доступа;
− отмена изменений в объекте;
− перемещение на уровень продвижения;
− перемещение на шаг жизненного цикла;
− создание объекта;
− создание версии объекта;
− создание связи;
− удаление версии объекта;
− удаление связи. 
На работу автоматических уведомлений влияет настройка **Параметры / База данных и оптимизация / Разрешить передачу значений атрибутов в службу автоматических уведомлений.** Уведомления об изменении атрибутов объектов будут приходить только при включении этой настройки. При выключенной настройке разрешено создавать настройки уведомления об изменении атрибутов объектов, но они не будут учитываться системой до тех пор, пока указанная настройка в параметрах IPS не будет включена. Также включение данного режима позволит службе автоматических уведомлений проверять условия на атрибуты при рассылке уведомлений. 
**Внимание!** Разрешенная передача значений атрибутов снижает производительность системы, т.к. производятся дополнительные операции чтения атрибутов.
Автоматическое уведомление представляет собой объект, содержащий настройки генерации уведомлений. На один объект уведомления можно назначить только одно событие.
Настройки объекта автоуведомления содержат три вкладки: условия срабатывания, адресат, способ уведомления.
На вкладке условия срабатывания отображаются настройки в зависимости от типа уведомления. Рассмотрим особенности некоторых из этих настроек.
Настройка типов объектов, для которых будет срабатывать уведомление, распространяется на указанные типы объектов и их дочерние типы.

Настройка автоуведомления с формулой на атрибуты будет учитываться системой только в том случае, если включена настройка **Параметры / База данных и оптимизация / Разрешить передачу значений атрибутов в службу автоматических уведомлений.**

Если настройка выключена, то под окошком с формулой об этом будет выведено предупреждение.

Также, при невозможности использовать старые либо новые атрибуты объекта – соответствующий пункт будет недоступен для выбора.
При установленном флажке команды **Распространить формулу на все объекты, собранные для генерации уведомления** распространяет формулу на объект-инициатор события и на все объекты, собранные для генерации уведомления (см. закладку **Адресат**). При выключенном флажке формула распространяется только на объект-инициатор.
При внесении изменений в список типов объектов/связей, для которых будет срабатывать автоуведомление, формула на атрибуты обнуляется в связи с перерасчетом атрибутов, общих для выбранных типов.
Для уведомлений о перемещении на шаг ЖЦ необходимо указать нужный шаг жизненного цикла. По умолчанию, в списке будет выбран первый шаг жизненного цикла объектов. При указании нескольких типов объектов необходимо, чтобы у них была общая схема ЖЦ, иначе список шагов будет пуст.
На вкладке **Адресат** осуществляется назначение получателей уведомления.
Адресат может быть конкретный либо вычисляемый.
На вкладке конкретного адресата необходимо сначала выбрать, какие виды адресатов будут использоваться: определенные пользователи, роли, группы. Также есть возможность отправки сообщения на указанную электронную почту.

При указании определенных пользователей уведомления будут рассылаться всем указанным пользователям.
При указании ролей уведомления будут рассылаться всем пользователям, которым назначены указанные роли.
При указании групп уведомления будут рассылаться всем пользователям, входящим в указанные группы. В данном случае также учитывается входимость групп друг в друга.
Через «;» можно указать несколько адресов электронной почты, на которые надо отправить уведомление. Уведомления на эти адреса придут безотносительно того, какой способ уведомления будет выбран на вкладке **Способ уведомления**.
**Вычисляемый адресат** может определяться различными способами в зависимости от типа события, на которое настраивается автоуведомление.

Вычисляемый адресат определяется на основании набора объектов, которых касается событие. 
Для событий, касающихся объектов, набор объектов вычисляется одним из следующих способов:
· Объект – инициатор события.
· Версии объектов указанных типов, в которые входит объект-инициатор указанным типом связей (требуется указание конкретных типов объектов, типов связей и правила подбора версий; учитывается только первый уровень входимости).
· Версии объектов указанных типов, из которых состоит объект-инициатор указанным типом связей (требуется указание конкретных типов объектов, типов связей и правила подбора версий; учитывается только первый уровень состава).
· Исполнения изделий.
· Список объектов, собранных схемой поиска (требуется указание схемы поиска).
Адресат для этих событий может быть определен одним из следующих способов:
· Автор объекта (пользователь, записанный в атрибуте **Автор** объекта).
· Владелец объекта (если владелец – группа, то уведомление получат все пользователи, входящие в эту группу).
· Менеджер проекта, которому принадлежит объект.
· Автор указан в атрибуте (требуется указать атрибут).
· Руководитель подразделения, которому принадлежит автор объекта.
· Руководитель подразделения, которому принадлежит владелец объекта.
Для событий, касающихся связей, набор объектов вычисляется одним из следующих способов:
· Родительский объект связи.
· Дочерний объект связи.
· Родительский и дочерний объекты связи.
Адресат в этом случае может быть определен одним из следующих способов:
· Автор связи.
· Автор объекта.
· Владелец объекта (если владелец – группа – уведомление получат все пользователи, входящие в эту группу).
· Менеджер проекта, которому принадлежит объект.
· Автор указан в атрибуте (требуется указать атрибут).
· Руководитель подразделения, которому принадлежит автор объекта.
· Руководитель подразделения, которому принадлежит владелец объекта.
Для уведомлений отказа в доступе доступны два варианта вычисляемого адресата: автор объекта и владелец объекта.
**Внимание!** Пользователь, в ходе работы которого была создана ситуация, при которой были отправлены уведомления, сам уведомления об этом событии не получит.
На вкладке **Способ уведомления** выбирается способ уведомления адресата:
− на внутреннюю почту;
− на внешнюю почту;
− смешанный.

Смешанный способ уведомления подразумевает отправку сообщения как на внутреннюю, так и на внешнюю почту адресата.
При невозможности отправить уведомление на внешнюю почту, уведомление будет отправлено на внутреннюю почту адресата, а в лог-файл AutoNotification.log будет записано предупреждение об этом.
В поле Текст уведомления показывается шаблон текста уведомления. При желании, в шаблон можно дописать необходимые комментарии.
В зависимости от типа события, на которое настраивается уведомление, в шаблоне бывают следующие подстановки: 
· **%Шаг жизненного цикла%** – Шаг жизненного цикла, на который переведен объект.
· **%Уровень продвижения%** – Уровень продвижения, на который переведен объект.
· **%Пользователь%** – Пользователь – инициатор события. В уведомлениях о нарушении прав доступа возможны ситуации, когда пользователь не может быть идентифицирован, о чем будет сказано в сообщении.
· **%Тип связи%** – Тип связи, который был создан/удален между объектами.
· **%Текст уведомления об отказе в правах доступа%** – полный текст уведомления об отказе в правах доступа.
· **%Тип проверки прав%** – тип непрошедшей проверки прав доступа
· **%Новое значение%** – новое значение измененного атрибута
· **[Заголовок объекта]** – Заголовок объекта, которого касается событие уведомления. Если уведомление приходит на внутреннюю почту – заголовок будет оформлен в виде ссылки на этот объект. Если по ссылке невозможно пройти – значит объект был удален из базы.
· **[Заголовок родительского объекта]** – Заголовок родительского объекта (для уведомлений о действиях со связью).
· **[Заголовок дочернего объекта]** – Заголовок дочернего объекта (для уведомлений о действиях со связью).
· **[Наимен. измененного атрибута]** – наименование измененного атрибута.
Автоуведомление может быть переведено на шаг ЖЦ **Блокировано**. В этом случае рассылка по нему производиться не будет.
