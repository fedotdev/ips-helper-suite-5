# Основные понятия (часть 2)

| Рабочая копия объекта | Один из способов модификации информационных объектов позволяет брать версию объекта на изменение, в результате чего в базе данных создается рабочая копия объекта с собственным набором атрибутов и исходящих связей, в которую пользователь и вносит изменения. В это время остальным пользователям видна архивная копия объекта, в которую эти изменения не попадают. Кроме того, остальные пользователи не могут взять данную версию объекта на изменения до тех пор, пока пользователь, взявший ее на изменение, не выполнит команду **Завершить редактирование**. По этой команде сделанные пользователем в рабочей копии изменения записываются в архивную копию, а сама рабочая копия удаляется из базы данных. |
| Роль | Пользователи входят в систему под одной из ролей, которые назначил им администратор системы. Роль позволяет ограничить набор клиентских модулей, загружаемых при старте универсального клиента. Кроме того, посредством ролей пользователю могут быть назначены права доступа и предметные области, в которых он работает. Например, полномочия администратора системы назначаются пользователю посредством роли **Администратор системы**. Роли хранятся в системе в виде информационных объектов. |
| Связь | Категория, устанавливающая подчиненное отношение между версией информационного объекта и другим информационным объектом, т.е. в версию объекта с идентификатором ObjectID входит объект с идентификатором ID. Такой способ связывания позволяет оставлять без изменения связи родительского объекта при выпуске новой версии любого из дочерних объектов. Подбор версий дочерних объектов при получении состава родительского объекта производится с помощью текущего правила подбора версий, а также текущего контекста редактирования. Все связи делятся на типы, которые определяют допустимый набор атрибутов у связи, видимость связей в клиентских приложениях, хранение истории связей и т.д. |
| Сервер приложений | Серверная часть информационной системы, реализующая бизнес-логику обработки информации и непосредственно взаимодействующая с СУБД для хранения там всей обрабатываемой информации. Реализованы следующие способы функционирования сервера приложений: \- консольное приложение; \- служба Windows; \- web-сервер. |
| Системная база данных IPS | База данных, в которой хранятся метаданные, а также картотека информационных объектов и их взаимосвязей. В этой базе данных также хранятся все атрибуты объектов и связей, кроме файловых и двоичных атрибутов, которые хранятся в файловых шкафах для обеспечения масштабируемости системы. |
| Системный глобальный идентификатор | Глобальный идентификатор объектов или метаданных, который начинается с символов **cad** (например, **cad0005d-306c-11d8-b4e9-00304f19f545**). Данные с такими идентификаторами нельзя удалять из базы, т.к. от них зависит функционирование программных модулей системы. |
| Создатель объекта | Обязательный атрибут объекта, содержащий идентификатор пользователя, который создал данную версию объекта. Может содержать ноль (пустое значение) в случае, если версия была создана в другой базе данных или другой информационной системе. Данный атрибут позволяет назначать специальные права создателям объектов (посредством назначения прав доступа группе **СОЗДАТЕЛЬ_ОБЪЕКТА**). Значение данного атрибута изменять нельзя. |
| Списковый атрибут | Атрибут, который может принимать только те значения, которые содержатся в списке допустимых значений. Этот список настраивается администратором при определении характеристик данного атрибута. |
| Ссылка на версию объекта | Атрибут типа **Ссылка на версию объекта** содержит локальный идентификатор версии и текстовый заголовок информационного объекта, на который он ссылается. Нельзя ссылаться на рабочие копии и заготовки объектов. Также не рекомендуется ссылаться на версионные объекты, т.к. при выпуске новой версии объекта ссылки останутся на его старую версию. Для работы с версионными объектами рекомендуется использовать механизм связей между объектами. |
| Ссылка на версию объекта без конкретизации | Атрибут типа **Ссылка не версию объекта без конкретизации** содержит локальный идентификатор версии и текстовый заголовок информационного объекта, на который он ссылается. В строковой части атрибута хранится заголовок базовой версии объекта, на который он ссылается. |
| Схема жизненного цикла объектов | Графическое представление последовательности допустимых шагов жизненного цикла объектов определенного типа. |
| Тип атрибута | Описатель именованной характеристики, которая может быть присвоена объекту или связи того или иного типа (например, **Наименование** , **Масса** , **Фамилия** и т.п.). Тип атрибута определяет тип, размерность и способы ввода данных, которые можно присваивать экземпляру атрибута, необходимость хранения истории введенных значений, фильтрацию атрибута в списках атрибутов и пр. |
| Тип данных атрибута | Определяет, какого рода данные может принимать атрибут: строки, числа, ссылки на объекты и пр. Типы данных бывают простыми (например, строка, дата или число) и комплексными (например, файл, ссылка на версию объекта, ссылка на версию объекта без конкретизации или вещественное число, выраженное в единицах измерения). |
| Тип объекта | Главная характеристика любого информационного объекта, которая определяет: − допустимый набор атрибутов, которые могут присваиваться объекту автоматически или вручную; − допустимые связи с другими объектами; − этапы жизненного цикла, на которые можно переводить данный объект (и, соответственно, права доступа к объекту); − набор команд контекстного меню, которые могут быть применены к данному объекту; − способы обработки объекта различными модулями системы и т.д. |
| Тип связи | Главная характеристика любой связи между информационными объектами, которая определяет: − допустимый набор атрибутов, которые могут присваиваться связи автоматически или вручную; − допустимые типы объектов, между которыми может существовать данная связь; − хранение истории связей; − способы обработки связей различными модулями системы и т.д. |
| Удаленный объект | Версия информационного объекта, находящаяся на специальном уровне продвижения **Удалено**. Информационные объекты удаляются из системы путем перевода на данный уровень продвижения. При этом удаляются все входящие и исходящие связи объекта, а также ссылки на него. Удаленные объекты видны в списках объектов только в случае, если включен специальный режим показа таких объектов или в выборке объектов содержится условие **Уровень продвижения = Удалено**. Полное уничтожение таких объектов в базе данных происходит в следующих случаях: − если у типа объекта опция **Время жизни удаленных объектов = 0** , то такие объекты уничтожаются сразу после перевода на уровень продвижения **Удалено** ; − если для удаленного объекта повторно вызывается команда **Удалить** ; − во время операции чистки мусора уничтожаются все удаленные объекты с истекшим временем жизни. |
| Узел информационной системы | База данных IPS, подключенная к IPS WebPortal для обмена информацией с другими базами данных. Узлами могут быть также базы данных других информационных систем (например, Intermech Search), выполняющих обмен данными посредством службы IPS WebPortal. |
| Универсальный клиент | Клиентское приложение, которое является оболочкой для всех клиентских модулей расширения информационной системы. Универсальный клиент производит подключение и авторизацию на сервере приложений, загружает в память и инициализирует модули расширения системы, производит автоматическое переподключение к серверу приложений в случае обрыва связи. Кроме того, универсальный клиент является поставщиком ряда сервисов, которые используют клиентские модули расширения: меню, панели инструментов, буфер обмена данными, панели фоновых задач и информационных сообщений, служба управления списками общих пиктограмм и т.д. |
| Уровень доступа объекта | Обязательный атрибут любого объекта, который хранит информацию об уровне доступа, который должен иметь пользователь для работы с данной версией объекта. Заполняется системой для объектов тех типов, у которых включена опция **Мандатное разграничение доступа** (см. п. ). |
| Уровень продвижения объекта | Категория, определяющая статус объекта в процессе его жизненного цикла. Уровни продвижения служат для объединения одинаковых по смыслу шагов в жизненных циклах объектов различных типов, что позволяет унифицировать их обработку различными модулями системы. Существуют следующие системные уровни продвижения объектов: − Персональный объект (объекты на данном уровне продвижения видны только своим владельцам); − Удаленный объект (см. Удаленный объект). |
| Файловый шкаф | Информационный объект, описывающий место хранения файловых атрибутов и атрибутов, содержащих большие массивы двоичных данных. В общем случае файловый шкаф хранит строку подключения к базе данных и имя таблицы, в которой будут храниться файлы и двоичные данные. Механизм файловых шкафов позволяет распределить обработку и хранение больших массивов данных между несколькими серверами и накопителями данных. |
| Шаг жизненного цикла объекта | Свойство объекта, определяющее текущее состояние объекта в процессе его жизненного цикла. От текущего шага жизненного цикла зависят права доступа к объекту и возможные способы его изменения, уровень продвижения объекта, способы обработки объекта различными модулями системы и пр. |
| Экземпляр атрибута | Именованная характеристика, присвоенная информационному объекту или связи между объектами. В зависимости от типа атрибута может содержать одно или несколько значений. |
| Электронная подпись | Аналог обычной подписи, который представляет собой зафиксированный системой факт выполнения определенным пользователем команды **Подписать** в процессе согласования определенного информационного объекта (например, чертежа, спецификации, техпроцесса и т.п.). В электронной подписи записаны дата и время подписания, должность и графа, в которой была поставлена подпись, а также дата и время последней модификации содержимого подписанного объекта, позволяющая контролировать неизменность подписанной информации. |
| Языковой вариант | Язык общения, на котором в данной информационной системе можно создавать атрибуты и записывать в них информацию. Например, в системе можно зарегистрировать английский языковой вариант, создать соответствующие атрибуты для данного языкового варианта и хранить у объекта перевод информации на английском языке. Каждый пользователь системы может указать один или несколько языков, на которых он хочет видеть информацию, хранящуюся в системе. |
