# Редактор схем жизненных циклов
Создание схемы жизненного цикла происходит в специальном редакторе, который расположен на закладке **Редактор схем жизненных циклов**. Редактор состоит из рабочей области и двух специальных панелей:
· **Свойства** — позволяет редактировать свойства выбранного шага жизненного цикла.
· **Палитра** — отображает в виде пиктограмм все существующие в системе уровни продвижения, с помощью которых составляют схемы жизненных циклов объектов.
Чтобы создать на схеме шаг жизненного цикла, отметьте в палитре пиктограмму требуемого уровня продвижения и переместите ее курсором мыши в рабочую область схемы ЖЦ. Чтобы создать связь между шагами ЖЦ, подведите курсор мыши к середине пиктограммы, так, чтобы пиктограмма стрелки курсора сменилась на изображение руки. В таком положении, удерживая курсор, подведите его к пиктограмме шага ЖЦ, с которым необходимо создать связь, в результате чего должна образоваться связь в виде стрелки. С помощью контекстного меню можно изменить направление связи, воспользовавшись командой **Развернуть** , или сделать связь двунаправленной, воспользовавшись командой **Двусторонняя**. Чтобы удалить связь или уровень продвижения, выделите их в рабочей области и нажмите клавишу **Delete**.
На панели свойств отображаются общие свойства выбранного шага жизненного цикла:
· **Восстанавливать мягкую конкретизацию версий**. Флаг позволяет указать системе на необходимость восстанавливать конкретизацию версий дочерних объектов при перемещении версии объекта на данный шаг ЖЦ. Восстановление будет произведено в том случае, если на предыдущих шагах ЖЦ мягкая конкретизация была автоматически выключена.
· **Выполнять обновление атрибутов, полученных от мастер-атрибута.** Параметр, включение которого позволяет проверить и обновить значения атрибутов, если они получены от объекта, на который ссылается мастер-атрибут. Параметр **Выполнять обновление атрибутов, полученных от мастер-атрибута** сработает только при условии если атрибут не влияет на дату модификации содержимого объекта и для него включен параметр **Возможна модификация без взятия на изменение**.
· **Запрет выпуска новых версий при наличии версии на этом шаге.** Данная опция позволяет отметить необходимые шаги схемы ЖЦ, наличие на которых версий объекта является основанием для запрета выпуска его новых версий.
· **Запрет существования более одной версии объекта на данном шаге**. Если данный флаг включен, то система не позволит переместить на данный шаг более одной версии любого объекта (за исключением версий, включенных в контексты редактирования). Данное свойство позволяет организовать последовательный процесс прохождения объектов по схеме ЖЦ, а также обеспечить однозначный подбор версий объектов на данном шаге.
**Внимание**! Данное свойство работает при условии, что для типа объекта включено свойство **Запрет выпуска новых версий согласно настройкам шагов ЖЦ**.
· **Запрет существования более одной контекстной версии объекта**. Данный флаг расширяет действие запрета существования более одной версии объекта на данном шаге, распространяя запрет и на версии, включенные в контексты редактирования и извещения об изменениях.
· **Комментарий**. Позволяет внести пояснение к шагу жизненного цикла.
· **Контроль подписей**. Позволяет настроить графы для подписей объектов, имеющих данную схему жизненного цикла. При работе с объектом, не заполнив указанные графы, невозможно будет перевести его на данный шаг ЖЦ. Чтобы настроить контроль подписей, вызовите диалог настройки граф для подписей с помощью кнопки, расположенной с правой стороны строки. Вызовите команду **Добавить новую группу** контекстного меню поля диалога. Отметьте графы, которые необходимо будет подписывать, и нажмите **ОК**. Переключатель **Использовать строгий контроль для данной графы** позволяет установить строгий контроль подписи, т.е. подпись объекта будет считаться устаревшей, если объект модифицировался после его подписания. 
Примечание: данная настройка будет доступна в том случае, если загружен модуль расширения **ЭП**.
· **Контроль прав доступа к объектам**. Позволяет назначить способ контроля прав доступа к объектам на данном шаге ЖЦ:
− **Не проверять права**. Позволяет игнорировать все проверки прав доступа к объекту.
− **Проверять права ЖЦ**. Проверяет только те права, которые назначены для данного шага ЖЦ на закладке **Схема жизненного цикла** для конкретного типа объектов.
− **Проверять права ЖЦ и объекта**. Проверяет сумму прав доступа, назначенных для данного шага ЖЦ у данного типа объектов и прав доступа, назначенных непосредственно данной версии объекта.
· **Наименование**. Позволяет изменить наименование данного шага жизненного цикла.
· **Необходимость извещения**. Определяет необходимость включения создаваемых версий объектов, находящихся на данном шаге ЖЦ, в извещения об изменениях. 
Примечание: данная настройка будет доступна в том случае, если загружен модуль расширения **Контроль изменений**.
· **Первый шаг**. Позволяет выбрать данный шаг ЖЦ в качестве первого шага, на который попадет версия объекта при её создании.
· **Переводить на шаг**. В этом поле можно указать шаг ЖЦ, на который система автоматически переведёт существующую на данном шаге версию объекта перед тем, как сюда будет перемещена другая версия этого объекта. Для выбора доступны только те шаги схемы, к которым от данного шага настроены связи. При автоматическом переводе версии объекта система производит все проверки, которые нужны для успешного перевода объекта на указанный шаг ЖЦ (права доступа, подписи и пр.).
· **Способ модификации объектов**. Определяет действия, которые необходимо произвести над данной версией объекта для того, чтобы можно было производить ее модификацию:
− **Выпуском новой версии объекта**. Позволяет модифицировать объект только посредством выпуска новой версии объекта.
− **Нельзя модифицировать объект.** Не позволяет модифицировать версию объекта на данном шаге жизненного цикла. Для модификации необходимо перевести данную версию объекта на другой шаг ЖЦ.
− **Непосредственно в базе данных**. Позволяет модифицировать версию объекта непосредственно в базе данных без каких-либо ограничений.
− **Через рабочую копию объекта.** Перед модификацией версию объекта необходимо взять на изменение. При этом версия принимает статус рабочей копии, т.е. может модифицироваться только тем пользователем, у которого данная версия объекта находится на изменении. Остальные пользователи не будут иметь доступа, чтобы модифицировать данную версию до тех пор, пока пользователь, у которого она находится на изменении, не выполнит команду **Завершить изменение**. 
· **Уровень продвижения**. Позволяет изменить уровень продвижения, не прибегая к замене пиктограмм и нарушениям связей в созданной схеме.
· **Фиксация базовой версии**. При переводе версии объекта на шаг ЖЦ, у которого включен данный флаг, система делает эту версию объекта базовой. Рекомендуется при включении этого флага также указывать значение в поле **Переводить на шаг** , чтобы на шаге фиксации версий всегда оставалась только одна версия объекта. В любом случае базовой останется только одна версия объекта – последняя из переведённых на данный шаг версий.
