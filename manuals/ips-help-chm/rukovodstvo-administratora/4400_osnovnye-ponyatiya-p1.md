# Основные понятия (часть 1)

В данной главе приводится описание терминов, которыми оперирует Intermech Professional Solutions. Знание терминологии необходимо для понимания принципов работы системы, поэтому администраторам рекомендуется внимательно ознакомиться с данным разделом руководства.
| **Термин** | **Описание** |
| --- | --- |
| Абстрактный тип объектов | Абстрактным называется тип объектов, который не допускает создание в системе информационных объектов данного типа. Абстрактные типы служат для смысловой группировки типов объектов, имеющих общие атрибуты, взаимосвязи и способы обработки информации. Например, абстрактный тип объектов **Изделия** содержит версионные типы **Сборочные единицы** , **Детали** , **Стандартные изделия** и т.д. |
| Активный файловый шкаф | Файловый шкаф, в который по умолчанию помещаются все создаваемые в системе файловые и двоичные атрибуты. |
| Атрибут | см. Экземпляр атрибута |
| Базовая версия объекта | Версия объекта, которая считается предпочтительной при работе различных механизмов поиска версий в системе. У любого информационного объекта в любой момент времени существует одна единственная базовая версия. Базовую версию можно удалить только в том случае, если в базе данных не существует других версий данного объекта. Базовые версии всегда отображаются в списках объектов вне зависимости от их вхождения в какие-либо контексты редактирования. Базовые версии могут использоваться правилами подбора версий в качестве основного или дополнительного критерия подбора версий, что позволяет организовать подбор таких версий при работе с составом и применяемостью объектов. |
| Брокер подключений | Специальная серверная служба, которая предоставляет клиентам IPS адреса работающих серверов приложений IPS в соответствии с указанным методом выбора сервера. Обеспечивает автоматическое подключение клиентов к доступному в данный момент серверу приложений, а также может использоваться для балансировки загрузки серверов приложений, возвращая клиентам адрес наименее загруженного в данный момент сервера. |
| Версионный тип объектов | Версионным называется тип объектов, который допускает создание произвольного количества версий информационного объекта данного типа. |
| Версия объекта | см. Информационный объект |
| Владелец объекта | Обязательный атрибут объекта, содержащий идентификатор пользователя, который является владельцем объекта. Данный атрибут позволяет назначать специальные права владельцам объектов (посредством назначения прав доступа группе **ВЛАДЕЛЕЦ_ОБЪЕКТА**). По умолчанию владельцем объекта является пользователь, создавший данный объект, однако владельца можно изменить (при наличии соответствующего права доступа к объекту). |
| Глобальный идентификатор (GUID) | Объекты любой категории (типы атрибутов, объектов и связей, сами информационные объекты и пр.) получают при создании глобальный идентификатор, который используется системой для идентификации информации как в рамках одной базы данных, так и при синхронизации информации между различными базами данных. Это позволяет однозначно идентифицировать объект, даже если он был неоднократно перемещен из одной базы данных в другую и изменил остальные идентификационные характеристики. **Внимание!** Глобальные идентификаторы, начинающиеся на CAD, являются системными и используются программным комплексом «ИНТЕРМЕХ» для идентификации собственных категорий объектов. Изменение настроек или удаление таких категорий объектов может быть заблокировано системой! При необходимости изменения заблокированных настроек следует обратиться в службу технической поддержки Интермех. |
| Группа атрибутов | Все типы атрибутов в системе делятся на смысловые группы, что облегчает поиск и обработку атрибутов, а также упрощает назначение прав доступа к атрибутам. Любой тип атрибута обязательно входит в системную группу **Все атрибуты** , а также может входить в произвольное количество других групп атрибутов. |
| Дата модификации объекта | Атрибут устарел и в данный момент системой не модифицируется. |
| Дата модификации содержимого объекта | Дополнительный атрибут информационного объекта, который содержит последнюю дату и время модификации содержимого объекта. Под содержимым объекта понимают совокупность атрибутов и исходящих связей объекта, которые определяют целостность хранящейся в объекте информации. Администратор системы указывает, какие именно атрибуты и связи влияют на дату модификации содержимого объектов того или иного типа, после чего система автоматически обновляет у объектов атрибут **Дата модификации содержимого объекта** при изменении соответствующих атрибутов или связей. Эта дата используется в дальнейшем в механизмах контроля устаревания электронных подписей, проверках актуальности комплектов документации и пр. |
| Дополнительный атрибут | Атрибут, который может быть добавлен (автоматически или вручную) к информационному объекту или связи в случае, если это допускает тип объекта или связи. |
| Жизненный цикл объекта | Совокупность статусов (шагов жизненного цикла), которые могут принимать объекты данного типа. |
| Заготовка объекта | Объекты в системе создаются в два этапа. На первом этапе создается заготовка объекта, которой можно присваивать значения атрибутов и накладывать связи без проверки правил, заданных в системе. Все проверки производятся в момент перевода заготовки в объект. Заготовки не видны в списках объектов и удаляются из базы операцией чистки мусора (по истечении определенного времени). На заготовки нельзя ссылаться из атрибутов объектов и связей. |
| Идентификатор версии объекта (ObjectID) | Обязательный атрибут, позволяющий идентифицировать любую версию любого информационного объекта в пределах одной базы данных. |
| Идентификатор объекта (ID) | Обязательный атрибут, позволяющий идентифицировать информационный объект в пределах одной базы данных. Все версии одного объекта содержат одинаковое значение данного атрибута. |
| Информационный объект | Базовая единица информации, описывающая какой-либо материальный или виртуальный объект, действие или явление. Каждый информационный объект характеризуется атрибутами, связями с другими объектами и своим жизненным циклом. Допустимый набор атрибутов, связей и шагов жизненного цикла определяется типом объекта. Объекты бывают версионными и неверсионными, что также определяется типом объектов. Неверсионные объекты могут иметь только одну версию, которая собственно и является самим информационным объектом. Версионный объект представляет собой совокупность всех версий объекта, объединенных общим идентификатором объекта. Среди всех версий объекта всегда есть одна базовая версия объекта. Остальные версии являются не базовыми. |
| Итерация | Сохранённое состояние атрибутов и состава версии объекта, предназначенное для отката сделанных после создания итерации изменений. |
| Категория объектов | Вся информация, которой оперирует информационная система, делится на категории (например, версия информационного объекта, сам объект и тип объекта относятся к разным категориям информации). Это позволяет различным модулям системы единообразно производить обработку информации, относящейся к различным категориям. Например, в системе можно назначать права доступа, как на версию объекта, так и на тип объекта, используя один и тот же внутренний механизм прав доступа. |
| Конкретизация версий | Механизм, позволяющий задать на связи между версией и объектом точную версию объекта, входящую в состав вышестоящей версии объекта. Конкретизация версии производится атрибутом связи **Идентификатор версии в составе**. Различают жесткую конкретизацию, задаваемую самой системой и имеющую наивысший приоритет при подборе версий объектов, а также мягкую конкретизацию, которую задают сами пользователи системы и которая может быть временно перекрыта другими механизмами подбора версий (например, контекстами редактирования). |
| Контекст редактирования | Специальный объект, позволяющий выполнять совместную работу пользователей над составами объектов на этапах редактирования и доработки. Содержит идентификаторы версий объектов, которые должны подбираться системой в приоритетном порядке при поиске состава и применяемости объектов. |
| Локальный идентификатор | Целочисленный идентификатор, используемый для работы с объектами, типами, атрибутами и пр. в рамках одной базы данных. При перемещении информации в другую базу данных эти идентификаторы изменяются. В связи с этим любая информация, которая может быть перемещена между различными базами данных, имеет также и глобальный идентификатор. |
| Мастер-атрибут | Содержит ссылку на объект, атрибуты которого являются источником значений для подчиненных атрибутов объекта с мастер-атрибутом. Присвоение значений подчиненным атрибутам происходит в момент присвоения значения мастер-атрибуту. |
| Метаданные | Информация, определяющая структуру и допустимые взаимосвязи хранимых в системе информационных объектов, а также способы их представления и модификации. |
| Многозначный атрибут | Атрибут, который может содержать более одного значения. В таблицах со списками объектов или связей для такого атрибута всегда выводится только первое значение. |
| Навигатор | Главное окно клиентской части IPS, позволяющее получить доступ к основным механизмам поиска и модификации информации в системе. |
| Неверсионный тип объектов | Неверсионным называется тип объектов, который не допускает создания более одной версии информационного объекта данного типа. |
| Номер группы изменений | Обязательный атрибут версии объекта, который содержит идентификатор группы изменений, к которой относится данная версия объекта. Группой изменений является совокупность связанных контекстов редактирования (извещений об изменении), которые объединяют версии объектов, выпущенные для проведения какого-то определенного изменения в изделии, документации и пр. Система заполняет номер группы изменений в момент включения версии объекта в контекст редактирования (в извещение об изменении). По-умолчанию в списках объектов показываются только базовые версии объектов, а также те версии, у которых номер группы изменений равен нулю либо тому номеру группы изменений, который соответствует текущему контексту редактирования. |
| Нормализованный индекс | Специальный вид вычисляемых атрибутов, который хранит вычисленные значения в так называемой нормализованной форме, которая позволяет приводить различные по написанию, но одинаковые по смыслу строки в общий вид. Это позволяет производить поиск и идентификацию информации даже в том случае, если оператор допустил ошибку при ее наборе (например, поставил лишний пробел или вместо русской буквы набрал одинаковую по написанию латинскую букву). Правила нормализации могут быть настроены администратором системы. |
| Объект | см. Информационный объект |
| Обязательный атрибут | Атрибут, который существует у каждого информационного объекта или связи вне зависимости от их типа. К обязательным атрибутам информационных объектов относятся: глобальные и локальные идентификаторы версии и объекта, тип объекта, порядковый номер версии объекта, шаг жизненного цикла и уровень продвижения версии объекта, дата модификации версии объекта, заголовок версии объекта, создатель и владелец объекта, номер группы изменений, признак базовой версии объекта, уровень доступа объекта. К обязательным атрибутам связи относятся: глобальный и локальный идентификаторы связи, идентификатор версии родительского объекта, идентификатор дочернего объекта, тип связи, дата и время создания связи, дата и время удаления связи. |
| Персональный уровень продвижения объектов | Версии информационных объектов, находящиеся на данном уровне продвижения, видны только тем пользователям, которые являются их владельцами. Администратор системы может увидеть персональные объекты других пользователей, включив специальный режим показа таких объектов. |
| Подчиненный атрибут | Атрибут, значение которому присваивается автоматически в момент присвоения значения соответствующему мастер-атрибуту. Источником значений для подчиненных атрибутов являются атрибуты информационного объекта, ссылка на который присваивается мастер-атрибуту. |
| Портфель | Модуль расширения системы, предназначенный для обмена информацией как между различными базами данных Intermech, так и с информационными системами сторонних производителей. |
| Правило подбора версий объектов | Набор условий, по которым система производит отбор версий объектов при получении состава и применяемости объектов. |
| Предметная область | Категория, позволяющая разделить всю хранящуюся в системе информацию на области применения. Это позволяет упростить пользовательский интерфейс системы, исключив из списков типы объектов, связей и атрибутов, не относящиеся к предметным областям, с которыми работает данный пользователь. Например, если роли **Конструктор** назначены предметные области **Конструкторская подготовка производства** и **Документооборот** , то пользователь, зашедший в систему в данной роли, не увидит информации, относящейся к администрированию системы, бухгалтерии, строительству и пр. Однако следует учитывать, что сами информационные объекты по предметным областям не фильтруются, поэтому в случае поиска среди объектов всех типов пользователю могут быть видны объекты, относящиеся к скрытым для него предметным областям. |
