# Детальное определение последовательности сбора глобальной таблицы
Глобальная таблица – это механизм для ускорения генерации документов: программа один раз обращается к базе данных и получает из нее всю необходимую информацию об объектах и связях между ними, которые будут использоваться для генерации документа. Оператор поиска вложенных объектов **Сохранять структуру** , который обычно используется для получения глобальной таблицы, читает из базы **полный развернутый состав** корневого объекта по связям заданных вами типов, и только после этого полученный набор данных фильтруется по типам объектов. Если для генерации вашего документа полный развернутый состав не нужен, и при этом он очень велик, то получение глобальной таблицы с помощью оператора поиска вложенных объектов может занимать очень много времени.
Для решения этой проблемы следует использовать детальное определение последовательности сбора глобальной таблицы, которое позволяет определить, какие объекты и по каким связям надо искать для объектов каждого типа, и какие атрибуты для них следует собрать. Это делается с помощью двух операторов: **Сбор глобальной таблицы** (корневой элемент) , в который должны входить операторы **Для типа объектов**. Оба оператора не могут иметь модификаторов. Оператор **Сбор глобальной таблицы** позволяет задать параметры поиска объектов непосредственно от головного объекта, на котором будет запущена генерация документа.
На вкладке **Общие параметры** указываются общие параметры, которые будут применяться к каждому поиску объектов в базе. 
Поле **Заменить объект(ы) контекста на объекты(ы) типа** используется, если скрипт требуется запускать не только на корневой объект (состав которого используется при сборе документа), но и на какой-нибудь другой объект, связанный с корневым – например, не на изделие, а на спецификацию этого изделия. Спецификация – это документ, входящий в корневое изделие. Чтобы программа могла найти корневое изделие, следует нажать на кнопку и выбрать тип **Изделия**. Чтобы программа смогла найти нужное изделие, в системе должно быть правило поиска объектов типа **Изделия** , работающее для спецификаций.
Панель **Общие собираемые атрибуты** позволяет определить, какие атрибуты объектов и связей должны попасть в глобальную таблицу для всех типов объектов. Первая кнопка позволяет добавить атрибут объекта , вторая – атрибут связи , а кнопка удаляет ненужный атрибут. Имейте в виду, что запрос атрибута, которого нет у некоторого типа объектов, может существенно замедлить сбор глобальной таблицы! В этой панели следует задавать только те атрибуты, наличие которых заведомо гарантировано для всех типов объектов, попадающих в глобальную таблицу. Прочие атрибуты следует задавать для конкретных типов объектов. Так из примера на рисунке выше для каждого объекта будет осуществляться поиск атрибутов **Обозначение** и **Наименование** , а также атрибутов связи – **Количество**. 
Общее условие выбора объектов будет проверяться на **всех** этапах сбора глобальной таблицы (а не только при поиске объектов от корня). Это поле позволяет избежать ввода одного и того же условия для всех операторов **Для типа объектов**. Для редактирования условия нажмите правую кнопку мыши и выберите нужную команду редактирования в локальном меню.
**Внимание**! Следите за атрибутами, используемыми в этом условии! Обычно при его вводе забывают, что не все объекты обязательно имеют все атрибуты, которые могут участвовать в условии. Если при проверке условия окажется, что у объекта нет атрибута, который в нем используется, система попытается его рассчитать, а если это не удастся, система посчитает, что условие ложно, и объект не будет добавлен в глобальную таблицу, как и его состав. Функция def (Атрибут) позволяет включить объект при отсутствии атрибута и не терять времени на попытку расчета.
**Внимание**! Убедитесь, что атрибуты объектов, используемые в общем условии, собираются в глобальную таблицу – в противном случае программе придется каждый раз искать эти атрибуты в базе данных, что, разумеется, существенно замедлит сбор таблицы.
Параметры поиска объектов от корня задаются на вкладке **Запрос для корня**.
Поле **Выборка базы данных** имеет такой же смысл, как и для операторов поиска объектов (см. п. ): вы можете задать выборку, условия которой будут добавлены к условиям поиска объектов в базе. Как обычно, нажатие кнопки с многоточием позволяет выбрать выборку, а остальные две кнопки создают новую выборку и сбрасывают выбор выборки.
Наиболее важны параметры поиска объектов, задаваемые в панели **Искать объекты и связи следующих типов**. Каждый тип связи в этой панели задает один запрос в базу. Для добавления нового типа связи нажмите кнопку **Искать по связи вниз** , если надо искать состав текущего объекта или **Искать по связи вверх** для поиска применяемости. После этого откроется диалоговое окно, в котором нужно выбрать тип связи. Если надо искать объекты по связям всех типов, выберите узел **Все типы связей**.
**Внимание**! Поиск по связям всех типов займет намного больше времени, чем по связям нескольких типов! Следует избегать поиска по связям всех типов, если это возможно, и ни в коем случае не задавать такой поиск, если вы просто не знаете точно, какие типы связей могут потребоваться. В будущем в вашей базе данных могут появиться новые типы связей, которые ни в коем случае не должны попадать в этот документ, но попадут, если вы зададите поиск по всем типам связей.
Для каждого заданного типа связей можно определить, какие объекты требуется найти по связям этого типа. Нажмите на кнопку и выберите типы объектов, которые нужно найти. Обратите внимание, что при этом нельзя выбрать корневой тип объекта (например, **Документы**) для выбора всех дочерних типов – каждый дочерний тип придется выбирать отдельно. В противном случае нельзя было бы задать выбор только объектов корневого типа, без дочерних типов.
Для удаления типа объекта или связи из дерева нажмите кнопку .
Панель **Исполнения** позволяет определить, нужно ли получать все исполнения корневого объекта. Это обычно требуется для групповых документов. Если все исполнения получать не нужно, но они есть, программа будет раскрывать состав только переданного исполнения (единичный документ для этого исполнения).
Локальное условие выбора объектов, действующее только при поиске непосредственно от корня, задается на закладке **Запрос для корня** в поле **Условие выбора объектов**. Как и для общего условия, все команды редактирования находятся в локальном меню, вызываемом по нажатию правой кнопки мыши.
На вкладке **Прочее** можно указать какие опции состава использовать при выводе в документ объекта с составом. 
Радиокнопки **Показывать весь состав** , **Не показывать скрытый состав** , **Не показывать скрытый состав и объекты к ним** позволяют задать режим работы со скрытым составом. Значение команд при выводе состава в документ аналогично командам отображения состава **Не показывать скрытый состав объекта** и **Не показывать объекты со скрытым составом** в навигаторе:
· **Показывать весь состав**. В этом режиме, который установлен по умолчанию, ЭС вообще не учитывает установки скрытия состава. 
· **Не показывать скрытый состав** _._ В этом режиме в получаемые данные входят объекты, структура которых должна быть скрыта, но не их состав.
· **Не показывать скрытый состав и объекты с ним** _._ В этом режиме в получаемые данные не входит не только состав объектов, но и сами объекты со скрытым составом.
Настройка **Использовать опции конфигуратора составов** применяется в том случае если необходимо при сборе глобальной таблицы учитывать только объекты по выбранным опциям конфигуратора составов для объектов использующих **Конфигуратор составов объектов**.
Переключатель **Собирать параметры файлов** необходимо включить в том случае, если следует загрузить информацию о файлах объектов в глобальную таблицу. При попытки повторной загрузки объектов этого типа в глобальную таблицу, система автоматически добавляет в таблицу следующие атрибуты:
· **Файл: Количество**. Количество файлов у объекта (целое число). 
· **Файл: Имя** _._ Имена всех файлов объекта (набор строк).
· **Файл: Размер** _._ Размеры всех файлов объекта (набор целых чисел).
· **Файл: Дата** _._ Даты модификации всех файлов объекта (набор дат).
· **Файл: Контрольная сумма** _._ Контрольные суммы всех файлов объекта (набор целых чисел).
Для обработки полученной информации следует использовать модификатор **Цикл** (желательно с оператором папки). В качестве **Переменной цикла** можно использовать любой временный целочисленный атрибут – в нашем примере на рисунке ниже использована **Переменная N**.
Значение этой переменной будет изменяться от 0 до **Файл: Количество-1**. На каждой итерации цикла, пользователь сможет обращаться к соответствующему элементу массивов **Файл: Имя** , **Файл: Размер** , **Файл: Дата** и **Файл: Контрольная сумма**. Например, для получения имени текущего файла достаточно будет написать **Файл: Имя[N]**.
В отличие от корневого оператора сбора глобальной таблицы, который всегда один, вложенных в него операторов **Для типа объектов** обычно несколько, в зависимости от сложности модели сбора данных. Каждый оператор **Для типа объектов** может обрабатывать сразу несколько типов объектов. Он описывает свою схему сбора состава или применяемости объектов, а также атрибуты, которые надо собирать только для объектов заданных типов.
**Внимание!** Программа всегда будет сопоставлять каждый тип объектов ровно с одним оператором **Для типа объектов** , даже если вы укажете этот тип в нескольких операторах. В первую очередь выбираются операторы, в которых указан именно этот тип, а не один из его родительских типов. Если таких операторов нет, выбирается тот, тип которого наиболее близок к данному типу по структуре наследования.
Панель **Для типов объектов** определяет, для каких типов объектов действует этот оператор. Для добавления типа объектов нажмите кнопку , а для удаления ненужного типа объектов – кнопку . Переключатель, расположенный слева от названия типа объекта, позволяет определить, нужен ли вам только этот тип объектов (если выключен) либо этот тип и все его дочерние типы (если включен).
Панель **Собираемые атрибуты** позволяет задать атрибуты, которые нужно собрать для объектов тех типов, которые вы задали в панели **Для типов объектов**. Обратите внимание, это **не те** атрибуты, которые будут запрошены в поиске, определенном на закладке **Поиск объектов**! Набор собираемых атрибутов для заданных типов объектов будет использоваться в других запросах в базу, которые могут найти объекты этого типа. Например, если у вас есть два оператора, один для объектов типа **Изделие** , а второй для объектов типа **Техпроцесс** , то атрибуты техпроцесса будут использоваться не при поиске его состава, а при любом поиске, который может вернуть техпроцессы.
Панель **Исполнения** позволяет определить, что для групповых объектов данного типа надо включать в глобальную таблицу не только сам объект, но и все его исполнения, либо только общую часть для всех исполнений. Эта функция пока не реализована, поэтому на рисунке панель запрещена.
Закладка **Поиск объектов** для этого оператора аналогична закладке **Поиск для корня** оператора **Сбор глобальной таблицы** (см. выше), но здесь вы задаете правила поиска объектов не от корня, а от каждого объекта, принадлежащего к одному из типов, выбранных вами в панели **Для типов объектов**.
Закладка **Прочее** для этого оператора аналогична одноименной закладки оператора **Сбор глобальной таблицы** (см. выше).
Общий алгоритм сбора глобальной таблицы достаточно прост. Сначала выполняется корневой оператор, который получает первую порцию объектов, по правилам, заданным вами на закладке **Поиск для корня**. При этом производится отдельный запрос в базу объектов заданных типов для каждого типа связей, и для каждого из этих типов программа ищет соответствующий оператор **Для типа объектов** , добавляя запрос атрибутов, заданных вами для этого типа.
После этого программа определяет, какой из операторов **Для типа объектов** должен обрабатывать каждый объект из полученной порции, и последовательно обрабатывает все операторы, для которых нашелся хотя бы один объект. Для каждого оператора, как и для корня, выполняется один запрос в базу на каждый заданный вами тип связей (независимо от количества объектов). Все найденные объекты попадают в следующую порцию объектов. Программа продолжает работать, пока не получит пустую порцию объектов, что будет означать завершение сбора глобальной таблицы.
