# Свойства
Задать или изменить свойства типа объектов можно на закладке **Свойства** рабочей области конфигуратора, выделив данный тип объектов в дереве свойства метаданных:
· **Атрибут-описатель**. Позволяет выбрать атрибут, принадлежащий данному типу объектов, значение которого будет являться заголовком объекта.
· **Версионность**. Позволяет управлять версионностью объектов данного типа: 
− **Абстрактный тип** — не допускает создание в системе объектов данного типа. Служит для смысловой группировки типов объектов, имеющих общие атрибуты, взаимосвязи и способы обработки информации.
− **Версионный тип** — допускает создание в системе версий объектов данного типа.
− **Неверсионный тип** — не допускает создания в системе версий объектов (т.е. объекты данного типа могут иметь только одну версию в базе данных).
· **Включать новые версии в текущий контекст редактирования**. Указывает системе на необходимость автоматического включения новых версий объектов данного типа в текущий контекст редактирования (если в панели инструментов **Текущий контекст редактирования** выбран контекст редактирования и включен **Режим автоматического обновления контекста**).
· **Возможен выпуск изделий по документу**. Имеет значение только для типов объектов, расположенных в ветке **Документы**. Определяет возможность выпуска изделий по документу. При назначении этого свойства в карточке документа появится закладка **Объекты** , на которой будет отображаться список объектов, выпускаемых по данному документу (например, исполнения детали, выпускаемые по чертежу).
· **Возможна рассылка уведомлений о действиях над объектами**. При назначении этого свойства, в карточке объектов данного типа появится дополнительная закладка **Уведомления** , в которой пользователь сможет подписать себя на получение уведомлений (по электронной почте IPS) о выбранном объекте, если над этим объектом будут совершаться какие-либо действия. Данный сервис доступен, если в системе установлен модуль электронного документооборота.
· **Время жизни удаленных объектов**. Определяет количество дней, которое будут храниться объекты данного типа в базе данных после их удаления. По умолчанию содержит 0, что означает немедленное удаление объектов из базы данных. Удаление объектов с истекшим сроком хранения производится в процессе удаления мусора (см. п. )
· **Глобальный идентификатор**. Глобальный идентификатор типа объектов.
· **Запрет выпуска новых версий согласно настройкам шагов ЖЦ.** При включении опции, система предоставляет возможность выпускать новые версии объекта. Данная возможность доступна для тех объектов, условия которых удовлетворяют следующим требованиям: все существующие версии объектов находятся на шагах ЖЦ, у которых выключена опция **Запрет выпуска новых версий при наличии версии на этом шаге**.
· **Идентификатор**. Локальный идентификатор типа объектов. Назначается системой автоматически и не подлежит дальнейшей модификации.
· **Изображение**. Позволяет загрузить пиктограмму, отображающую суть данного типа объектов. Чтобы загрузить пиктограмму, нажмите кнопку, расположенную с правой стороны отмеченной строки, и в появившемся диалоге укажите путь к файлу пиктограммы. Система рассчитана на отображение иконок размером 64 x 32, 32 x 16 и 16 x 16 пикселей. 
· **Имя объекта**. Поле, обязательное для заполнения. Содержит наименование объектов данного типа, например, **Деталь**. Может быть длиной до 255 символов.
· **Индексировать таблицу атрибутов**. Позволяет включать/выключать в базе данных индексы для значений атрибутов объектов данного типа. Действует только на локальные типы объектов. По умолчанию флаг выключен, что позволяет ускорить операции записи значений атрибутов и уменьшить размер базы данных. Включать индексацию нужно только в тех случаях, если требуется поиск/сортировка по значениям атрибутов, для которых система не может использовать индексы в оптимизационной таблице объектов данного типа, например, если нужен регулярный поиск по значениям многозначного атрибута среди объектов данного типа. 
· **Классификация создаваемых объектов.** Позволяет определить, нуждаются ли объекты данного типа в классификации:
− **Обязательная классификация** — требует обязательной классификации при создании объектов данного типа.
− **Выборочная классификация** — при создании объектов данного типа классификацию можно будет пропустить.
− **Не классифицировать** — при создании объектов данного типа диалог классификации появляться не будет. Однако в дальнейшем объекты данного типа могут быть классифицированы, например, с помощью команд **Навигатора** **Копировать/Вставить**.
· **Комментарий.** Позволяет внести пояснения относительно назначения данного типа объектов (до 450 символов). 
· **Копировать права доступа в новую версию.** Позволяет копировать права доступа из версии объекта, на основе которой создается новая версия, для назначения их новой версии объекта данного типа.
· **Краткое наименование.** Позволяет указать уникальное краткое наименование типа объектов (до 32 символов). Может содержать пустое значение. 
· **Локальный тип объектов.** Включает признак локального типа объектов. Для объектов локального типа не действуют правила наследования видимости, т.е. объекты данного типа нельзя будет увидеть в списке всех объектов, зарегистрированных в системе. Также они не будут видны (и, соответственно, не могут быть найдены) в списках объектов родительских типов. Это позволяет уменьшить количество записей в оптимизационных таблицах объектов и, тем самым, увеличить производительность системы в целом. Однако следует помнить, что не все функции системы могут работать с локальными типами объектов. Например, локальные типы документов нельзя помещать в архивы, т.к. они не смогут быть видны в списке документов архива.
· **Любой атрибут.** Определяет, можно ли добавлять к объектам данного типа любые атрибуты.
· **Мандатное разграничение доступа.** Включает для объектов данного типа режим мандатного разграничения прав доступа (см. п. ).
· **Наименование.** Уникальное наименование типа объектов (до 255 символов).
· **Наследование прав доступа.** Позволяет при вычислении прав доступа к объекту данного типа использовать применяемость объекта связями, указанными в свойстве **Связь по умолчанию**. В этом случае при отсутствии прав, назначенных непосредственно данному объекту, система получает объекты, в которых применяется данный объект, и производит проверку аналогичных прав доступа у них. Проверка производится рекурсивно до верхнего уровня вложенности объектов (или до обнаружения объекта, которому эти права были назначены), поэтому включение данной опции может сильно замедлить обработку системой объектов данного типа. Не рекомендуется включать такую проверку для объектов, которые могут иметь множественную применяемость указанным типом связи!
· **Объекты выпускаются в рамках текущего проекта**. При включении данной опции система начинает автоматически присваивать создаваемым объектам данного типа принадлежность к текущему проекту, если текущий проект выбран пользователем в интерфейсе клиентской программы IPS (см. ).
· **Предметная область.** Позволяет отметить в выпадающем списке предметные области, к которым относится тип объектов. Если указано значение **Все** , то данный тип объектов будет виден всем пользователям, независимо от предметных областей, с которыми они работают.
· **Разрешить создание итераций.** Данный флаг включает команды создания и просмотра списка итераций для объектов данного типа.
· **Разрешить создание итераций в автоматическом режиме.** При включении данного режима система будет автоматически создавать итерации объектов данного типа сразу после изменения любого из атрибутов, влияющих на дату модификации содержимого объекта. Соответственно, для включения данного режима нужно, чтобы данному типу объектов был добавлен атрибут **Дата модификации содержимого объекта** , а также был включен флаг **Разрешить создание итераций**. Следует учитывать, что созданная в данном режиме итерация содержит только один изменившийся объект, поэтому для отдельных типов объектов могут возникнуть трудности с восстановлением взаимосвязанных данных, т.к. их сохранение пройдёт в разных итерациях (либо не произойдёт вообще, если администратор не включил данный режим для всех взаимосвязанных типов объектов).
· **Расширенная регистрация событий в журнале.** Включенный параметр позволяет системе IPS дополнительно записывать в журнал событий некоторые действия пользователей, такие как открытие карточки объекта.
· **Связь по умолчанию.** Позволяет указать тип связи, который будет использоваться клиентской программой для показа состава объектов данного типа. В дополнение к данной настройке администратор может назначать типы связей для ролей (см. п. ). Например, для роли **Технолог** в составе сборочных единиц кроме связей между изделиями могут просматриваться также и технологические связи.
· **Скрывать диалог включения в итерацию объектов состава**. Включенное свойство позволяет показать сокращенный диалог по созданию или сохранению итерации при выполнении команд **Создать /Итерацию** или **Сохранить в итерацию**.
