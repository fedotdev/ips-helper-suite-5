# Операторы поиска объектов
Операторы поиска объектов – наиболее важные операторы в скрипте, поскольку именно от них обычно зависит правильная работа скрипта и его производительность. Эти операторы позволяют выбирать объекты нужных типов, используя связи между объектами. Кроме того, операторы поиска объектов позволяют сохранить значения атрибутов, которые потребуются при обработке других операторов, в памяти, что позволит не считывать эти значения каждый раз. Существует пять операторов поиска объектов:
 **родительские** объекты - те, в которые непосредственно входит текущий объект контекста. 
 **дочерние** объекты – те, которые непосредственно входят в текущий объект контекста.
 **связанные** объекты – те, которые имеют какие-либо связи с текущим объектом контекста.
 **содержащие** объекты – все объекты, в которые входит текущий объект (не обязательно непосредственно).
 **вложенные** объекты – все объекты, входящие в текущий объект (не обязательно непосредственно). 
В самом простом случае для поиска объектов требуется указать, по каким связям нужно искать объекты, каким условиям они должны удовлетворять, и какие атрибуты объектов и связей нужно запомнить для последующего использования. Желательно задавать типы искомых объектов и связей, если другие типы объектов и связей не нужны. Это позволяет существенно повысить эффективность работы оператора, поскольку без задания типов система будет искать _все_ объекты по _всем_ типам связей.
В результате выполнения оператора поиска экспертная система создает временную таблицу, в которую помещаются все найденные объекты. Временная таблица существует только при выполнении оператора поиска объектов и вложенных в него операторов. Если нужно сохранить найденные данные надолго, для этого следует использовать глобальную таблицу, которая не удаляется даже после завершения работы скрипта генерации документа. Правила работы с глобальной таблицей будут описаны в п. .
Операторы **вложенные объекты** и **содержащие объекты** обычно выполняются намного дольше прочих операторов поиска объектов, поскольку они не останавливаются после нахождения непосредственно связанных объектов, а производят последовательный поиск для каждого найденного объекта, пока они не закончатся. Следует по возможности избегать использования этих операторов.
**Внимание!** Если текущий контекст состоит из нескольких объектов, экспертная система будет обрабатывать результаты поиска для каждого из них, а потом объединит все найденные результаты вместе во временной таблице. 
Для выбора типов объектов используется панель **Искать объекты и связи следующих типов**. Для редактирования типов объектов нажмите кнопку **Настроить типы объектов** справа от панели, а типов связей – кнопку **Настроить типы связей**. Нажатие этих кнопок приводит к появлению диалогового окна, в котором требуется пометить нужные типы объектов или связей.
Панель **Собираемые атрибуты и сортировка** позволяет выбрать атрибуты объектов и связей, которые будут собираться во временной таблице для каждого найденного объекта. Для добавления атрибута объекта нажмите кнопку **Добавить атрибут объекта** , атрибута связи – кнопку **Добавить атрибут связи** , а для удаления текущего атрибута – кнопку **Удалить** . Чтобы задать сортировку временной таблицы, выберите атрибут, по которому нужно сортировать, и нажмите переключатель , пока не установите требуемую операцию сортировки. Этот переключатель может принимать следующие значения: **Без сортировки** , **Сортировать по возрастанию** и **Сортировать по убыванию**. Можно определить сортировку по нескольким атрибутам сразу – в этом случае система сначала будет сортировать по комбинации атрибутов, в порядке их указания.
**Условие выбора объектов** – это обычная логическая формула экспертной системы, которая позволяет отбросить те объекты, которые не должны попасть во временную таблицу. Его можно задать в соответствующем окне так же, как и любое другое условие.
**Внимание!** В операторах и следует задавать условия выбора объектов и тип выбираемых объектов с особой осторожностью, поскольку и условие, и соответствие типа объекта проверяются на каждом шагу поиска объектов, а не к общему результату поиска. Например, если требуется получить объекты типа **Переход** , которые обычно не входят непосредственно в объект типа **Техпроцесс** , но входят в его развернутый состав, нельзя назначать условие **Тип объекта = Переход** в качестве условия выбора объектов, поскольку оно отфильтрует промежуточные объекты, и оператор не вернет никаких результатов.
Для задания условий на выбор объектов можно также использовать выборку базы данных. Создание выборок описывается в . Выборки для скриптов относятся к отдельному подтипу **Выборки и классификаторы / Общие выборки / Выборки для скриптов ЭС**. Для установки выборки нажмите кнопку , а для ее удаления – кнопку . Кнопка позволяет создать новую выборку. Выборки обычно работают быстрее, чем обработка условий экспертной системы, но обеспечивают меньше функций. Поэтому желательно использовать выборки для всех задач, для которых они подходят.
Переключатель **Не по глобальной таблице** позволяет указать способ поиска объектов. Его следует включать в том случае, если поиск объекта следует выполнять не по глобальной таблице (см. п. ).
**Внимание!** Поиск не по глобальной таблице будет обращаться за информацией в базу данных, так что займет намного больше времени, чем поиск по глобальной таблице. Его следует использовать лишь тогда, когда нет глобальной таблицы, или вы по каким-то причинам не хотите заносить туда данную информацию.
На закладке **Глобальная Таблица** можно определить, нужно ли использовать глобальную таблицу, нужно ли ее сохранять, а также прочие настройки выбора объектов. Переключатель **Добавить текущий объект в таблицу** предписывает занести во временную таблицу не только результаты поиска объектов, но и сам исходный объект, для которого также будут получены значения всех заданных атрибутов. Это часто используется при сохранении глобальной таблицы.
Использовать глобальную таблицу можно двумя способами, в зависимости от того активировано ли свойство **Не по глобальной таблице** на вкладке **Объекты, связи и атрибуты**. 
Если свойство **Не по глобальной таблице** активно, поле **Данные из глобальной таблицы** можно указать, что результат текущего поиска требуется объединить с данными глобальной таблицы (кнопка **Объединение**) либо отфильтровать только те объекты, которые присутствуют в глобальной таблице (кнопка **Пересечение**). По умолчанию данные из глобальной таблицы не используются (кнопка **Не использовать**).
При не активном свойстве **Не по глобальной таблице** необходимо искать объекты не путем запросов в базу данных, а только среди тех объектов и связей, которые были сохранены в глобальной таблице. Это позволяет существенно сократить время обработки скрипта, особенно если одно сохранение развернутой структуры объекта в глобальной таблице позволяет включить этот переключатель для большинства остальных операторов поиска объектов.
При поиске по глобальной таблице вместо кнопок **Не использовать** , **Объединение** и **Пересечение** появляются кнопки **Обычный поиск** и **Все данные**. В режиме **Все данные** экспертная система вообще не проводит никакого поиска, а в качестве результата поиска используются все записи глобальной таблицы, удовлетворяющие условию выбора объектов (см. ниже). Режим **Обычный поиска** используется в тех случаях, когда нужно выбрать не все объекты глобальной таблицы, а только те, из которых состоят (или в которые входят) объекты контекста.
Оба способа позволяют задать дополнительное условие выбора объектов, по которому экспертная система отфильтрует объекты глобальной таблицы перед объединением, пересечением или поиском. 
**Условие развертывания структуры (на каждом шагу)** для операторов, которые ищут больше, чем на один уровень (**Содержащие объекты** или **Вложенные объекты**) позволяет задать условие, которое будет отрабатывать на каждом шагу и обрежет ненужные ветви выбора. 
**Условие после выбора** для операторов, которые ищут больше, чем на один уровень (**Содержащие объекты** или **Вложенные объекты**) позволяет указать условие после всего выбора. Пример: условие "тип объекта = Нормирование" на каждом шагу не позволит добраться до объектов Нормирование, поскольку промежуточные объекты будут иметь другой тип. Если такое условие задать после выбора, то такое условие отработает правильно.
Работая с глобальной таблицей, следует задавать ограничения на типы объектов и связей только в том случае, если объекты и связи других типов не должны попадать в таблицу даже в качестве промежуточных. Желательно указывать только те атрибуты, которые часто используются в операторах, использующих глобальную таблицу – задание лишних атрибутов на всякий случай может значительно замедлить формирование глобальной таблицы.
Для изменения глобальной таблицы служит группа кнопок **Изменение глобальной таблицы**. По умолчанию выбрана кнопка **Без изменений** , при которой глобальная таблица не меняется. Выберите **Сохранить данные** , чтобы сохранить результат поиска объектов из временной таблицы в глобальную, **Добавить данные** , чтобы дописать в глобальную таблицу данные о найденных объектах и **Очистить таблицу** , чтобы удалить из глобальной таблицы все данные (обычно используется перед серией операторов с установкой **Добавить данные**).
Дополнительные параметры поиска объектов можно указать на закладке **Прочие**. Переключатель **Сохранять дубликаты** позволяет задать режим, при котором один и тот же объект будет занесен во временную таблицу столько раз, сколько раз он встретится при поиске. Это обычно используется при подсчете количества объектов, материалов и т.д. По умолчанию этот переключатель выключен, и при этом каждый объект заносится в таблицу только один раз.
При необходимости экспертная система допускает сортировку с использованием пользовательской функции сравнения объектов. Для этого требуется написать соответствующую функцию и зарегистрировать ее на сервере ЭС (см. **п. 9.1.3 Функции сравнения в «Руководстве программиста»**). Если регистрация прошла успешно, то выбрать нужную функцию сравнения можно будет в поле **Внешняя функция сравнения при сортировке объектов**. Если для скрипта была назначена специальная функция сортировки, следует включить переключатель **Встроенная сортировка**.
Группа **Исполнения** позволяет определить режим работы с исполнениями изделий, если они есть. Существует четыре режима работы с исполнениями:
· **Не учитывать исполнения**. В этом режиме ЭС вообще не учитывает исполнения изделий, входящих в текущий контекст.
· **Общая часть для всех исполнений**. В этом режиме выделяется только общая часть для всех исполнений изделий контекста – то есть, те изделия, которые входят во все исполнения.
· **Переменная часть текущего исполнения** _._ Экспертная система найдет только ту часть состава текущего исполнения, которая не входит в общую часть для всех исполнений. Цикл по всем изменениям организуется модификатором **Для всех**.
· **Все данные для всех исполнений**. Экспертная система найдет все изделия, которые входят хотя бы в одно исполнение.
Переключатель **Использовать имеющиеся исполнения** позволяет не получать структуру изменений заново, а использовать ту структуру, которая была получена прежде. Это экономит время, избавляя от повторного анализа структуры исполнений.
Группа **Опции состава** позволяет задать необходимость использования опций конфигуратора составов и опций показа скрытого состава. Если включен переключатель **Использовать опции конфигуратора составов** , оператор поиска объектов найдет не все объекты состава, а только те, которые входят в конфигурацию, определяемую текущими опциями конфигуратора составов. Радиокнопки из этой группы позволяют задать режим работы со скрытым составом:
· **Показывать весь состав**. В этом режиме, который установлен по умолчанию, ЭС вообще не учитывает установки скрытия состава. 
· **Не показывать скрытый состав** _._ В этом режиме в получаемые данные входят объекты, структура которых должна быть скрыта, но не их состав.
· **Не показывать скрытый состав и объекты с ним** _._ В этом режиме в получаемые данные не входит не только состав объектов, но и сами объекты со скрытым составом.
**Внимание**! Операторы поиска объектов обычно изменяют текущий контекст. Если у оператора нет модификаторов, то его дочерние операторы будут выполняться для набора объектов, найденных оператором поиска. Если модификаторы есть, они могут повлиять на контекст дочерних операторов – описание модификаторов приводится в п.
