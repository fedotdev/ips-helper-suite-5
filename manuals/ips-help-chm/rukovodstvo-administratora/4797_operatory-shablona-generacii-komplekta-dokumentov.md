# Операторы шаблона генерации комплекта документов
Операторы шаблона генерации документов доступны в скриптах **Шаблоны комплекта документов** (см. п. ). Эти шаблоны отличаются от остальных видов скриптов тем, что они намного проще – в частности, они не содержат никаких модификаторов.
В шаблонах генерации комплекта присутствует оператор поиска вложенных объектов , который предназначен для сохранения развернутой структуры исходного объекта в глобальной таблице. Эту таблицу впоследствии можно использовать во всех скриптах генерации документов, чтобы больше не обращаться к базе данных. 
**Внимание**! Если развернутая структура сохраняется, соответствующий оператор должен быть первым в шаблоне генерации комплекта. В противном случае экспертная система полагает, что сохранение структуры не задано и производит его автоматически. Не нужно сохранять структуру в каждом скрипте генерации документа – достаточно сделать это один раз в шаблоне генерации комплекта.
В настоящее время вместо оператора **Сохранять структуру** используется операторы **Сбор глобальной таблицы** и **Для типа объектов**. Подробнее описание работы с данными операторами будет дано в п. .
Шаблон генерации комплекта документов имеет структуру, сходную с тем комплектом, который должен получиться в результате. Как правило, на верхнем уровне находится головной комплект документов, в который могут входить дочерние комплекты и документы. Следовательно, и в шаблоне генерации комплекта нужно ввести оператор создания головного комплекта, в который будут входить операторы создания дочерних комплектов и документов, как изображено на рисунке выше.

Выключение переключателя **Создать комплект** позволяет отказаться от создания объекта комплекта; в этом случае созданные документы войдут в состав комплекта верхнего уровня. Например, на рисунке ниже слева показан пример, когда в шаблоне, комплекты на операцию не создаются, и все документы войдут в состав головного комплекта документов на технологический процесс (переключатель выключен). На рисунке справа создается отдельный комплект документов на операцию (переключатель включен).
**Внимание**! Головной комплект будет создан независимо от состояния переключателя **Создать комплект**. В противном случае создаваемые документы было бы некуда включать.
Параметр **Комплект для типа объекта** , позволяет экспертной системе определить, для каких объектов их нужно создавать. Для каждого объекта заданного типа, входящего в развернутую структуру текущего объекта контекста при выполнении данного оператора, будет создан один объект комплекта документов. 
Для ввода типа создаваемого объекта присутствует поле **Тип комплекта документов**.
Параметр **Тип связи к комплекту документов** , позволяет указать тип связи, по которой будет добавлен комплект документов к объекту. Необходимо помнить, что данная связь должна быть определена между объектом и комплектом документов в конфигураторе.
Поле **Постфикс** позволяет задать краткое сокращение, которое будет использовано для присвоения наименований создаваемым документам. Если объект, на который был создан документ, имеет номер, то название документа будет состоять из номера и постфикса (например, «005 ОК»), а если не имеет – из обозначения объекта и постфикса (например, «А001.М1. ТП КТД»).
Параметр **Дополнительный комплект** позволяет пометить комплект документов, который будет формироваться по необходимости по команде **Дополнительный комплект** и добавляться в основной комплект с соответствующим постфиксом. Данный комплект документов при формировании основного комплекта командой **Генерация комплектов документов** не формируется. 
Поле **Условие** позволяет задать условие, при выполнении которого будет создаваться комплект. Если это условие не будет выполнено, то комплект не будет создан, и все операторы, входящие в текущий, не будут выполняться для данного объекта. Условие вводится точно так же, как и для других операторов.

В верхней части окна настройки параметров оператора при помощи радиокнопки можно выбрать тип (скрипт, сценарий или настройки) используемый для формирования документа.
**Документ генератора ЭС** использует для формирования документа объект **Скрипт генерации документов**.
**Сценарий генерации на С#** использует для формирования документа скрипт, написанный на языке **C#.**
**Документ TECHCARD** использует для формирования документа объект **Настройки документов TechCard**.
В поле ниже указывается сам скрипт генерации документов, сценарий С# или настройка документов TechCard.
В поле **Документ для типа объектов** выбирается объект, для которого предназначен данный документ. Как и оператор создания комплекта, оператор создания документа также будет выполнен по одному разу для каждого объекта заданного типа, входящего в развернутую структуру текущего объекта контекста. Например, оператор создания карты эскиза будет выполнен для каждого объекта эскиза, входящего в текущую операцию.
Переключатель **Не создавать пустой документ** позволяет задать собственный механизм определения, какие документы являются пустыми и, следовательно, не должны создаваться – например, операционная карта может быть пустой, если операция не содержит ни одного перехода. Если этот переключатель включен, экспертная система перед генерацией каждого документа по этому оператору присваивает системному атрибуту **Признак пустого документа** значение **истина** , и, если скрипт генерации документа не присвоит ему значение **ложь** , документ будет удален как пустой.
Настройка **Брать документ соисполнителя** позволяет не генерировать заново документы, которые были сгенерированы ранее в шаблоне комплекта соисполнителя. В шаблоне комплекта соисполнителя должен быть включен переключатель **Шаблон соисполнителя**. 
Например, соисполнитель разработал операцию и сформировал комплект документов соисполнителя для данной операции.
При генерации владельцем ТП комплекта документов на техпроцесс данные документы, если они отмечены галочкой **Брать документы соисполнителя** в шаблоне документов на ТП, не будут заново генерироваться, а будут скопированы из комплекта документов соисполнителя.
Настройка **Не нумеровать** отвечает за нумерацию документа в комплекте документов. Если переключатель включен, значение идентификатора, отвечающего за нумерацию страниц документа в комплекте документов (см. рис. ниже) не будет выводиться. При этом в общем количестве листов комплекта документов данные страницы будут учитываться, если не установлена галочка **Не включать в общее количество листов**.
Некоторые документы должны создаваться только после того, как будут созданы все остальные документы – например, ведомость технологических документов (ВТД). Для таких документов следует включать переключатель **Второй проход**.
**Внимание**! операторы создания документов и комплектов будут выполнены несколько раз, по очереди для каждого подходящего объекта, хотя в шаблоне нет никаких операторов поиска объектов и модификаторов, предписывающих выполнение операторов для найденных объектов. Шаблоны комплектов документов обрабатываются **не так** , как прочие скрипты – подобное неявное поведение позволяет сильно упростить шаблоны, а также ускорить их обработку.
Поле **Постфикс** аналогично такому же полю - оператора **Создать комплект**.
Радиокнопки **Документ на группу объектов** применяются для изменения последовательности вывода группы объектов. 
При выборе опции **Нет** все объекты, удовлетворяющие условию, будут выведены в отдельные документы.
При выборе опции **Последовательные объекты** все объекты, удовлетворяющие условию, будут выведены в несколько отдельных документов. В каждом документе допускается вывод только последовательных объектов, до тех пор, пока какой-либо из объектов перестанет удовлетворять условию вывода. Следующий объект, из группы который будет удовлетворять условию будет выводится в новом документе. Пример см. ниже.
При выборе опции **Все объекты** все, удовлетворяющие условию, объекты будут выведены в один документ.
Например, имеется ТП с 5-ю эскизами. Эскизы 1.1, 1.2, 2.1, 2.3 имеют формат КЭ – А4, эскиз 2.2 – А3.
В **Условии при генерации**(описание см. ниже) в параметрах шаблона документа задана формула для вывода только эскизов формата А4. 
При генерации комплекта документов с включённой опцией **Нет** , в комплекте документов будет сформировано 4 документа, в каждом по 1 эскизу (см. рис. ниже слева). При выборе опции **Последовательные объекты** в комплекте документов будут сформированы 2 документа. В первом документе будут отображаться эскизы 1.1, 1.2, 2.1, во втором – эскиз 2.3, т.к. эскиз 2.2 не удовлетворяет условию <Формат КЭ> = "А4" и соответственно последовательность объектов прерывается (см. рис. ниже в центре). При выборе опции **Все объекты** в комплекте документов будут сформирован один документ, в котором будут отображены все эскизы, удовлетворяющие условию: 1.1, 1.2, 2.1, 2.3 (см. рис. ниже справа).
Оператор создания документа также имеет **Условие при генерации** , которое должно быть истинным для того, чтобы экспертная система сгенерировала документ. В этом условии можно использовать значения временных атрибутов, установленные при генерации предыдущих документов: например, таким образом можно вывести первый из эскизов на операцию в операционную карту с эскизом, а для остальных создать отдельные карты эскизов. Для этого скрипт генерации операционной карты с эскизом должен запомнить идентификатор первого эскиза, а в операторе генерации карт эскизов следует наложить условие **идентификатор объекта не равен запомненному**. 
**Предварительное условие** работает по аналогии с **Условие при генерации** за исключением того, что данного условие проверяется на этапе сбора всех данных по комплекту. Тогда как условие при генерации уже непосредственно при генерации этого документа. Таким образом если предварительное условие не выполняется, то объект для которого должен быть сгенерирован документ будет пропущен. На рисунках ниже показан пример генерации документа МК на техпроцесс с видом производства мехобработка. Было задано условие на вывод документа <Техпроцесс единичный>.<Вид производства> = Окраска. В первом рисунке показан пример окна **Информация трассировки** , когда условие задано как предварительное, во втором как условие при генерации.
Оператор **Ссылка на документ** позволяет вывести в комплекте документов объект, ссылающийся на документ, в составе объекта, на который формируется комплект документов, и просматривать его в комплекте. 
В поле **Создавать ссылку на объект типа** необходимо выбрать тип объекта - документ, который нужно передать в ссылку.
В поле **Тип создаваемого объекта со ссылкой** необходимо выбрать тип объекта, который будет создан как ссылка на объект-документ.
В области **Копировать атрибуты** добавляются атрибуты, значения которых необходимо скопировать из объекта-документа во вновь созданный объект со ссылкой.
Например, в ТП на операцию присутствует документ – Инструкция #1(docx). При формировании комплекта документов, в комплекте документов появится объект Ссылка на Инструкция #1(docx), при просмотре которого отображается сам документ Инструкция #1(docx).
**Внимание**! Для правильной работы данного оператора обязательно в сборе глобальной таблицы для типа объекта указать поиск объектов, на который будет ссылаться данный оператор.
