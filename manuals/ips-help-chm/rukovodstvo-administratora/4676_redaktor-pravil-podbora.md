# Редактор правил подбора
В приведенном выше примере, новое правило было создано на основе правила **Последние версии объектов**. В редакторе, появившемся на втором шаге работы мастера по созданию нового объекта, доступны один основной критерий **Номер версии объекта – АТРИБУТ НЕ ПУСТ** , и один дополнительный критерий **Номер версии объекта – ИМЕЕТ МАКСИМАЛЬНОЕ ЗНАЧЕНИЕ**.

Рассмотрим подробнее архитектуру редактора:
**1\. Панель инструментов:**
 – добавить критерий подбора версий в правило.
 – удалить текущий критерий подбора версий из правила.
 – добавить значение для сравнения в текущий критерий подбора версий.
 – удалить текущее значение для сравнения из текущего критерия.
 – переместить критерий для сравнения вверх по списку критериев.
 – переместить критерий для сравнения вниз по списку критериев.
**2\. Область, в которой находится дерево основных критериев подбора:**
В дереве отображаются основные критерии подбора, а также их содержимое.
Столбец **Критерии, виды значений для сравнения** отображает атрибуты фильтруемой версии, значения которых будут передаваться в функцию для сравнения во время подбора версий.
 – кнопка, с помощью которой открывается диалоговое окно выбора атрибута.
Столбец **Отрицание** отображает статус переключателя отрицания значений функции. В выпадающем списке пользователь может выбрать значение НЕТ, которое даст инвертированный **(ДА/НЕТ, НЕТ/ДА)** результат выполнения функции сравнения. 
Столбец **Функция сравнения, аргументы** отображает функцию сравнения из выпадающего списка. Список функция сравнения изменяется от типа данных в атрибуте критерия.
Столбец **Объединение** отображает указанное группирование нескольких критериев сравнения.
**3\. Панель управления:**
Панель управления содержит настройки дополнительного критерия подбора версий, фильтрации и т.д..
На строке **Дополнительный критерий** : пользователю предоставляется возможность выбрать атрибут дополнительного критерия посредством кнопки . В дополнительном критерии подбора версий могут использоваться следующие функции равнения: **БАЗОВАЯ ВЕРСИЯ ОБЪЕКТА, ИМЕЕТ МИНИМАЛЬНОЕ ЗНАЧЕНИЕ или ИМЕЕТ МАКСИМАЛЬНОЕ ЗНАЧЕНИЕ**.
На строке **Фильтровать составы по дате** пользователю предоставлена возможность указать дату выполнения подборы версии.
Опция **Раскрывать все узлы** позволяет раскрыть все узлы в дереве основных критериев подбора версий при условии, что переключать включен.
Опция **Правило** **для редактирования**. Данная опция позволяет изменить атрибут **Запрет использования правила при редактировании объектов** с примечанием **"Используется для запрета использования правила при выполнении команд Редактировать, Открыть, Открыть с помощью...".**
Опция **Игнорировать пользовательскую конкретизацию.** При включении данной опции подбор по мягкой конкретизации будет игнорироваться.
Опция **Правило по умолчанию**. Глобальная настройка для всей базы данных IPS. Правило, выбранное по умолчанию, будет предлагаться для фильтрации составов по умолчанию. 
Для редактирования нового правила подбора версий следует:
1\. Добавить новый критерий подбора с помощью кнопки __.
2\. В открывшемся диалоговом окне необходимо выбрать атрибут для критерия и нажать на кнопку .
3\. В столбце **Функции сравнения, аргументы** следует выбрать из выпадающего списка необходимую функцию сравнения для нового критерия.
_Примечание: описание всех функций сравнения, допустимые функции сравнения для различных типов данных атрибутов можно отыскать в**«Руководств е**_** _программиста» в п. 6.3.1.7_** _**Фильтрация состава**. **Применимость функций сравнения к типам данных атрибутов.**_
В примере выберем функцию сравнения **В УКАЗАННОМ ДИАПАЗОНЕ (С ГРАНИЦАМИ)**. Для данной функции допускается два значения для сравнения – нижняя граница диапазона и верхняя граница диапазона.
4\. Следует выбрать значение для сравнения.
Значения для сравнения бывают трех видов:
− атрибут;
− константа;
− значение пользователя.
5\. В столбце **Функции сравнения, аргументы** с помощью выпадающего списка необходимо указать временной диапазон.
Примечание: установка временного диапазона необходима для того, чтобы подбор версии объектов осуществлялся по значению атрибута **Дата модификации содержимого объекта** , значение которого удовлетворяет указанным условиям (включительно). 
6\. При необходимости можно добавить второй основной критерий подбора версий, для этого следует нажать кнопку или воспользоваться командой Добавить критерий из контекстного меню.
7\. В открывшемся окне выберем атрибут-критерий:
8\. Для выбранного критерия следует указать функцию сравнения.
9\. При необходимости следует указать отрицание значения этой функции.
Примечание: комбинация функция и отрицание, что описаны в пп. 8,9, позволяет подбирать все версии объектов, у которых указанный атрибут отсутствует, либо у него нет значения (т.е. объекты, для которых не настроена видимость).
10\. Для группировки двух критериев следует выбрать **И** в столбце **Объединение**.
Примечание: если сгруппировать критерии, то будут подбираться только те версии объектов, которые соответствуют сразу обоим критериям подбора.
11\. При необходимости следует настроить дополнительный критерий
**Внимание!** По умолчанию включен переключатель **Правило для редактирования** , следовательно, доступна только одна функция сравнения – **Базовая версия объекта**. Если требуется выбирать не базовую версию, а отобранную по другим функциям сравнения, следует выключить переключатель **Правило для редактирования**.
**Внимание!** Настройка **Фильтровать составы по дате** может использоваться только в том случае, если среди основных критериев подбора есть критерий для атрибутов **Шаг жизненного цикла** или **Уровень продвижения**. В остальных случаях включить данную настройку нельзя.
12\. Для завершения создания правила подбора версий, необходимо нажать кнопку .
