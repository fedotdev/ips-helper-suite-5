# Как работает экспертная система
При любом расчете и любой генерации документа надо обязательно учитывать, в каком контексте они должны работать. **Контекст** – это объект либо набор объектов, для которых запускается расчет или генерация документа. При расчете значения атрибута в расчет принимается только один объект контекста (если передано несколько объектов, берется первый из них).
Когда пользователь или какая-либо сборка запускает расчет какого-нибудь параметра, в первую очередь экспертная система ищет правила расчета этого параметра. Обычно параметр определяется в виде пары **< Тип Объекта>** и **< Тип атрибута>**. Если такого правила нет, экспертная система пытается загрузить общее правило расчета для данного типа атрибутов (без учета типа объекта). Правила расчета атрибута – это скрипт особого типа, который обязательно включает все формулы, таблицы и скрипты экспертной системы, которые можно использовать для определения значения искомого атрибута.
**Внимание**! После сохранения объектов экспертной системы, позволяющих рассчитать значения тех или иных атрибутов, система автоматически запоминает, что эти атрибуты можно рассчитывать с помощью сохраненных объектов. Если правил расчета атрибута не существовало, то они будут созданы, и, если там не было ссылки на сохраняемый объект, то она будет добавлена.
Каждый объект экспертной системы (формула, таблица или скрипт) обычно снабжается условием, которое определяет, когда этот объект может применяться для расчета, а когда не может. Экспертная система выполняет правила расчета атрибутов по тем же правилам, что и любой скрипт – то есть, сверху вниз. Как только будет найдена формула, таблица или скрипт с истинным условием (для проверки условия используется объект контекста), она и будет применена. Если с ее помощью удастся получить результат, прочие объекты в правилах не будут рассматриваться, несмотря на то, что среди них могут быть и другие объекты с выполняющимися условиями. Таким образом, правила расчета атрибута также определяют последовательность применения объектов экспертной системы.
Нередко для расчета значения параметров не хватает значений других параметров. В этом случае экспертная система пытается вычислить значение всех недостающих параметров, используя тот же алгоритм, что и при вычислении исходного параметра – загружаются правила расчета атрибута, и экспертная система начинает анализ объектов, с помощью которых можно рассчитать его значение. Таким образом, цепочка рассчитываемых параметров может быть достаточно длинной, и расчет значения параметра может занимать достаточно длительное время. Если окажется, что система уже пыталась искать один из недостающих параметров, расчет закончится неудачно.
**Внимание**! Если при расчете условия экспертная система не может найти значение какого-либо атрибута, условие считается **ложным**. Это избавляет от получения случайных результатов – например, вследствие использования формул и таблиц, которые не должны были использоваться. Если необходимо, чтобы условие могло работать и при отсутствующих значениях атрибутов, следует использовать функцию Def (см. п. ) или переключатель **Если нет значения атрибута, подставлять пустое**.
При выполнении любой операции экспертная система генерирует **отладочную информацию** , которая имеет иерархическую структуру. Эта информация позволит вам узнать, что делала экспертная система, а если она не работает так, как ожидалось – узнать причину этого. Как правило, отладочная информация выдается после завершения задачи, хотя некоторые модули могут получать ее по команде пользователя (это необходимо, например, чтобы определить, почему задача не завершается).
Полный отчет трассировки может содержать огромное количество информации, в котором может быть трудно разбираться, несмотря на иерархическую структуру. К счастью, экспертная система позволяет определить, какая информация должна попадать в отчет трассировки, а какая не должна. Для этого достаточно использовать команду **Настройка / Параметры IPS** и выбрать пункт **Система / Экспертная система / Трассировка**(см. п. ). Параметр **Флаги трассировки** позволяет указать, какую информацию следует включать в отчеты трассировки.
Для того, чтобы сохранить информацию трассировки, нажмите правую кнопку мыши и выберите в локальном меню команду **Сохранить**. Сохраненную информацию трассировки можно послать в службу технической поддержки ИНТЕРМЕХ, если ее сотрудники попросят об этом.
Каждый раз, когда экспертная система ищет значение какого-либо атрибута, исходной точкой для поиска является текущий объект контекста. Таким образом, если формула или таблица ссылается на какой-нибудь атрибут без указания типа объекта, экспертная система ищет этот атрибут в текущем объекте контекста. Если такого атрибута нет, она пытается рассчитать его значение обычным способом, а при неудаче выдается ошибка. То же самое происходит, если нужно найти пару **< Тип объекта>.<Тип атрибута>**, если нужный тип объекта совпадает с типом текущего объекта контекста.
Если же тип объекта не совпадает с типом текущего объекта контекста, экспертная система должна найти объект нужного типа, используя текущий объект контекста в качестве отправной точки. Для этого она использует правила поиска объектов нужного типа, если они существуют. Достаточно один раз определить, как экспертная система должна искать объекты используемых вами типов, и в дальнейшем об этом можно не беспокоиться. Если правил поиска объектов нужного типа нет, или они не позволяют получить объект нужного типа, экспертная система выдаст ошибку.
Правила поиска объектов можно создавать как общие (для объектов определенного типа, независимо от того, какой атрибут требуется получить у найденного объекта), так и специальные, которые будут работать только при поиске значения именно заданного атрибута. В первую очередь система ищет специальное правило, и только если его нет – общее. Это позволяет определить различные правила поиска объектов в зависимости от того, какой атрибут найденного объекта предполагается использовать.
