# Генерация документов и комплектов с использованием универсальных скриптовых языков программирования
Генерация сложных и больших по объему содержащейся информации документов посредством скриптов может занимать довольно продолжительное время – до нескольких часов. Сценарии представляют собой пользовательский код, написанный на одном из поддерживаемых системой языков программирования (в настоящее время только C#) и предназначены для генерации документов, ведомостей и комплектов документов на объекты любых типов. В системе существует два типа сценариев:
· Сценарии генерации документов и ведомостей – предназначены для генерации отдельных документов и ведомостей.
· Сценарии генерации комплектов документов – предназначены для генерации комплектов документов и ведомостей.
На выполнение сценарии вызываются соответственно командами контекстного меню **Отчеты и документы/Сценарии генерации документов и ведомостей** и **Отчеты и документы/Сценарии генерации комплектов документов**.
Основные атрибуты сценариев:
· **Типы объектов, на которые назначен сценарий**. Сценарий будет доступен на выполнение только для типов, указанных в этом атрибуте и их дочерним типам. Если типы не указаны, то сценарий будет доступен на выполнение для всех объектов.
· **Текст сценария**.
· **Язык сценария**.
· **Сторона выполнения сценария**. Клиент или сервер приложений.
Дополнительно для сценариев генерации документов доступны следующие атрибуты:
· **Шаблон генерируемого документа**. Содержит ссылку на шаблон, по которому генерируется документ. 
· **Тип генерируемого документа**. Если указан тип генерируемого документа, то после выполнения сценария система автоматически создаст документ указанного типа и заполнит его файл сгенерированным документом. 
· **Тип связи для включения документа в состав**. Если указан тип связи, то созданный по предыдущему пункту документ будет включен в исходный объект данным типом связи. 
· Доступны два режима работы. По умолчанию для каждого исходного объекта будет создан и включен в состав отдельный документ. Второй режим подразумевает создание одного документа и включение его в состав всем исходным объектам. Режимами можно управлять при помощи атрибута Один документ. (см.ниже)
· **Открыть в редакторе**. Если установлен этот флаг, то после выполнения сценария сгенерированный документ будет отображен в редакторе.
· **Один документ**. Если установлен этот флаг, то по результатам работы скрипта будет создаваться и включатся в исходные объекты указанным типом связи один документ. 
Если в сценарии заполнен атрибут **Тип генерируемого документа** , то после выполнения сценария система автоматически создаст документ указанного типа, заполнит его файл сгенерированным документом, заполнит наименование документа, а если указан атрибут **Тип связи для включения документа в состав** – включит созданный документ в исходный объект данным типом связи. При этом если у объекта будет в составе документ данного типа, то система предложит создать версию, создать новый документ или обновить существующий документ. 
Дополнительно для сценариев генерации комплектов документов доступны следующие атрибуты:
· **Шаблон комплекта документов**. Содержит ссылку на шаблон, по которому генерируется комплект документов. 
Для просмотра и редактирования текста сценария используется редактор сценариев, который открывается по команде **Смотреть** или **Редактировать** для сценария.
В коде функции Execute можно задать атрибуты генерируемому документу. Обозначение и Наименование можно указать в свойствах document.Designation и document.Name соотвественно. Для того, чтобы добавить документу другой произвольный, допустимый типом документа атрибут, необходимо воспользоваться методом document.SetAttributeValue([string attributeName], [string attributeValue]). В качестве attributeName указывается глобальный идентификатор типа атрибута и знак @ перед ним, например, для атрибута Примечание значение параметра attributeName будет выглядеть так: @cad00021-306c-11d8-b4e9-00304f19f545. В значение параметра attributeValue указывается устанавливаемое атрибуту значение в строковом виде.
