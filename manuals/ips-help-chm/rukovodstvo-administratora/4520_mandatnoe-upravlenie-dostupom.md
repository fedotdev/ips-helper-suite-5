# Мандатное управление доступом
Мандатное управление доступом – разграничение доступа субъектов (пользователей) к объектам, основанное на назначении метки конфиденциальности для информации, содержащейся в объектах, и выдаче официальных разрешений (допуска) субъектам на обращение к информации такого уровня конфиденциальности.
В качестве метки конфиденциальности в IPS служит обязательный атрибут **Уровень доступа объекта** , которым обладают все информационные объекты системы. Разрешением на допуск субъектов к информации управляет атрибут **Уровень доступа** , который назначен всем пользователям системы. Список допустимых значений данного атрибута определяет возможные уровни конфиденциальности информации, которая хранится в системе. Список возможных уровней можно изменять при соблюдении следующих условий:
· Минимальный уровень доступа должен иметь значение 0.
· Уровни доступа с большими значениями должны считаться более секретными.
· Во всех базах данных, с которыми производится обмен информационными объектами, список уровней доступа должен быть одинаковым.
· Изменять список уровней доступа нужно до того, как начался процесс присвоения уровней информационным объектам, иначе результат может быть непредсказуемым.
При входе в систему у пользователя запрашивается уровень доступа, с которым он будет работать в данной сессии. По умолчанию предлагается уровень доступа, назначенный пользователю администратором системы (либо тот, который был выбран пользователем в предыдущем сеансе работы), но пользователь может выбрать мЕньший уровень, если этого требует текущая работа. Для изменения уровня доступа сессии пользователя требуется перезагрузка клиента IPS.
Для того, чтобы объекты определённого типа могли получать уровни доступа, отличные от минимального, администратор IPS должен включить в Конфигураторе БД для данного типа объектов переключатель **Мандатное разграничение доступа**. 
После этого для объектов данного типа начинает применяться смешанная мандатно-дискретная модель разграничения доступа. Это значит, что в первую очередь система проверяет уровень доступа объекта. Если он выше уровня доступа сессии пользователя, то пользователь вообще не будет знать о существовании объекта. Если уровень доступа сессии равен уровню доступа объекта – пользователь имеет полные права на данный объект. Если уровень доступа объекта ниже уровня доступа сессии – пользователь может только просматривать объект, но не изменять (чтобы не внести в объект более секретную информацию).
Если уровень доступа сессии позволяет пользователю выполнить запрошенное действие над объектом, то система приступает к проверке дискретных прав доступа (см. п. ), а иначе пользователь получает отказ вне зависимости от дискретных прав, которыми обладает данный пользователь.
Уровень доступа присваивается объектам следующими способами:
· При содании объекта ему присваивается уровень доступа пользовательской сессии, создавшей объект.
· Пользователь может изменить уровень доступа уже созданного объекта на закладке **Свойства** , если он имеет право **Изменение уровня доступа объекта** для данного объекта.
· Уровень доступа объекта может быть автоматически повышен системой до уровня доступа пользовательской сессии в момент взятия объекта на изменение в том случае, если в системе включен режим **Настройка / Параметры IPS / Пользователи / Безопасность учётных записей / Автоматическое повышение уровня доступа редактируемых объектов**.
· При включении объекта в проект объект автоматически получает уровень доступа проекта.
Система накладывает ряд ограничений на объекты, связанные с уровнями доступа объектов:
· Нельзя вставлять в состав объекта объекты с уровнем доступа бОльшим, нежели уровень доступа самого объекта. При необходимости это сделать пользователь должен предварительно повысить уровень доступа вышележащего объекта. Данное ограничение может быть снято администратором системы с помощью опции **Настройки / Параметры IPS / Безопасность учётных записей / Разрешить секретные объекты включать в состав объектов с общим доступом.**
· В портфель IPS не могут быть записаны объекты с уровнем доступа выше, чем у сессии пользователя, которая вызвала формирования портфеля.
· На портал IPS не могут быть опубликованы объекты с уровнем доступа выше, чем у сессии пользователя, инициировавшего публикацию. На процесс публикации также накладывается ограничение уровня доступа системной сессии, которая занимается собственно публикацией данных на портал.
· У разных версий одного объекта могут быть разные уровни доступа. При этом во всех интерфейсных элементах (даже в дереве версий) пользователь будет видеть только те версии, уровень доступа которых не выше уровня доступа текущей сессии пользователя.
· У всех объектов с мандатным разграничением прав доступа, принадлежащих одному проекту, одинаковый уровень доступа – это уровень доступа самого проекта.
· При запуске IPS в режиме исполнения обязанностей уровень доступа сессии будет определяться максимальным уровнем доступа пользователя, обязанности которого будут исполняться. Однако этот уровень не должен превышать уровень доступа пользователя, который будет выполнять эти обязанности.
Примечание: видимость объектов контролируется системой независимо от значения переключателя **Мандатное разграничение доступа** у типа объектов. Это значит, что выключение мандатного разграничения доступа не изменит видимости объектов, которые уже были переведены на более секретные уровни доступа, а также не отключит контроль входимости более секретных объектов в менее секретные. После выключения данного переключателя нужно будет вручную вернуть объектам обычный уровень доступа.
