# Планировщик задач
IPS позволяет автоматически запускать на серверах приложений различные административные и рабочие задачи, используя для этого окно планировщика задач. Это, в частности, позволяет перенести выполнение трудоёмких задач на ночные часы и выходные, чтобы не замедлять работу системы в рабочие часы. Команда главного меню **Настройка/Планировщик** **задач** доступна администратору системы в случае, если загружен модуль **Конфигуратор базы данных.** По команде появляется окно со списком задач, запуск которых уже настроен в системе.
В поле **Приоритетный сервер обработки очереди задач** можно указать компьютер, который будет использоваться системой для запуска задач, у которых не указан обрабатывающий сервер. Для запуска задач на указанном компьютере должен быть запущен сервер приложений IPS, подключенный к этой базе данных. Кнопка **Изменить** подтверждает выбор сервера обработки задач. Если сервер не выбран, то обработкой очереди занимается первый из запущенных серверов приложений IPS. В этом случае обработка очереди автоматически передаётся другому серверу приложений IPS в случае остановки первого сервера.
В окне планировщика задач также доступны следующие команды:
 **Создать**. Позволяет настроить расписание запуска новой задачи на сервере приложений.
Для задачи нужно указать следующие параметры:
· **Выполняемая задача**. В списке доступных задач нужно выбрать задачу, расписание запуска которой нужно настроить. Список возможных задач зависит от версии IPS и загруженных на сервере модулей расширения системы. Любую задачу можно поместить в список выполнения произвольное количество раз, однако рекомендуется следить за тем, чтобы не накладывалось время выполнения одной и той же задачи, т.к. при этом могут возникать блокировки в базе данных.
· **Наименование задачи**. В этом поле можно указать наименование задачи, которое будет отображаться в списке настроенных задач.
· **Имя сервера**. В это поле можно указать имя сервера приложений, на котором должна запускаться настраиваемая задача. На этом сервере должен быть загружен сервер приложений IPS, работающий с этой базой данных. Данная настройка нужна для функционирования задач, запуск которых должен производиться только на определённом сервере.
· **Периодичность**. В этом поле нужно указать периодичность запуска задачи. Для разовой задачи нужно указать дату и время запуска задачи. Разовые задачи удаляются из списка задач сразу после выполнения. 
· **Расписание задачи**. Для периодических задач нужно указать расписание их запуска, а для разовых – дату и время запуска. 
· **Немедленно запускать задачу, если пропущен плановый запуск**. Если у задачи включен данный переключатель, то при старте сервера приложений задача будет сразу запущена на выполнение, если её плановый запуск был пропущен (например, из-за остановки сервера приложений). Не рекомендуется включать данный переключатель ресурсоёмким задачам, т.к. это может сильно замедлить запуск сервера приложений.
 **Редактировать**. Команда позволяет изменить свойства указанной в списке задачи.
 **Удалить**. Команда удаляет выбранную задачу из списка задач. Если задача в данный момент выполняется, то её выполнение прерываться не будет.
 **Запустить**. Команда немедленно запускает на выполнение выбранную в списке задачу. Запуск производится на сервере приложений, к которому в данный момент подключен клиент IPS.
 **Обновить**. Команда перечитывает с сервера список настроенных задач.
В минимальном комплекте поставки системы предусмотрены следующие задачи:
· **Диагностика системы**. Задача позволяет автоматически рассылать администраторам системы уведомления о наступлении событий, которые могут негативно сказаться на работоспособности системы (см. п. ).
· **Извещения: актуализация всех извещений, у которых наступил срок.** Задача отслеживает срок изменения и срок окончания изменения у всех извещений в базе IPS. Извещения, у которых наступил срок изменения, переводятся на шаг ЖЦ **Актуализация** , в том числе переводятся все объекты, включенные в эти извещения, на соответствующие шаги ЖЦ. Извещения, у которых наступил срок окончания изменения, переводятся на шаг ЖЦ **Хранение** , что также изменяет шаг ЖЦ включенных в извещение объектов.
· **Обновление значений атрибутов, полученных по ссылкам мастер-атрибутов.** Задача обновлять значения атрибутов объектов, полученные через механизм мастер-атрибутов: выполняется поиск объектов на шагах ЖЦ с включенным флагом **Выполнять обновление атрибутов, полученных от мастер-атрибута** , а далее обновляются те значения атрибутов, у которых в описании атрибута для типа объектов задан мастер-атрибутов и включен переключатель **Выполнять обновление данных от мастер-атрибута**.
Примечание: переключатель **Выполнять обновление данных от мастер-атрибута** можно включать только если атрибут не влияет на дату модификации содержимого объекта и для него включен флаг **Возможна модификация без взятия на изменение**.
· **Очистка кэша сервера приложений**. Задача очищает память сервера приложений, занятую различными данными, которые сервер приложений вычитал из СУБД и хранит в памяти на случай повторного использования. Данную задачу рекомендуется выполнять в том случае, если процесс сервера приложений IPS начинает занимать слишком много памяти.
· **Очистка файлового кэша сервера приложений**. Сервер приложений имеет собственный кэш извлечённых на диск файлов, которые хранятся в специальной изолированной области системного диска на физическом или виртуальном сервере, где запущен сервер приложений IPS. Этот кэш позволяет ускорить повторный доступ к файлам и двоичным данным, к которым уже обращались в данном сеансе работы сервера приложений. Файловый кэш автоматически очищается при перезагрузке сервера приложений IPS. Данная задача позволяет очищать этот кэш в случае, если сервер приложение длительное время работает без перезагрузки, а размер системного диска на сервере приложений очень ограничен.
· **Перегенерация представлений данных**. Задача производит обновление оптимизационных таблиц в базе данных (см. п. ). Поскольку перегенерация оптимизационных таблиц – операция очень длительная и должна выполняться в момент отсутствия активных пользователей системы, то удобнее её выполнять по расписанию в нерабочее время с помощью Планировщика задач, нежели с помощью соответствующей команды меню **Утилиты администратора**.
· **Перемещение двоичных данных между файловыми шкафами**. Данная задача перемещает двоичные данные и файлы объектов и итераций в соответствующие файловые шкафы (если были произведены соответствующие настройки для уровней продвижения (см. п. ) и итераций (см. п. ).
· **Пересчёт релевантности данных в общем поисковом индексе**. Данная задача пересчитывает весовые коэффициенты встречаемости слов в объектах, что позволяет производить более точную сортировку найденных объектов по их соответствию поисковому запросу. Задачу рекомендуется выполнять раз в неделю.
· **Проверка целостности данных**. Производит проверку базы данных на наличие различных ошибок и нарушений целостности данных, которые могут быть исправлены системой автоматически. Отчёт о выполнении данной задачи можно посмотреть в файле RepairData.log на сервере приложений. 
· **Рассылка уведомляющих выборок через Email**. Задача предназначена для опроса уведомляющих выборок, для которых указана рассылка уведомлений через EMail, и рассылки сообщений об изменении в составе найденных выборками объектов на соответствующие ящики электронной почты. Описание уведомляющих выборок находится в .
· **Сбор статистики использования лицензий**. Данная задача позволяет собирать сведения об использовании сетевых лицензий программных продуктов Интермех и сохранять эту информацию в текстовые файлы формата **.csv** для просмотра и анализа этой информации в электронных таблицах (например, в MS Excel). По умолчанию файлы сохраняются в каталог с логами сервера приложений IPS, на котором выполняется данная задача. Файлы имеют имена вида LicenseReport2017_Busy0.csv и LicenseReport2017_Free0.csv. В файле с суффиксом **Busy** хранится статистика по выделенным лицензиям, а в файле с суффиксом **Free** – статистика свободных лицензий. Номер после суффикса позволяет создавать несколько файлов на один отчетный период в случае, если в ключе изменяется состав лицензий. По умолчанию отчетный период – год, но можно указать системе режим создания ежемесячных файлов статистики (параметр MonthlyReport = 1 в секции appSettings конфигурационного файла сервера приложений). Параметр LicenseReportPath позволяет указать папку для размещения файлов отчетов. Сервер лицензий указывается параметром ServerName.
Для работы задачи **Сбор статистички использования лицензий** необходимо добавить в конфигурационный файл сервера приложений параметр "LicenseReportGuardantEndpoint" и задать значение вида http://{Сервер_лицензирования}:{порт}/api/getmonitorinfo, где:
− Сервер_лицензирования – это наименование компьютера, где установлен менеджер лицензий;
− порт – для ключа guardant – 8996. Например, <http://servername:8996/api/getmonitorinfo>.
· **Синхронизация с Imbase 5.0**. Данная задача производит синхронизацию данных Imbase (таблицы, папки, каталоги) с данными из системы предыдущего поколения (Imbase 5.0), согласно настроек см.п. . В случае, если на предприятии ранее не использовалась система Imbase 5.0 и данные из нее не перекачивались, запуск данной задачи не требуется.
· **Синхронизация со службой каталогов**. Данная задача выполняет синхронизацию списка пользователей IPS с доменом Active Directory. Перед настройкой данной задачи нужно один раз выполнить соответствующую команду синхронизацию списка пользователей с доменом (см. п. ), иначе задача не будет знать, с каким именно доменом необходимо выполнять дальнейшую синхронизацию.
· **Сценарий планировщика: Справочник переходов корректировка Доп текст перехода.** Задача со скриптом для корректировки значений атрибута **Доп текст перехода** объектов справочника Imbase в значение, которое начинается с заглавной буквы, замена нижнего регистра на верхний.
· **Сценарий планировщика: Справочник переходов корректировка Наименование.** Задача со скриптом для корректировки значений атрибута **Наименование** объектов справочника Imbase в значение, которое начинается с заглавной буквы, замена нижнего регистра на верхний.
· **Удаление устаревших данных**. Задача очищает базу данных IPS от устаревшей информации (см. п. ). Рекомендуется настроить ежедневное выполнение данной задачи. Отчёт о выполнении данной задачи можно посмотреть в файле ClearTrash.log на сервере приложений.
· **Фоновая индексация изменившихся атрибутов**. Данная задача производит индексацию изменившихся файловых атрибутов, используя установленные на сервере приложений IPS конвертеры файлов (см. п. ). Список установленных конвертеров (а также размер очереди на индексацию) можно узнать в консольном сервере IPS с помощью команды converters. Ошибки индексации файлов можно посмотреть в файле indexing.log на сервере приложений.
**Внимание!** Все вышеперечисленные задачи рекомендуется выполнять в нерабочее время (когда активность пользователей в системе минимальна или полностью отсутствует). Также желательно, чтобы эти задачи не пересекались по времени друг с другом.
В планировщике задач также предусмотрена возможность запуска пользовательских сценариев. Сценарии представляют собой код, написанный на одном из поддерживаемых системой языков программирования (в настоящее время только C#).
Для добавления нового сценария планировщика задач выполните в **Навигаторе** IPS команду **Создать** , по следующему пути **Информационное пространство/Объекты/Настройки системы/Сценарии/Сценарии планировщика задач**.
Основные атрибуты сценариев планировщика задач:
· **Текст сценария**
Код сценария (не требуется заполнять в момент создания объекта).
· **Заголовок объекта**
Наименование сценария, которое будет отображаться в планировщике задач.
Для просмотра и редактирования текста сценария используется редактор сценариев, который открывается по команде **Смотреть** или **Редактировать** для сценария.
После завершения создания объекта сценария, он будет доступен для выбора в окне создания задач планировщика.
