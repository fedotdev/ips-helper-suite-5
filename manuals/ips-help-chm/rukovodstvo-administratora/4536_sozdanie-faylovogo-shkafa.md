# Создание файлового шкафа
Чтобы создать новый файловый шкаф, выполните следующие действия: 
1\. Отметьте элемент **Файловые шкафы** в дереве окна администратора базы данных и примените команду **Создать** его контекстного меню.
2\. Заполните поля появившегося диалога и нажмите **Далее**.
· **Активный файловый шкаф**. Позволяет указать, является ли данный файловый шкаф активным.
· **Наименование**. Позволяет ввести уникальное наименование файлового шкафа.
· **Строка подключения к базе данных или каталог файловой системы**. Позволяет ввести строку подключения к базе данных (о формате строки подключения см. ).
· **Тип файлового шкафа**. Позволяет указать тип шкафа:
− **MS SQL Server, Oracle, PostgreSQL** – двоичные данные будут размещаться в таблице соответствующей базы данных;
− **Intermech Document Server** – для размещения двоичных данных будет использована служба IPS Data Vault Server (см. главу );
− **Файловая система** – двоичные данные будут размещены в указанном каталоге файловой системы.
· **Имя таблицы файлового шкафа**. Позволяет указать имя таблицы файлового шкафа. Для файловых шкафов типа **Intermech Document Server** и **Файловая система** таблица создается в системной базе данных IPS, но она не содержит самих тел файлов и двоичных данных.
3\. На закладке **Свойства** можно задать дополнительные атрибуты файлового шкафа.
· **Пароль подключения к Data Vault Service.** См. главу .
· **Файловый шкаф для хранения итераций.** Этот атрибут можно добавить файловому шкафу в том случае, если данный шкаф будет использоваться для хранения двоичных данных итераций. В момент создания итерации её файловые и двоичные атрибуты будут помещены в активный файловый шкаф. Однако в дальнейшем эти данные могут быть перенесены задачей перемещения двоичных данных между шкафами в файловый шкаф, предназначенный для хранения итераций. Такой файловый шкаф может быть создан на более медленных и дешевых носителях, т.к. итерации, по сути, являются страховыми копиями данных, и скорость доступа к ним не имеет большого значения. Также не имеет смысла создавать несколько файловых шкафов для хранения двоичных данных итераций – система всё равно будет использовать только один из них (первый попавшийся).
