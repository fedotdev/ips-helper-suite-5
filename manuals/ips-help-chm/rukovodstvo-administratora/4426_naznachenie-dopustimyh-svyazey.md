# Назначение допустимых связей
Назначение допустимых связей, их направлений и корректировка их свойств осуществляется на закладке **Допустимые связи**. 
Рабочая область закладки **Допустимые связи** делится на два основных раздела:
· **Связи** – раздел, отображающий направления связей с допустимыми типами объектов в виде выпадающего списка, раздел расположен с левой стороны рабочей области.
Жирным шрифтом в списке выделены типы связей, для которых уже назначены допустимые типы объектов. Такие связи автоматически размещаются в верхней часть списка **Связи**.
· **Свойства связей** – раздел, отображающий свойства связей между данными типами объектов, расположен с правой стороны рабочей области.
Чтобы назначить связь с типом объектов, существующим в базе данных, из выпадающего списка выберите направление для создаваемой связи, и примените команду **Добавить** контекстного меню рабочей области. В появившемся диалоге выберите тип объектов, с которым будет установлена связь.
Если связь с каким-либо из типов объектов назначена, в рабочей области будут отображаться свойства заданной связи применительно к данному типу объектов:
· **Автоматическая классификация дочернего объекта.** Включенное свойство позволяет системе проверять входимость в классификаторы родительского объекта, в составе которого созданы дочерние объекты соответствующего типа. Созданные дочерние объекты автоматически помещаются в папки классификатора родительского объекта, а в соответствии с формулами этих папок производится вычисление атрибутов дочернего объекта.
· **Влияет на содержимое родительского объекта**. Если это свойство связи включено, то при модификации атрибутов этой связи меняется дата модификации содержимого родительского объекта. 
· **Запретить копировать связи при создании версии**. Данный флаг управляет созданием связей при выпуске версии объекта (команда **Создать/Версию**). По умолчанию новая версия объекта получает весь набор исходящих связей от версии, на основе которой она была создана.
· **Контроль существования связи**. Определяет обязательность наличия связи между объектом данного типа и объектом типа, указанного для данной связи:
− **Запрещенная связь**. Запрещает создавать такую связь.
− **Обязательная связь**. Требует обязательного наличия такой связи. В системе невозможно будет создать объект данного типа, не включив его в состав родительского объекта данным типом связи, т.е. обязательность связи действует по отношению к дочерним объектам. Например, объекты типа **Единица измерения** должны создаваться только в составе объектов типа **Физическая величина** , но физические величины могут не содержать единиц измерения.
− **Одна из обязательных связей**. Требует наличия любой из связей, для которых включено данное значение контроля существования связи. Контроль осуществляется только среди связей одного типа.
− **Разрешенная связь**. Создание таких связей возможно, но не обязательно.
· **Копировать атрибуты в дочерний объект**. Данная опция позволяет включить режим копирования значений атрибутов в дочерние объекты соответствующего типа, создаваемые в составе данным типом связи. Атрибуты копируются в те дочерние объекты, у родителей которых включен флаг **Копировать атрибуты в дочерний объект** , а также которым можно добавлять атрибут в соответствии с его типом. У копируемых атрибутов должна быть включена опция **Копировать значение дочернему объекту**. 
· **Копировать связи при создании по прототипу**. Если данное свойство включено, то при создании нового объекта по прототипу родительского объекта (команда **Навигатора** **Создать/По прототипу**) все связи данного типа будут скопированы в новый объект. На команду создания версии объекта (команда **Создать/Версию**) данная настройка не влияет.
· **Максимальное количество связей.** Позволяет указать максимальное количество применений объектов дочернего типа в объектах родительского связью данного типа. Например, значение 1 означает, что объект дочернего типа не может входить более чем в один объект родительского типа данным типом связи.
· **Обработка состава родительского объекта.** Позволяет указать, какие объекты состава будут обрабатываться при изменении родительского объекта по правилам, указанным в опции **Отслеживать изменение родительского объекта** :
− **Дочерние объекты текущего типа.** При отмеченной установке будут обрабатываться только объекты данного типа, непосредственно входящие в состав родительского объекта (данная установка для технологических типов объектов должна быть установлена всегда).
− **Дочерние объекты в составе контекста.** При отмеченной установке будут обрабатываться объекты всех типов, которые входят в состав контекста редактирования вместе с родительским объектом (например, чтобы при проведении изменений по извещению завершить редактирование версии измененного перехода вместе с завершением редактирования версии техпроцесса).
− **Все объекты состава.** При отмеченной установке всегда будут обрабатываться все объекты состава всех типов.
В абсолютном большинстве случаев достаточно установки только опции **Дочерние объекты текущего типа**. При этом, для правильной работы по извещениям с составом техпроцессов на связи **Технологический состав** между типами объектов **Техпроцесс базовый** и **Цехозаход** должны быть установлены все три опции.
· **Отслеживать изменение родительского объекта.** Позволяет указать, какие действия необходимо произвести с объектами данного типа при осуществлении таких же изменений у родительского объекта.
− **Нет**. Не отслеживается изменение родительского объекта.
− **Взятие на редактирование**. При взятии на редактирование родительского объекта будут взяты на редактирование и дочерние объекты данного типа. Не рекомендуется установка данной опции для технологических типов объектов при работе с версиями объектов по извещениям (будут создаваться ненужные версии объектов, которые не требуется изменять по извещения), а так же из-за ухудшения быстродействия системы (например, при настройке, когда в случае взятия на редактирование техпроцесса будут взяты на редактирование и все объекты его развернутого состава). 
− **Отмена изменений**. При выполнении команды **Отменить изменения** для родительского объекта будут отменены и изменения, сделанные в дочерних объектах данного типа.
− **Завершение редактирования**. При завершении редактирования родительского объекта будет завершено редактирование и дочерних объектов данного типа.
− **Изменение шага ЖЦ**. При изменении шага жизненного цикла родительского объекта, дочерние объекты данного типа тоже будут переведены на такой же шаг ЖЦ, если схема жизненного цикла позволяет это сделать.
· **Разрешить конкретизацию пользователям**. Позволяет пользователям указывать на данной связи конкретизацию версии дочернего объекта (мягкую конкретизацию версии). Для включения опции требуется, чтобы данному типу связи предварительно был добавлен атрибут **Идентификатор версии в составе**. Мягкая конкретизация версий не имеет приоритера над контекстами редактирования и подбором версий по сериям и датам и автоматически выключается при перемещении версии родительского объекта на шаг с уровнем продвижения **Производство**.
· **Разрешить автоматическую конкретизацию.** При создании допустимой связи, включенное свойство **Разрешить автоматическую конкретизацию** позволяет системе автоматически назначать связи конкретизацию той версии дочернего объекта, которая входит в состав родительского объекта, а тип связей должен допускать наличие атрибута **Идентификатор версии в составе**.
· **Разрешить создание более одной связи с тем же объектом.** Если свойство включено, то между объектами, уже объединенными данным типом связи, можно создавать дополнительные связи этого типа.
· **Свойство наследования контекста связи**. Свойство определяет порядок наследования связей в иерархии типов объектов:
− **Собственный**. Связь назначена непосредственно данному типу объектов и автоматически распространяется на все дочерние типы объектов.
− **Унаследован**. Связь унаследована от родительского типа объектов. При этом все значения свойств таких связей становятся неактивными и изменить их можно, только изменив значения свойств связей родительского объекта. Если необходимо изменить значения свойств связи именно у дочернего объекта, необходимо свойство наследования поменять на **Собственный**.
· **Синхронизировать идентификационные атрибуты.** Данный флаг используется модулем PDM для синхронизации идентификационных атрибутов **Обозначение** , **Наименование** и **Код ОКП** у объектов, связанных данным типом связи, например, при изменении обозначения сборки меняет обозначения у соответствующих конструкторских документов.
· **Синхронный перевод связанных объектов на шаги ЖЦ.** Если этот флаг включен, то родительский и дочерний объекты, связанные данным типом связи, будут перемещаться по схеме жизненного цикла одновременно. При этом не имеет значения, для какого из объектов была вызвана команда изменения шага ЖЦ. Для синхронного перевода требуется, чтобы обе версии объектов были на одном и том же исходном шаге ЖЦ. Соответственно, схема ЖЦ должна быть у обоих объектов одна и та же.
· **Синхронное завершение изменений связанных объектов.** Если флаг включен, то при завершении редактирования родительского или дочернего объекта, связанного данным типом связи, также будет завершено редактирование и связанного объекта (если он взят на изменение этим же пользователем). На операцию взятия на изменение действие данного флага не распространяется.
· **Создавать итерации дочерних объектов.** Указывает системе на необходимость автоматического создания итераций дочерних объектов при создании итерации родительского объекта. При восстановлении состояния родительского объекта из такой итерации будут восстановлены состояния и всех дочерних объектов по данному типу связи. Например, при создании итерации сборочной единицы следует также создавать итерацию конструкторской спецификации, т.к. она является отражением состава сборки.
· **Способы обработки удаления связанных объектов**. Позволяет настроить обработку удаления объектов, связанных данным типом связи (запрещать удаление при наличии такой связи, удалять дочерний объект при удалении родительского и пр.).
· **Тип связи по умолчанию.** Свойство определяет, является ли данный тип связи типом связи по умолчанию между указанными типами объектов. Используется различными командами системы (**Создать в составе** , **Добавить в состав** , **Копировать/Вставить** и пр.) для определения типа связи в том случае, если между указанными объектами разрешено создавать связи нескольких типов.
Чтобы удалить связь, выделите тип объекта, с которым создана связь и примените команду его контекстного меню **Удалить**.
