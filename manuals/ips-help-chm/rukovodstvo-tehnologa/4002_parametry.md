# Параметры
В данном разделе задаются общие параметры работы с технологическими объектами.
В области **Маршрут обработки** доступны следующие параметры для настройки:
· **Автоматически завершать МО**. При включенном режиме «**да** » при создании объекта, входящего в МО будет автоматически создан маршрут обработки и завершено его редактирование. При установленном режиме «**нет** » объект МО будет создан, но останется на редактировании.
· **Контроль уникальности РМ в МО.** Устанавливает запрет – «**да** » / возможность – «**нет** » создания более одного РМ в МО.
· **Контроль уникальности заготовок в МО.** Устанавливает запрет – «**да** » / возможность – «**нет** » создания более одной заготовки в МО.
· **Контроль уникальности входимости в МО.** Устанавливает запрет – «**да** » / возможность – «**нет** » создания более одной входимости в МО.
· **Запрет добавления МО в несколько изделий.** Устанавливает запрет – «**да** » / возможность – «**нет** » добавления одного и того же МО в несколько изделий.
В области **Настройки группового /типового ТП** доступны следующие настройки:
· **Настройки дополнительных связей для привязки**. Позволяет указать дополнительные связи, по которым будет осуществляться привязка объектов ГТП/ТТП к элементам ЕТП. По умолчанию привязка элементов состава ГТП/ТТП в единичных техпроцессах выполняется только по связи **Технологический состав**. 

Например, в составе ГТП/ТТП имеются операции, в которые, в свою очередь, по связи **Технологический сквозной ТП** добавлен сквозной ТП или операции из сквозного ТП. Для того, чтобы иметь возможность в групповом ТП привязывать объекты сквозного ТП к элементам в ЕТП, необходимо в **Настройки дополнительной связи для привязки** добавить связь **Технологический сквозной ТП**. 
Окно **Настройки дополнительных связей** привязки разбито на две части. В левой части окна при помощи команд **Добавить** / **Удалить** производится добавление/удаление типов дополнительных связей. В правой части – указывается **Режим привязки объектов** :
− **Существующий объект**. При привязке объектов по указанной связи, копия объектов в ЕТП создаваться не будет, а будет создана новая связь с элементом ГТП. Например, в составе ГТП имеется операция Термическая обработка, в которую добавлены операции из сквозного ТП (Закалка, Отпуск). При осуществлении привязки сквозных операций к элементам в ЕТП в операцию Термическая обработка по связи Технологический сквозной ТП будут включены уже существующие объекты операции (Закалка, Отпуск).
− **Определяется настройкой типов объектов**. При привязке объектов по указанной связи, режим привязки будет определяться текущими правилами создания копии объекта данного типа.
· **Настройка атрибутов объектов ГТП/ТТП, передаваемых в объекты ЕТП.** Позволяет настроить список атрибутов объектов/связей, значения которых в момент привязки объектов ГТП/ТТП к элементам ЕТП будут копироваться, даже в том случае, если у данного атрибута объекта/связи в конфигураторе будет установлено значения свойства – **Запрет копирования значения у прототипа** – **Да**. 
Для добавления атрибутов объектов необходимо выделить элемент **Тип объекта** и воспользоваться командой контекстного меню **Добавить тип объекта**. Далее для добавленного объекта воспользоваться командой контекстного меню **Добавить тип атрибута**. Для добавления атрибутов связи необходимо воспользоваться командами **Добавить тип связи** и **Добавить тип атрибута** соответственно. Далее для атрибута следует добавить **Тип родительского объекта** и **Тип дочернего объекта**.
В области **Общие** доступны следующие настройки:
· **Уровень раскрытия состава**. Устанавливает, на сколько уровней будет раскрыт состав технологического объекта при выполнении команды контекстного меню **Навигатора Раскрыть состав.**
· **Фильтр Imbase.** Устанавливает, какой тип фильтра на каталоги и справочники Imbase будет устанавливаться по умолчанию в системе.
· **Режим команды “Вставить”.** Позволяет задать режим вставки объекта при копировании / перемещении объекта путем перетаскивания. 
− **Вставить перед**. Объект будет вставлен перед объектом, на который указывает наводящая стрелка.
− **Вставить после**. Объект будет вставлен после объекта, на который указывает наводящая стрелка.
− **Отображение меню**. При копировании/перетаскивании объекта пользователю будет выдаваться меню выбора вставки объекта.
· **Принудительное включение в контекст.** При выбранной опции «**да** », технологические объекты, если контекст редактирования выбран, всегда будут попадать в него независимо от выбранного режима панели инструментов **Обычный режим** или **Режим автоматического обновления контекста**. Если выбрана опция «**нет** », при указанном контексте редактирования, настройка включения в контекст будут определяться установленным режимом на панели инструментов **Обычный режим** или **Режим автоматического обновления контекста**.
· **Отображение форм, не привязанных к Imbase.** Если выбрана опция «**нет** », при наличии у объекта форм, привязанных к Imbase, которые удовлетворяют заданному условию вывода, формы, привязанные к типу объекта отображаться для данного объекта не будут. 
Если выбрана опция «**да** », для объекта будут отображаться как форма, привязанная к справочнику Imbase, так и формы, привязанные к типу объекта.
Например, у объекта операция имеются две формы:**Операция ГИБКА,** привязанная к справочнику Imbase, и форма **Карточка операции +,** привязанная к типу объекта. 
При выключенной опции **Отображение форм, не привязанных к Imbase** , для операции Гибка будет отображаться только карточка формы **Операция ГИБКА.** Для операции Контроль только **Карточка операции +**(т.к. карточка **Операция ГИБКА**) не удовлетворяет условию.
При включенной опции **Отображение форм, не привязанных к Imbase** , для операции Гибка будет отображаться обе карточки.
· **Показывать карточку для объектов из Imbase при изменении.** При изменении объекта, добавленного из Imbase (командой контекстного меню **Изменить**), после закрытия окна выбора из Imbase, будет выдаваться окно **Карточка объекта**.
· **Отображать диалог выбора при ИИ.** Если выбрана опция «**нет** » для технологических объектов состава ТП при вызове команды **Создать версию** диалог выбора ИИ для создания версии объекта (см. рис. ниже) отображаться не будет при соблюдении условий: 
− В текущем окне для объекта, на котором вызвана команда, корневой элемент дерева – это ТП.
− Версия этого ТП выпущена в рамках извещения (ТП входит в извещение).
− Текущий контекст редактирования данного окна равен этому же извещению.
Если все условия выполнены будет автоматически создана версия объекта в контексте данного ИИ.
Если хотя бы одно из вышеперечисленных условий не будет выполнено, либо для данного параметра выбрана опция «**да** », диалог выбора ИИ будет показан в обычном режиме.
В области **Портал** доступны настройки:
· **Привязка технологических данных для изделия**. Если выбрана опция «**да** », при импорте версии изделий через портал для указанных узлов технологические данные в системе от предыдущей версии объекта будут привязаны к импортируемой версии изделия.
