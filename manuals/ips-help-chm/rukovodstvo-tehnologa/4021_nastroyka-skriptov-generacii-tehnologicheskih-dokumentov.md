# Настройка скриптов генерации технологических документов
В данном разделе рассмотрены примеры скриптов формирования технологических документов, а также описание различных элементов, которые могут быть использованы в данных скриптах.
Описание принципов работы со скриптами генерации документов приведено в 
Рассмотрим пример скрипта генерации маршрутной карты на бланке по ГОСТ 3.1118-82 (в **Навигаторе** IPS данный бланк находится в разделе **Объекты/Настройки системы/Шаблоны документов (бланки)**).
Для удобства, а также для группировки отображаемых в документе данных по типам, в скрипте создано несколько операторов **Блок** , которые будут выполняться по ходу скрипта сверху вниз.
Первый блок **Параметры изделия** предназначен для заполнения информации об изделии, на которое создан техпроцесс. Т.к. документ **Маршрутная карта** предназначен на техпроцесс, то необходимо от техпроцесса пройти по составу вверх по связи **Технологический состав** и найти требуемое изделие. Для этого внутрь блока вставляем оператор **Содержащие объекты** с модификатором **Для первого** (т.к. техпроцесс не входит непосредственно в состав изделия, а через маршрут обработки, то оператор **Родительские объекты** здесь использовать нельзя) – будет найдено первое изделие, в состав которого входит техпроцесс.
В параметрах оператора указываем тип связи, по которому будем искать изделие от техпроцесса, а в параметрах модификатора установим условие на тип объекта, который необходимо найти (объекты всех типов, являющихся дочерними для типа объекта **Изделия**).
Следующий этап – запись данных об изделии в текстовые поля шапки маршрутной карты. Для этого используется оператор **Запись данных в поле**. В данном примере заполняем параметры значениями атрибутов изделия **Обозначение изделия** , **Наименование изделия** и **Масса** , при необходимости в документе их может быть гораздо больше.
После заполнения данных об изделии заполняем поля с информацией о техпроцессе. Для этого создаем отдельный блок **Параметры техпроцесса** , внутрь которого вставляем операторы **Запись данных в поле**. Т.к. мы находимся на уровне техпроцесса, то искать нам вверх или вниз по составу ничего не надо. А вот для записи в соответствующие поля бланка таких атрибутов как **Принадлежность проекту** (в других скриптах так же могут использоваться атрибуты фамилия проверяющего или разработчика) приходится использовать результат формулы – строковое представление атрибута (т.к. данные атрибуты имеют тип **Ссылка на версию объекта,** и**Ссылка на версию объекта без конкретизации** и их значение в документе отображалось бы в виде цифры – идентификатора объекта в базе).
В следующем блоке **Параметры заготовки** присутствуют операторы **Запись данных в поле** , которые отвечают за заполнение текстовых полей шапки бланка данными о заготовке на изделие. 
Т.к. заготовка и техпроцесс находятся на одном уровне вложения в составе маршрута обработки, то от техпроцесса необходимо пройти по составу на один уровень вверх, найти маршрут обработки, и от него вниз на один уровень к заготовке. Но в скрипте генерации маршрутной карты такой поиск отсутствует, в блоке **Параметры заготовки** присутствуют только элементы **Запись данных в поле**. Поиск объекта от другого объекта в данном случае реализован при помощи другого типа объекта экспертной системы – **Правило поиска объектов** , в котором указывается тип объекта, от которого начинается поиск и различные операторы с модификаторами для поиска требуемого типа объектов по составу. Если в операторе **Запись данных в поле** указан необходимый тип объекта, то экспертная система сама найдет этот объект через правило поиска и заполнит его в шаблоне документа при помощи скрипта генерации.
В качестве примера рассмотрим скрипт поиска заготовки от техпроцесса (в **Навигаторе** IPS данный скрипт находится в разделе **Объекты / Объекты экспертной системы / Скрипты ЭС / Правила поиска объектов**). 
В его состав входит оператор поиска родительского маршрута обработки, в состав которого в свою очередь входит оператор поиска дочерней заготовки. Последней строкой является оператор возврата найденного объекта.
Правило поиска объекта можно было использовать в скрипте генерации маршрутной карты ранее, на этапе заполнения шаблона документа данными об изделии, что позволило бы сделать данный скрипт менее громоздким. К тому же одно правило поиска может использоваться для различных скриптов и формул экспертной системы IPS.
Вернемся к скрипту генерации маршрутной карты. Следующий блок **Рабочая область** описывает последовательность заполнения полей в таблице шаблона документа, служащей для вывода переменной информации.
Первым оператором, входящим в состав данного блока, является **Выбор элемента документа** , в его параметрах указывается идентификатор элемента шаблона, который будет являться рабочей областью, и который необходимо заполнить требуемой информацией.
Следующий элемент блока **Рабочая область** – это оператор **Дочерние объекты** с модификатором **Для всех** , при помощи которого находим комментарии к техпроцессу. 
В параметрах модификатора указываем тип объекта, который необходимо найти (Комментарий). Чтобы в параметрах оператора не указывать тип связи, по которому необходимо производить поиск, оставляем не отмеченной установку **Не по глобальной таблице**.
Внутрь оператора поиска комментария вложен оператор **Создать элемент документа** , в свойствах которого указывается строка рабочей области шаблона документа, которую необходимо будет создать при генерации. В данном случае это строка, в которую будут выводиться комментарий к ТП.
Внутрь оператора **Комментарий** включаем операторы **Запись данных в поле** для вывода значений атрибута **Текст комментария** для ТП. 
При помощи следующего элемента блока **Рабочей области** оператора **Дочерние объекты** с модификатором **Для всех** , находим все цехозаходы техпроцесса, а при помощи аналогичного вложенного в него оператора **Для всех операций** , находим все операции для текущего цехозахода.
Внутрь оператора **Для всех операций** включаем операторы **Присваивания,** для создания переменных с последующим использованием их в расчетах, и оператор **Создать элемент документа** – **Создание строки А** , внутрь которого будут выводиться данные по операции.
Внутрь оператора **Создание строки А** включаем следующие операторы:
· **Запись данных в поле** – для вывода значений атрибутов **Номер операции** , **Операция** , **Код операции, участок**.
· **Родительские объекты** с модификатором**Для первого** – для поиска цехозахода и вывода значения атрибута **Цех** при помощи вложенного оператора **Запись данных в поле**.
· **Дочерние объекты** с модификатором**Для всех** – для поиска сквозных ТП, обозначение которых будет присвоено вложенному оператору присваивания в переменную **Str4**.
· **Блок Если надо вывести номер КЭ в строку А** – позволяет при помощи вложенного оператора **Дочерние объекты** с модификатором **Для первого** определить имеется ли у данной операции эскиз и присвоить его номер переменной **Str2** в операторе**Присваивания**.
· **Блок заполнение ИОТ, если есть КЭ** и**Блок заполнения ИОТ, если есть КЭ, но нет ИОТ** – предназначен для указания условия для вывода вложенного оператора **Запись данных в поле ИОТ+КЭ**.
· **Блок Заполнение ИОТ, если нет КЭ** – для настройки параметров, в случае если у операции нет эскиза. Внутри блока при помощи операторов **Запись данных в поле** с модификатором **Если существует** осуществляется настройка заполнения значений атрибута **ИОТ**. 
Следующий вложенный элемент оператора **Для всех операций** служит для поиска данных по оборудованию. Для этого после оператора создания строки операции на одном с ним уровне вложения включаем в скрипт оператор **Блок Строка Б** , в котором будем искать все оборудование, находящееся непосредственно в составе операции и параметры нормирования.
Внутри блока **Строка Б** включаем оператор присваивания для создания и обнуления значения переменной **ID** оборудования. 
Далее вставляем оператор **Создания строки Б** для вывода данных по оборудованию, в которую, в свою очередь вставляем операторы:
· Оператор поиска**Для оборудования на операции** , в который, вставляем оператор **Запись данных в поле** для вывода модели оборудования (состоит из атрибутов **Код АСУП** , **Размеры и параметры** , Наименование) и оператор **Присваивание** для присваивания значения **Идентификатор версии объекта,** найденного оборудования, переменной **ID** оборудования. Данную переменную мы будем использовать в дальнейшем для поиска дополнительного оборудования.
· **Блок Параметры нормирования от операции** , который включает операторы вывода значений атрибутов **КОИД** , **ЕН** , **УТ** , **разряд** , **ОП** , **СМ** и оператор **Дочерние объекты Персонал** с модификатором **Для всех** , включающий оператор **Запись данных в поле** для вывода атрибутов **код. проф,** **КР**.
· Оператор поиска дочерних объектов операции**\- Нормы времени для операции,** включающий операторы **Запись данных** в поле, для вывода атрибутов **Тпз** , **Тшт** , **Кшт**.
Следующим в блоке **Строка Б** добавлен оператор поиска **Для остального оборудования** , предназначенный для поиска наличия дополнительного оборудования (например, если в операции используется несколько видов оборудования). Для этого используем условие сравнения **Идентификатор версии объекта** найденного оборудования с переменной **ID** , значение которой было присвоено этапом ранее. Если условие выполняется, у операции присутствует дополнительное оборудование, которое будет выведено в дополнительной строке Б. Внутрь **строка Б** вложены два оператора **Запись данных в поле** с модификатором **Если существует**. Отличие между ними заключается в записи результатов формулы в зависимости от условия (если данное оборудование указано, как вариант, в **Запись результатов формулы** перед атрибутами добавляется **«Или»**).
Рассмотрим два следующих вложенных элементов оператора **Для всех операций** – оператор **Создание элемента Процент контроля** с модификатором **Для всех** и **Блок Примечание для операции**.
Данные элементы предназначены для вывода значения атрибутов **Процент контроля** и **Примечание для операции**. Для наглядности данные элементы имеют разные методики вывода. В элементе **Процент контроля** условие задается при помощи модификатора **Если существует** . В элементе **Примечание для операции** условие задается на дополнительном операторе **Блок** , в который, в свою очередь, входит оператор **Создание строки примечания**.
Следующим этапом будет производиться поиск материалов, входящих в состав операции при помощи оператора поиска дочерних объектов с модификатором **Для всех**. В отличие от оборудования, все материалы на операцию (даже если их несколько), в нашем случае, выводятся в бланк однотипно. Поэтому внутрь оператора **Материал** просто вставляем оператор **Создание строки для материала** , в который, в свою очередь, вставляем операторы Запись данных в поле для атрибутов **Наименование** , **Обозначение** , **код** , **ЕВ** , **Н. расхода**.
Следующий этап – поиск переходов на операции. Так как переходы находятся в составе операции на одном уровне с оборудованием и материалами, но в документе должны выводиться после них, то такой же порядок соблюдаем и в скрипте генерации: оператор **Дочерние объекты** с модификатором **Для всех** для поиска переходов вставляем внутрь строки поиска операции после строки поиска материалов. В нашем примере выполнение данного оператора заблокировано символом «**#** » в наименовании оператора, но, для лучшего понимания работы скриптов, рассмотрим данный этап тоже подробно.
В состав данного оператора включаем оператор **Создания строки О** для вывода данных по переходу. Оператор **Запись данных в поле - Переход** , включенный в состав оператора создания строки перехода служит для вывода текста перехода, состоящего из значений результатов формулы вывода атрибутов **Номер объекта** , **Текст перехода дополнительный, Контролируемый параметр**.
Точно так же, как и для операции мы проводили вывод **Процент контроля** , для переходов мы будем выводить методику контроля. Для этого внутрь оператора **Для переходов на операцию** вставляем оператор создания строки с модификатором **Если существует** , в которую, в свою очередь, вставляем оператор **Запись данных в поле** для вывода значения атрибута **Методика контроля**.
Поскольку в скрипте для операции мы уже проводили поиск процента контроля, для поиска и вывода значений атрибута **Процент контроля** на переходе будем использовать оператор **Вызов процедуры** , для обращения к имеющемуся оператору в скрипте.
Следующий этап – поиск режимов и норм времени на переходе. Нормы основного и вспомогательного времени на переход необходимо выводить в документе на той же строке, что и режимы. Но в некоторых случаях, режимы на переход могут отсутствовать. В этом случае в документ будет выводиться только строка со значениями норм времени. Поэтому нам необходимо создать две ветки в скрипте, первая для поиска и вывода режимов вместе с нормами времени, вторая – отдельно нормы времени. Для того, чтобы во второй ветке нормы времени не выводились во второй раз, будем использовать переменную **Нормы времени на переход по режимам**. Первоначально присвоим ей значение «**нет** ». Далее в первой ветке, при помощи оператора поиска дочерних объектов, будем производить поиск режимов на переходе. Указываем сортировку по атрибуту **Наименование** (т.к. режимов на переходе может быть несколько, и важно определить их порядок вывода). Внутрь оператора поиска вставляем оператор **Создание строки Р** , в котором будем выводить значения атрибутов режима на переходе и так же вставляем **Блок Заполнение норм времени**. В данном блоке будем производить поиск норм времени и выводить их в уже созданную строку Р. Так как нормы времени находятся непосредственно на переходе, нам необходимо при помощи оператора поиска родительского объекта с модификатором **Для первого** подняться на уровень вверх к переходу и далее при помощи вложенного оператора поиска дочерних объектов найти нормы времени на этот переход и вывести их в строку Р. 
Последним этапом будет присвоение значение «**Да** » переменной **Нормы времени на переход по режимам**. Это в дальнейшем будет свидетельствовать о том, что нормы времени уже заполнены.
Во второй ветке будем производить поиск только норм времени на переходе. Первоначально проверим не была ли уже заполнена строка с режимами и нормами времени. Для этого вставим условие проверки отсутствия у переменной **Нормы времени на переход по режимам** значения «**Да** ». Если условие выполняется, нормы времени еще не заполнены. Внутрь оператора **Для норм времени на переходе** вставляем оператор **Создание строки Р** , в котором будем выводить значения атрибутов **То** и **Тв**. 
Следующим этапом выведем на переходе оснастку и материалы. Для этого воспользуемся оператором **Вызов процедуры**. Для вывода материалов на переходе будем производить **Вызов оператора Материалы** (ранее используемого на операции). Для вывода оснастки на переходе будем производить **Вызов оператора оснастка с группировкой по типам со спецоснасткой**(будет добавлен следующим этапом в операции, после переходов).
Последним этапом в ветке **Для переходов на операции** производим поиск и вывод комментария к переходу.
Следующий этап – поиск оснастки на операцию. Поскольку оснастку необходимо выводить соблюдая определенный порядок вывода с группировкой по типу оснастки, используем оператор поиска дочерних объектов с модификатором **Цикл с группировкой** . 
Данный цикл позволит нам найти оснастку на операции, сгруппировав и отсортировав ее по типу оснастки. Для каждого найденного объекта оснастки будет выполнен **Блок выбора** , который позволит прервать выполнения вложенных операторов после первого успешно выполненного оператора – **Блок оснастка** или **Блок задание на сто**. 
В каждом из блоков **оснастка** или **задание на сто** производим вывод данных по оснастке в операторе **Запись данных в поле,** значения которых берутся из поля **Запись результатов формулы** в зависимости от типа оснастки.
Последним элементом скрипта, который входит в оператор **Для всех операций** , производим поиск и вывод комментария к операции.
