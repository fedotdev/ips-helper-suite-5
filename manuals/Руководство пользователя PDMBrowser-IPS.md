# 1 Введение

**PDM Browser** — это универсальный модуль интеграции систем трёхмерного моделирования с базой данных **IPS**. Модуль **PDM Browser** встраивается в CAD-систему и предоставляет конструктору доступ к командам **IPS** непосредственно из CAD-системы. **PDM Browser** может быть интегрирован со следующими CAD-системами:

- Autodesk Inventor.
- Creo Parametric.
- SOLIDWORKS.
- Solid Edge.
- Unigraphics (NX).
- КОМПАС-3D.
- КОМПАС-График.

Функционал данного модуля обеспечивает коллективную работу конструкторов над моделированием деталей и сборок, позволяет управлять их составом с учётом вариантов исполнений, допустимых заменителей, опций конфигуратора и т.п. Модуль обеспечивает автоматическое считывание состава изделия из моделей сборочных единиц, генерацию по моделям конструкторских спецификаций, а также ассоциативную связь между свойствами моделей и атрибутами документов и изделий в системе **IPS**.

В рамках интеграции реализованы следующие функции:

- автоматическое считывание состава изделия из сборок **Cadmech** при занесении их в архив;
- запоминание в архиве ссылочных связей между различными файлами **Cadmech** (между сборкой и входящими в нее подсборками и деталями; между файлами моделей и оформленными чертежами);
- поддержка исполнений моделей **Cadmech** и их автоматическая синхронизация с вариантами исполнения изделий в **IPS**;
- двухсторонняя синхронизированная связь между параметрами (свойствами) моделей **Cadmech** и архивом **IPS** через карточки документов и изделий;
- вставка компонентов из архива и из базы данных объектов **IPS** в сборку;
- возможность связать модель с объектом **IMBASE** или материалом;
- поддержка конфигурируемого состава - возможность назначения опций компонентам сборки, исходя из условий применения и функционального назначения;
- использование PDM флагов, для управления отображением компонентов в составе сборки и в архиве **IPS**;
- поддержка допустимых замен – возможность назначения заменителя или группы заменителей для компонентов сборки с последующей передачей данной информации в PDM систему **IPS**;
- возможность запуска процесса согласования документации из окна **Дерева состава**;
- синхронизация компонентов созданных в **CAD-системе** с элементами справочно-информационной базы данных **IMBASE**.



# 2 Основные принципы работы модуля PDM Browser

Модуль **PDM Browser** имеет два основных режима работы – режим **Дерево состава** ![](35e4f762fc1cfea5610d92e2d225d5b4_img.jpg) и режим **Спецификация** ![](b6a97e4835c8c5eb846fcac2cc15117e_img.jpg). Режим **Спецификация** используется при оформлении конструкторской спецификации на сборку (см.4). Для работы с составом сборки основным является режим **Дерево состава**.

## 2.1 Работа PDM Browser в различных CAD-системах

После установки модуля **PDM Browser**, вызов окна **Дерева состава** в CAD-системе осуществляется по команде **PDM Browser (Дерево состава)**.

Кроме этого, на главной панели инструментов создается отдельная закладка, содержащая панель быстрого доступа к основным командам **PDM Browser**. Благодаря данной панели у конструктора есть возможность удобного и эффективного способа работы со сборкой и ее компонентами, а также взаимодействия с системой **IPS** без вызова окна **PDM Browser**.

Рассмотрим расположение команд **PDM Browser** и представление панели быстрого доступа в различных CAD-системах.

#### 2.1.2.1 Файл настроек ConvertProe.ini

При регистрации моделей CAD-системы в архиве **IPS** параметры документа и объектов, которые по нему выпускаются, записываются в файл модели. Отображение имен параметров необходимо по следующим причинам:

- Имена параметров в моделях CAD-системы могут состоять только из букв, цифр и знака подчеркивания. Поэтому такие параметры **IPS** как "Раздел СП", "Ключ IMBASE", "Н.контр", "Т.контр" и др. не могут быть записаны в модель, т.к. имена параметров содержат недопустимые символы - точки и пробелы.
- Максимальная длина имени параметра в **Creo Parametric** - 31 символ. Поэтому параметры **IPS** или **IMBASE** с большей длиной имени также не могут быть перенесены в модель.
- На вашем предприятии может использоваться своя система именования параметров моделей.
- **IPS** допускает создание параметра документа и параметра объекта с одинаковым именем, а CAD-система - нет. Например, в карточке **IPS** на закладках "Документ" и "Объект" есть параметр "Примечание". Значение этого параметра для документа и объекта может быть различным, но записать в модель CAD-системы оба значения одновременно нельзя.

Устранить все эти проблемы можно с помощью правил отображения имен параметров **IPS** имена параметров моделей CAD-системы. Правила задаются с помощью файла **ConvertProE.ini**.

Общая схема отображения имени параметра **IPS** в имя, пригодное для использования в CAD-системе, выглядит так:

<имя\_в\_**IPS**> <префикс><имя\_в\_CAD-системе>.

Т.е. к имени параметра добавляется префикс, который позволяет определить, к чему относится параметр - к документу или объекту. Также имя параметра модифицируется таким образом, чтобы устранить проблемы, описанные выше.

Например:

| Имя параметра в IPS | Имя параметра в CAD-системе |
|---------------------|-----------------------------|
| Раздел СП           | ART_Раздел_СП               |
| Ключ IMBASE         | ART_Ключ_IMBASE             |
| Н.контр.            | DOC_N_KONTR                 |
| Т.контр.            | DOC_t_контр                 |

Файл **ConvertProE.ini** является обычным ini-файлом и состоит из 4-х секций:

- **секция [Common]** позволяет указать префиксы, которые будут добавляться к именам параметров объектов и документов. По умолчанию заданы следующие префиксы:

[Common]

DocPrefix = DOC\_; префикс для параметров документов

ArtPrefix = ART\_; префикс для параметров объектов

- **секция [Names]** позволяет указать, каким образом изменить имя параметра, если оно содержит недопустимые символы, такие как пробелы, точки и др. Например:

[Names]

Раздел СП = Раздел\_СП

Н.контр. = N\_KONTR

Т.контр. = t\_контр

- **секция [Chars]** позволяет указать замены отдельных символов в именах параметров. Правила из этой секции используются только в том случае, если не удалось преобразовать имя параметра с помощью секции [Names]. Наиболее подходящее применение этой секции - замена пробелов в именах на какой-либо другой символ (знак подчеркивания):

[Chars]

" " = " \_ "

- **секция [Convert]** необходима в том случае, если на вашем предприятии используется своя система именования параметров в моделях. Правила из этой секции применяются к преобразованному с помощью 3-х предыдущих секций имени параметра. Например, если у вас используется следующая система имен:

D\_NUMBER - обозначение модели

M\_NAME - наименование модели

MASS - масса модели

R\_SP - раздел спецификации

то правила секции будут выглядеть следующим образом:

[Convert]

ART\_Обозначение = D\_NUMBER

ART\_Наименование = M\_NAME

ART\_Масса = MASS

ART\_Раздел\_СП = R\_SP

***Примечание:*** *при написании имен параметров соблюдайте регистр букв, в частности латинские буквы обязательно должны быть набраны в верхнем регистре (т.е. так, как в CAD-системе).*

В случае если у вас различаются параметры для разных типов документов, или параметр составной, т.е. состоит из нескольких параметров, то вам необходимо добавить после секции **[Convert]** секции с перечислением типов документов.

Например:

Пусть "Наименование" у "Сборочной единицы" будет состоять из двух параметров "DESCRIPTION1" и "DESCRIPTION3", а «Обозначение» будет соответствовать параметру "TITL". У "Детали" параметр "Наименование" будет соответствовать параметру "DESCRIPTION2", а "Обозначение" - "TITLE"

Таким образом Вам необходимо добавить следующие секции со следующими правилами конвертации:

[0100 Сборочные Единицы]

Наименование = DESCRIPTION1, DESCRIPTION3

Обозначение = TITL

[0200 Детали]

Наименование = DESCRIPTION2

Обозначение = TITLE

Помимо этого, Вам необходимо добавить секцию [COMMON] в файл **...\CAD\CADInterface\ProE\ProEPdm.ini**

В данной секции для переменной "SORT\_TYPE\_PARAM\_NAME" указать параметр, по которому определяется тип документа. Значение этого параметра используется для именования секций в **ConvertProE.ini**.

Например:

Тип документа прописан в параметре "SORT\_TYPE"

Вам необходимо добавить следующую строку в файл **ProEPdm.ini**

[COMMON]

SORT\_TYPE\_PARAM\_NAME = SORT\_TYPE

***Примечание:*** *файл **ConvertProE.ini** должен быть одинаковым у всех пользователей, которые используют **IPS** совместно с CAD-системой.*

При регистрации моделей **КОМПАС-3D** в архиве **IPS** параметры документа и объектов, которые по нему выпускаются, записываются в файл модели. Правила отображения имен параметров задаются с помощью файла **ConvertKs.ini**.

##### **Секция [Common]**

- **WRITE\_MATERIALID=1/0**

Позволяет указать, прописывать ли в свойства документа ID материала, взятого из марочника материалов **IMH** или **IMBASE**. Если значение равно «1», то ID материала будет прописано в свойства документа **КОМПАС-3D**. Если значение равно «0», то не будет.

- **IS\_LOG=1/0**

Параметр отвечает за включение и выключение записи лог-файла **PDM Browser**. Если значение равно «1», то запись файла включена. Если значение равно «0», то выключена.

- **MASS\_PRECISION=0, 1, 2 и т.д.**

Параметр отвечает за значение массы, которая будет передана в **IPS**. Цифра после знака «равно» означает количество знаков после запятой.

- **PROPERTIES\_SOURCE\_FILE=Диск установки\IM\CAD\Kompas\IMProperties.lpt**

Параметр указывает путь к папке с файлом **IMProperties.lpt**, в котором хранятся атрибуты. Желательно указывать серверный путь, т.к. этот файл будет использоваться всеми пользователями при добавлении нового атрибута через **PDM Browser**.

###### - **IS\_PROCESS\_STD\_PART=0/1**

Параметр указывает, будет ли вызываться **IPS** при добавлении стандартного изделия из системы **ПОЛИНОМ:MDM**. Если значение равно «1», то **IPS** будет вызываться. Если значение равно «0», то не будет.

##### **Секция [Convert]**

Конвертирует имена параметров для занесения в **IPS**.

Например:

Н.контр.=Н. контр.

где Н.контр. – параметр в **IPS**.

Н. контр. – параметр в **КОМПАС-3D**.

##### **Секция [StampParameters]**

В эту секцию заносятся параметры, которые прописываются в соответствующую ячейку основной надписи чертежа при условии, что данный параметр присутствует в свойствах документа. Для этих параметров должен быть определен идентификатор ячейки в секции **[StampData]** файла **ConvertKs.ini**.

##### **Секция [StampData]**

Позволяет указать идентификаторы ячеек, в которые будут выводиться параметры из **IPS**.

Например:

Разработал\_ЭЦП=120

***Примечание:** файл **ConvertKs.ini** должен быть одинаковым у всех пользователей, которые используют **IPS** совместно с **КОМПАС-3D**.*

### 3.2.6 Команда «Взять на редактирование»

Команда **Взять на редактирование** ![](51fa12e9938db9b91c0132320af2b84a_img.jpg) добавляет документ на рабочий стол **IPS**. Пользователь, взявший его на редактирование, может вносить изменения в данный документ. При этом он становится недоступным для редактирования для других пользователей.

Документ, взятый на редактирование в **Дереве состава**, помечается зеленым цветом. Документ, который сдан в архив, – черным цветом. Не зарегистрированный в архиве или взятый на редактирование другим пользователем документ помечается серым цветом.

Для того чтобы редактировать документ с версиями, нужно из архива **IPS** взять на редактирование извещение, выпущенное на него.

### 3.2.7 Команда «Взять ветку на редактирование»

С помощью команды **Взять ветку на редактирование** ![](c2ecea60f1990c304f36f34e0bfaef4d_img.jpg) сборка со всеми входящими в нее деталями и подсборками помещается на рабочий стол **IPS**, после чего пользователь может вносить изменения в модели и чертежи.

Документы, взятые таким образом на редактирование, становятся доступными только для просмотра остальным пользователям системы **IPS** до тех пор, пока пользователь не выполнит команду **Завершить изменения** (п.[3.2.8](#)) или **Отменить изменения** (п.[3.2.13](#)).

### 3.2.8 Команда «Завершить редактирование»

Команда **Завершить редактирование** ![](c8253b2ca77e4963bebd7529f83f9028_img.jpg) возвращает и записывает сделанные в текущем документе изменения в архив **IPS**. Рабочая копия документа в данном случае удаляется с рабочего стола. Для последующего редактирования компонента необходимо взять его на редактирование в **IPS** или открыть в CAD-системе, и в окне **Дерево состава** вызвать команду **Взять на редактирование** (п.[3.2.6](#))

Команда доступна для группы отмеченных документов.

Для передачи документа с версией в архив, необходимо в архиве **IPS** вернуть в архив извещение, выпущенное на него.

### 3.2.9 Команда «Завершить редактирование в ветке»

Команда **Завершить редактирование в ветке** ![](15c9cca23297adb811cdb4a21b95fab3_img.jpg) позволяет вернуть в архив сборку со всеми входящими в нее деталями и подсборками. Рабочая копия документов при этом удаляется с рабочего стола. Для повторного взятия сборки на редактирование необходимо открыть ее в CAD-системе и в окне **Дерево состава** вызвать команду **Взять ветку на редактирование** (п. [3.2.6](#)) либо в **IPS** выполнить команду **Взять на редактирование**.

При выполнении данной команды для сборки, в составе которой есть незарегистрированный компонент, он автоматически регистрируется в архиве **IPS**.

### 3.2.10 Команда «Сохранить изменения»

Команда **Сохранить изменения** ![](001db52133ab4d4e6f33ee52d8a36710_img.jpg) записывает все изменения документа в архив. При этом документ остается на рабочем столе пользователя для внесения последующих изменений. После выполнения этой команды все остальные пользователи системы **IPS** смогут увидеть изменения, сделанные в файле документа.

***Примечание:** в **Дереве состава** значок статуса у документа после сохранения меняется или пропадает.*

### 3.2.11 Команда «Расширенное сохранение»

Команда **Расширенное сохранение** ![](f985c1b56f6a89991588bb83755d7e08_img.jpg) выполняется для формирования состава изделий или обновления информации по изделиям. При выполнении данной команды для сборок она будет автоматически применена для всех подсборок и деталей, входящих в сборку.

При выполнении расширенного сохранения для документа, не зарегистрированного в базе данных **IPS**, он будет автоматически зарегистрирован в **IPS**.

### 3.2.12 Команда «Сохранить изменения в ветке»

### 3.2.13 Команда «Отменить изменения»

С помощью команды **Отменить изменения** ![](3271ad3f963d2e9d60af4e824e455014_img.jpg) все произведенные изменения над документом удаляются и документ возвращается в архив. В этом случае рабочая копия удаляется с рабочего стола, а в архиве остается та копия документа, которая была до изменений. Команда не доступна для группы компонентов.

записывает изменившиеся файлы документа в базу данных. Если же файлы на диске более старые, чем находящиеся в рабочей копии в базе данных, то **IPS** записывает на диск файлы из базы данных.

Таким образом, если один из пользователей, участвующих в коллективной работе, сделал какие-либо изменения, то при выполнении синхронизации его изменения будут записаны в рабочую копию документа в базе данных. При выполнении синхронизации документа другим пользователем изменившиеся файлы будут скопированы из базы данных на диск, что позволит этому пользователю увидеть изменения в документе.

Рассмотрим пример использования синхронизации документов. Существует сборочная единица **Рычаг регулировочный**, в которую входят две подсборки – **Вал** и **Привод управляющий**. Пользователю Иванову необходимо подкорректировать первую подсборку (**Вал**), а пользователю Петрову – вторую подсборку (**Привод управляющий**). Для этого каждый из пользователей должен взять на редактирование соответствующую подсборку, загрузить ее в **Cadmech** и выполнить необходимые операции. Однако удобнее было бы взять на редактирование всю сборку целиком, чтобы видеть, как изменения в подсборке влияют на компоновку всей сборки.

Недостатком такого подхода является то, что если один из пользователей, например Иванов, возьмет на редактирование основную сборку (**Рычаг регулировочный**), то **IPS** не позволит взять эту же сборку на редактирование пользователю Петрову.

Для решения этого затруднения предназначен так называемый режим совместной работы над документами. При его использовании документ, который взят на редактирование одним из пользователей (в приведенном примере это сборочная единица **Рычаг регулировочный**), может быть открыт в CAD-системе другим пользователем. Второй пользователь сможет вносить изменения в подсборки и детали основной сборки, если те не взяты на изменение первым пользователем.

Первое отличие режима совместной работы от открытия на просмотр взятой на редактирование сборки заключается в том, что сборка и входящие в ее состав подсборки и документы **IPS** помещаются не во временный каталог, а по путям хранения их рабочих копий.

Второе отличие заключается в том, что, одновременно работая над одной и той же сборкой, пользователи имеют возможность видеть изменения, вносимые в сборку другими пользователями без сохранения изменений в архивной копии документа или возврата документа в архив. Для этого используется специальная операция – **синхронизация** изменений.

***Примечание:** более подробно о совместной работе с документами см. в Руководстве пользователя системы **IPS**.*

### 3.2.15 Команда «Создать версию»

Команда **Создать версию** в дереве состава **PDMBrowser** активируется через контекстное меню для компонентов, входящих в состав сборки.

Вызов команды запускает процесс создания версии объекта в окне «**Создание версии объекта**». Затем, для внесения необходимых корректировок, модель открывается в собственном окне программы CAD.

### 3.2.16 Команда «Выбрать версию...»

С помощью команды **Выбрать версию...** в **Дереве состава** меняется одна версия компонента сборки на другую. Для выполнения операции необходимо выбрать компонент сборки, вызвать команду **Выбрать версию...**, указать версию в соответствующем окне списка версий **IPS**. При сохранении сборки в архив версия компонента сохраняется в составе сборки.

В случае, если в сборке выбрана не актуальная версия компонента, то при сдаче сборки в архив **IPS** выдаст соответствующее предупреждение.

В окне **Дерево состава** есть возможность отображать параметры **Версия** и **Статус версии** для состава сборки. В поле параметра **Версия** отображается номер версии документа. Данный параметр читается из атрибута документа **Номер версии** в **IPS**.

В зависимости от того, какая версия документа выбрана командой **Выбрать версию**, параметр **Статус версии** может принимать следующие значения:

- Актуальная версия. Более новых версий нет.
- ↑ Актуальная версия. Есть более новые версии.
- Конкретизированная версия. Более новых версий нет.
- ↑ Конкретизированная версия. Есть более новые версии.

***Примечание:** команда недоступна, если сборка открыта в контексте редактирования.*

### 3.2.17 Команда «Выбрать актуальную версию...»

Команда **Выбрать актуальную версию** в **Дереве состава** позволяет отменить конкретизацию версии. При этом в колонке **Версия** поля **Дерева состава** будет отображаться номер актуальной версии. В колонке **Статус версии** будет отображаться статус актуальной версии (зеленый кружок) (см.п.[3.2.15](#)).

***Примечание:** команда недоступна, если сборка открыта в контексте редактирования.*

### 3.2.21 Команда «Связать с объектом IMBASE»

Команда **Связать с объектом IMBASE** позволяет сопоставить компонент CAD-системы с элементом справочно-информационной базы данных **IMBASE**. В этом случае параметры, имеющиеся в базе данных **IMBASE** для выбранной записи, будут переданы в свойства компонента CAD-системы.

Например, мы имеем модель болта, у которой не заполнены параметры компонента (наименование, покрытие и пр.). Соответственно при создании спецификации на узел, в который он входит, мы не получим о нем записи в соответствии с ЕСКД (Болт M10-6gx35 OCT 37.001.123-75). Если же мы свяжем этот болт с записью в базе данных **IMBASE**, то при создании спецификации вся информация о данном стандартном изделии будет передана из нее.

### 3.2.24 Команда «Примечание для СП»

Иногда появляется необходимость, чтобы несколько экземпляров одной детали передавались в спецификацию как отдельные записи, а не суммировались. ### 3.2.25 Команда «Создать доп. замены...»

С помощью команды **Создать доп. замены...** ![](36f06f5166699f74ba8f4d48e635dcb0_img.jpg) создаются допустимые заменители для документа либо для группы документов. В **Дереве состава** могут создаваться допустимые замены следующих конфигураций:

- Одна позиция может заменяться на другую позицию.
- Одна позиция может заменяться на несколько других позиций, используемых совместно.

3. В появившемся окне ввести нужное количество вариантов доп. замен, в **Дереве состава** выбрать компоненты состава варианта при помощи кнопок:

### 3.2.29 Команда «Создать компонент...»

По команде **Создать компонент...** ![](f4a0621425c41ac5740861def630d6a7_img.jpg) в **IPS** создается новый документ (модель детали или сборки), после чего он добавляется в состав сборки в **Дереве состава** и в модели. При вызове команды в **IPS** появляется стандартный диалог создания нового документа.

После создания компонента в мастере создания **IPS** необходимо выполнить его позиционирование в сборке в CAD-системе. Компонент может быть размещен в пространстве модели либо с привязкой к ребру другой детали либо свободной вставкой в любом месте рабочей области. Аналогичная команда находится на панели инструментов **PDM**.

### 3.2.30 Команда «Создать новый документ»

Команда **Новый документ** ![](3f41268aaa93dab4a01c59fb2f124f87_img.jpg) располагается на панели быстрого доступа к командам **PDM**. При помощи данной команды происходит создание нового документа в системе **IPS**. В отличие от команды **Создать компонент**, новый документ не добавляется в сборку и в **Дерево состава**, а открывается в новом окне CAD-системы для последующего ее редактирования.

Данная команда отсутствует в контекстном меню **PDM Browser**.

## 3.3 Формирование состава доработанной сборочной единицы

В дереве состава **PDMBrowser** предусмотрена возможность формирования структуры **Доработанной сборочной единицы**, включая установку следующих признаков:

- Дорабатываемое изделие;
- Снимаемая составная часть;
- Вновь устанавливаемая составная часть.

**Доработанная сборочная единица** — изделие, изготавливаемое путём доработки другого изделия. В системе **IPS** представляет собой объект типа **«Доработанная сборочная единица»**, относящийся к родительскому типу **«Сборочная единица»**.

**Дорабатываемое изделие** — изделие, подлежащее доработке с целью получения **Доработанной сборочной единицы**. Включается непосредственно в её состав. В качестве дорабатываемого изделия может использоваться любой объект, относящийся к типу **«Изделия»** (включая **«Стандартные изделия»**, **«Прочие изделия»**, **«Детали»** и др.)

Для формирования состава доработанной сборочной единицы необходимо предварительно активировать соответствующий режим:

1. На панели инструментов окна **PDMBrowser** выбрать команду **«Настройки»** ![](d04ca4a7c96119cae88e9f94326d51f5_img.jpg).
2. В открывшемся окне перейти на вкладку **«Дополнительно»**.
3. Установить флаг **«Разрешить режим „Доработанная сборочная единица“»**.

Рассмотрим описание основных параметров **Карточки записи**:

- **Обозначение** – обозначение документа. Обязательное поле для заполнения перед передачей данных в **AVS**. Если документ сдан в архив, редактирование параметра недоступно.
- **Наименование** – наименование документа. В случае если документ не взят на редактирование, параметр нельзя изменить.
- **Раздел СП** – раздел спецификации, в который должен войти указанный компонент. После сдачи детали в архив атрибут становится недоступен для редактирования. Обязательное поле для заполнения перед передачей данных в **AVS**.
- **Позиция** – номер позиции компонента в спецификации. Параметр может передаваться из **AVS** или может быть заполнен вручную.
- **Количество** – в поле можно указать необходимое количество компонентов, входящих в сборку. К примеру, в сборку для упрощения могут не вставляться некоторые детали. Допустим, в сборке существует 50 винтов, но в спецификации необходимо заложить некоторый запас. Для этого в поле **Количество** необходимо указать нужное число винтов с запасом. При этом в поле **реальное** будет указано действительное количество компонентов в сборке, которое нельзя изменить в **Карточке записи**. В окне **PDM Browser** в поле **Количество** в скобках также будет указано реальное количество компонентов. При указании количества так же можно указать единицы измерения, которые выбираются из выпадающего списка. В таком случае в поле **Количество** рядом с количеством будут прописаны и единицы измерения.

***Примечание:** крепежные элементы в системе **Cadmech КОМПАС-График** формируются автоматически в двух проекциях – вид «в плане» и вид «в профиль». В случае, если в проекции «в плане» добавлено более одного элемента, то в **Карточке записи** необходимо в поле **Количество** указать необходимое количество компонентов.*

- **Материал** – поле отображает выбранный материал. Параметр недоступен для редактирования в **Карточке записи**. Изменить или добавить материал можно в окне **PDM Browser** или через команду **Задать параметр** (см.п.[3.2.5](#)).
- **Масса** – отображает массу компонента. Параметр записывается в **Карточке документа** из CAD-системы, и его также можно изменить в **Карточке записи**.
- **Исполнение** – исполнения сборки, в которых используется указанный компонент. Поле недоступно для редактирования.
- **Примечание** – графа, в которой записываются дополнительная информация для изделия (формат, единица измерения, масса и т. д.).
- **Код ОКП** – поле предназначено для ввода кода объекта по классификатору ОКП. В **Карточке записи** поле недоступно для редактирования.
- **Формат** – формат чертежа компонента. В поле **Карточки записи** параметр может вводиться вручную для деталей.

С помощью команды контекстного меню **Данные из спецификации...** ![](dc3095de6dc3b5f4ac1918489af7552c_img.jpg) либо аналогичной команды на панели инструментов **Объединить с данными из спецификации** изменения каких-либо параметров, которые были сделаны в спецификации в рабочей папке обновляются и появляются в составе сборки **PDM Browser**.

Рассмотрим случай использования команды на примере создания записи в **AVS** и добавления ее в сборку CAD-системы:

1. В раздел спецификации необходимо добавить деталь, которой нет в составе изделия. Для этого в **AVS** в контекстном меню раздела **Детали** вызываем команду **Создать запись**. В окне **Создание записи** вводим необходимые параметры и добавляем запись в раздел. После чего выполняем в **AVS** команду **Связать с CAD**. Далее переходим в CAD-систему командой **Вернуться в CAD-систему**.
2. Вызываем окно **PDM Browser** в режиме **Спецификации**. По команде **Объединить с данными из спецификации** происходит синхронизация изменений, и добавленная запись появляется в составе сборки в **PDM Browser**. Запись, добавленная из спецификации, обозначается значком статуса ![](61053c3370843795c92b06068ebd93d4_img.jpg) - виртуальный элемент (добавлен из AVS).

Так как для записи не создан файл на диске, то в поле вместо имени файла прописывается **Запись, созданная в AVS**. Все остальные параметры (Обозначение, наименование...) заполняются в соответствии с введенными данными в спецификации.

3. Далее необходимо создать файл в рабочей папке для записи и добавить ее в сборку в CAD-системе. Для этого в контекстном меню для детали выполняем

команду **Добавить в сборку**. Затем в окне указываем рабочую папку для сохранения модели. В результате в дереве изделия CAD-системы появится добавленная деталь. Вставка в сборку детали производится ( в зависимости от CAD-системы) либо в центр системы координат, либо компонент позиционируется в сборке при помощи указателя мыши (перемещается за курсором).

**PDM Browser** существует команда **Разбить по выноскам** ![](fee2cf1b4e911a36481719eb4dba7ae3_img.jpg). Кнопка доступна на панели инструментов и в контекстном меню для компонента сборки.
