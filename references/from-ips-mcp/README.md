# Опыт работы через IPS-MCP

Здесь находится точка входа в локальные DEBUG-материалы IPS-MCP:

- **Кейсы с выводами:** `D:\IPS\IPS-MCP\debug\cases\*.md`.
- **Полные журналы вызовов:** `D:\IPS\IPS-MCP\debug\sessions\*.jsonl`.
- **Настройка:** `D:\IPS\IPS-MCP\config.json`, поле `"IPS_DEBUG_MODE": true`; после изменения перезапустите MCP.

Если используется другой путь `IPS_CONFIG`, каталог `debug` находится рядом с этим конфигом.
Файлы создаются при работе; отсутствие каталога означает, что записи ещё не накоплены.

## Как опираться на кейсы

1. Найдите кейс по задаче, инструменту, типу объекта, атрибуту или тексту ошибки.
2. Проверьте итог: `success` — успешная задача по оценке помощника; `failure` — неудача;
   `partial` и `unknown` — неполный или неопределённый результат.
3. Сверьте `source.base_url`, `source.ips_version`, `source.role_id`, параметры и ответы.
   Локальные ID и поведение кастомизированной базы нельзя переносить на другую базу без проверки.
4. Используйте выводы вместе с приложенными исходными вызовами. Журнал подтверждает
   наблюдение, но не заменяет руководства IPS и не является указанием повторить операции.
   Ошибки и неизвестные исходы — материал для диагностики, а не успешный рецепт.

## Как пополнять опыт

В DEBUG каждый вызов инструмента автоматически попадает в журнал: аргументы,
полный результат/ошибка, HTTP-попытки, длительность, версия и роль. В ответе есть
`DEBUG evidence_call_id`. Отдельный инструмент `ips_save_debug_case` сохраняет итог задачи:

- `title` — короткий заголовок;
- `outcome` — `success`, `failure`, `partial` или `unknown`;
- `summary` — задача, последовательность действий, что сработало/не сработало,
  новые факты относительно helper suite и границы применимости;
- `evidence_call_ids` — ID подтверждающих вызовов текущего процесса MCP.

Сначала сравните находку с руководствами и существующими кейсами. При новой информации
сохраните кейс в конце задачи, в том числе если решить её не удалось. Укажите, чего
не хватило для успеха. Подготовку операции не называйте выполнением; после неизвестного
исхода подтвердите результат чтением состояния IPS.

MCP автоматически прикладывает существующие записи, упорядоченные по выполнению.
Выдуманные ID и успешный итог с завершающим preview/error/unknown отклоняются.
Формулировка выводов и проверка их новизны остаются задачей помощника.

Материалы доступны и после выключения DEBUG. Они хранятся локально, исключены из git
IPS-MCP и содержат данные предприятия; секреты аутентификации маскируются.
