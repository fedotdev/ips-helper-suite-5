# Общие правила IPS-MCP

- Используйте базовые имена `ips_get_*`. В вашем клиенте к базовому имени может добавляться префикс сервера (например в opencode — `ips_ips_get_*`); сверяйтесь со списком инструментов вашего клиента.
- `composition_tree`: глубина до 3, до 500 узлов, до 10 разворачиваемых `object-link`.
- Для списков используйте пагинацию с `page_size` до исчерпания страниц.
- Для технолога по умолчанию — не более 25 вызовов MCP на запрос; после каждых 10 вызовов показывайте промежуточный результат. Другие скиллы наследуют это правило при обходе состава.
- Результаты ограничены правами сервисного аккаунта и его ролью.
- Роль выбирается инструментом `ips_set_role`: `techno` = `IPS_ROLE_TECHNO_ID` (чтение), `prog` = `IPS_ROLE_PROG_ID` (запись). Роль общая на процесс MCP — технолог в начале сессии возвращает `techno`, программист перед записью ставит `prog`; проверка через `ips_get_current_user` (`roleVersionId`).
- Для технолога запись выключена без исключений.
- Для других скиллов запись двухфазная: вызывающий скилл сначала делает `prepare`, затем показывает пользователю операции, объекты, атрибуты и изменения и только после явного подтверждения вызывает `commit`.
- Двухфазный протокол применяется только если запись разрешена действующими инструкциями. Он не отменяет read-only-ограничение корневого `AGENTS.md`.
- Для Workflow проверяйте наличие файлового/экспортного инструмента отдельно: карточка объекта и его атрибуты не являются IWF-экспортом. На 2026-11-09 такой инструмент в подключённом MCP отсутствует; подробности — `skills/ips-workflow/references/iwf-format.md`.

## DEBUG MODE и повторное использование опыта

- Локальные кейсы IPS-MCP: `D:\IPS\IPS-MCP\debug\cases\*.md`. Инструкция и границы достоверности — `D:\parsing\IPS-Durdom-5\ips-helper-suite-5\references\from-ips-mcp\README.md`. Перед исследованием ищите подходящий кейс и проверяйте базу, версию IPS, роль и подтверждающие ответы.
- Флаг `IPS_DEBUG_MODE: true` в `D:\IPS\IPS-MCP\config.json` включает журнал после перезапуска MCP. В ответах появляются `DEBUG evidence_call_id`, в списке инструментов — `ips_save_debug_case`.
- После успешной или неудачной задачи с новыми находками сравните их с документацией helper suite и имеющимися кейсами. Сохраните через `ips_save_debug_case` задачу, последовательность шагов, ошибки, новые факты, вывод и применимость; передайте ID фактических вызовов этой задачи. Итог выбирайте честно: `success`, `failure`, `partial` или `unknown`.
- Preview подтверждает только подготовку. После `unknown`/`partial_unknown` успех можно описывать лишь после проверки фактического состояния. Ответ одного инструмента не доказывает завершение всей задачи.
- `ips_save_debug_case` сохраняет локальный Markdown, не меняет данные IPS и не требует переключения роли или включения write-инструментов. Без этого вызова подробные результаты остаются в `D:\IPS\IPS-MCP\debug\sessions\*.jsonl`.

## Локальная копия IPS-MCP

- При анализе интеграции IPS через MCP используйте репозиторий https://github.com/fedotdev/IPS-MCP.
- Если локальной копии нет, скачайте репозиторий в рабочую папку при наличии доступа к терминалу и сети.
- Если копия уже существует, проверьте локальные изменения перед обновлением и не перезаписывайте их.
- Сначала прочитайте инструкции репозитория, затем документацию, исходники и тесты.
- Если нужных инструментов нет, сообщите об этом ограничении.
