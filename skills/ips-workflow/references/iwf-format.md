# IWF: проверенный локальный контракт

## Происхождение и проверка

Основа локального компонента — предоставленный пользователем `iwf_unpack.py` для Python 3.10+
(получен из `C:\Users\fedor\Downloads\iwf_unpack.py` 2026-11-09).
Сохранены проверки zlib, Expat без DTD/сущностей, ограничение размера, эксклюзивное создание
и удаление незавершённого выхода. В сьюте добавлены потоковое чтение, фиксированная граница
выходного каталога, пакетный режим и локальная обратная упаковка. Внешних зависимостей нет.
Присланный `iwf_unpack_test_results.json` — результаты пользователя, не замена запуску тестов сьюта.

XML получен из IWF с началом zlib на смещении 0 (`78 9C`). Иные корректные zlib-заголовки
допускаются самой библиотекой. gzip, raw deflate, префикс перед zlib, усечённый поток,
хвост и второй поток отклоняются. Лимит XML — 20 971 520 байт; при декомпрессии разрешён
только один дополнительный байт для обнаружения превышения. `flush()` без лимита не применяется.

XML проверяется Expat с запретом DTD и деклараций сущностей и отключёнными parameter entities.
Неизвестная или неподдерживаемая кодировка — ошибка отдельного файла в JSON; пакет продолжает работу.
Парсер ничего не выполняет и не загружает ресурсы. Наличие текста сценария, XInclude или ссылки
на stylesheet не означает выполнение/раскрытие этих данных. Сохраняются исходные байты XML,
включая BOM, объявление кодировки и переводы строк.

Выходной путь фиксирован относительно **скрипта в репозитории**:
`output/business-processes`. Не переносите скрипт в каталог установленной копии скилла;
инструкции используют абсолютный путь к репозиторию. Проверка пути разрешает символьные
ссылки/junction и затем проверяет границу каталога; `xb` запрещает перезапись существующих файлов.
Двоеточие в компонентах выходного пути после корня диска запрещено: результат не может быть
именованным потоком NTFS существующего файла.
Это проверка пути в рабочем каталоге агента, не ОС-песочница для конкурирующего вредоносного процесса.

## Структура SimpleBriefcase

Изученные файлы имеют корень `SimpleBriefcase`, `xsi:type="SimpleBriefcaseClient"`, `Version=1`.
Это наблюдение по экспортам, не полная XSD-схема и не гарантия совместимости всех версий IPS.

| Участок | Смысл и правило сохранения |
|---|---|
| `Map/Items/Item` | Словари доменов (`ObjectTypes`, `Objects`, атрибуты и др.): локальный ключ, GUID, Caption, ObjectGuid. Не считать все ID идентификаторами объектов. |
| `Items/BriefcaseItem[@xsi:type='BriefcaseObject']` | Начало записи объекта: `ID`, `TypeID`, `Caption`, `LCStep`; `IsRoot` отмечает корневой шаблон. |
| Последующие `BriefcaseAttribute` | Атрибуты предшествующей записи объекта/связи до следующей такой записи. `ID` здесь — ID атрибута. |
| `BriefcaseRelation` | Запись связи: `ID`, `TypeID`, `ProjObjectID`, `PartObjectID`; может иметь собственные последующие атрибуты. |
| `Blob` | `Arc`, `RealFileSize`, Base64 `Binary`. Не изменять при правке описания. `NotPacked` и `Zstd` — внутренние кодеки, отдельные от внешнего zlib. |
| `CreateVariables` | Флаг контейнера; сохранять исходное значение, не менять по предположению. |

Не разбирайте этот формат как дерево вложенных действий. Для изменения одного описания
нужно сначала найти запись нужного объекта и границы её атрибутов. Редактирование только
`Map/.../Caption` не заменяет изменения записи в `Items`. Дубликаты/висячие ссылки, несогласованные
Map/Items, корень, отсутствующие исполнители и недостижимый «Стоп» требуют отдельной проверки схемы.

Упаковка `encode` сохраняет XML как есть и создаёт стандартный zlib-поток. Сжатые байты не обязаны
совпасть с исходным IWF при другой версии zlib; инвариант — побайтовый XML после обратного чтения.
Успех конвертера означает корректность XML и контейнера, не прохождение проверки бизнес-логики IPS.

- Шаблон `1293283`: «Согласование КД [2] Фадеева», тип `1133`, `readOnly=true`.
- Атрибут `1432` указывает на родительский шаблон `1150322` «Согласование КД Оригинал».

  по типу `1313` и атрибуту `1306 = 1293283` вернул четыре объекта.
- Нужное условие: **`1293318`**, «Формировать аутентичный файл?», описание пустое;

- `1331` «Условие перехода»: `ftShortBlob`; значение не вернулось через инструмент чтения
  атрибутов. `null` в поиске не доказывает, что формула пуста.
- `18009` «Формировать аутентичный файл»: `ftBoolean`. Формула локального родительского
  экспорта ссылается на него, но актуальная формула дочернего условия через MCP не проверена.
- Объекты связей между действиями: тип `1151`, поиск по `1306`. В записи связи:
  `1370` — начальный ID, `1371` — конечный ID, `1388` — числовой тип перехода.
  Исходящие из `1293318`: `1293350 → 1293315` «Формирование аутентичного файла» (тип 2),
  `1293352 → 1293290` «Стоп» (тип 3). Семантику чисел 2/3 отдельно не подтверждали.

Числовые ID локальны. Метаданные проверяются соответствующими `ips_get_*_type`,
а связи с конкретным процессом — фактическими значениями атрибутов.

### Чего текущий MCP не предоставляет

В обнаруженном каталоге нет инструментов скачивания/выгрузки IWF, чтения BLOB или импорта
модели Workflow. MCP-ресурсы также отсутствуют. Не представляйте локальную копию родительского
экспорта как скачанный IWF объекта `1293283`.

В локальном OpenAPI IPS-MCP есть обычный файловый endpoint
`GET /core/api/files/objects/{objectId}/files/{blobId}`, но он не опубликован MCP-инструментом,
а наличие такого endpoint не доказывает, что шаблон хранится как готовое IWF-вложение.
`POST /core/api/briefcase/StartExport` описывает иной экспорт с серверным путём/категориями;
не запускайте его вместо выгрузки одного процесса. Источник: `D:\IPS\IPS-MCP\swagger.json`.

Отдельные текстовые атрибуты могут иметь preview/commit-контракт даже при отсутствии
выгрузки IWF. Подготовка preview для `1293318`, атрибут `7`, успешна; commit в этой сессии
не выполнялся из-за действующего read-only-ограничения корневых инструкций.
