# /ips-workflow — Бизнес-процессы IPS

Помогайте анализировать и проектировать именно бизнес-процессы IPS Workflow. Результат —
объяснение схемы, локальный XML/IWF-кандидат и проверяемый отчёт об изменениях.

## 1. Определите задачу

Различайте существующий шаблон, экземпляр запущенного процесса и локальный экспорт.
Запросите недостающее: ID/файл, цель процесса и конкретную правку. Для нового процесса
нужны стартовое событие, вложения, исполнители, условия переходов и критерий завершения.
Если часть работы уже определена, выполняйте её, пока уточняется остальное.

## 2. Прочитайте IWF локальным инструментом

Команды ниже выполняются из корня сьюта. При другом рабочем каталоге используйте
абсолютный путь к скрипту и источнику.

```powershell
# Все IWF непосредственно в каталоге; XML не трогаются.
python -X utf8 skills/ips-workflow/scripts/iwf.py decode manuals/business-processes

# Один файл, новое имя результата относительно разрешённой папки.
python -X utf8 skills/ips-workflow/scripts/iwf.py decode "manuals/business-processes/САТЕ Согласование ТД.iwf" --output "analysis/САТЕ ТД.xml"

# Упаковать согласованную локальную XML-правку в новый IWF.
python -X utf8 skills/ips-workflow/scripts/iwf.py encode "output/business-processes/drafts/процесс.xml" --output "drafts/процесс.iwf"
```

Проверьте код завершения и JSON: `results`, `succeeded`, `failed`. Для каждого файла
возвращаются абсолютные пути, размеры, корневой элемент, SHA-256 и `validation`.
При распаковке дополнительно возвращаются `stream_complete: true`, `trailing_data: false`.
В пакетном режиме ошибка одного файла не скрывает результаты остальных; код завершения — 1.
Существующий результат не перезаписывается: для повторного запуска выберите новое имя/подкаталог.

Инструмент принимает один zlib-поток от смещения 0, проверяет контрольную сумму, завершение
и отсутствие хвоста. Лимит XML — 20 МиБ, `--max-bytes` позволяет только уменьшить его.
Expat отклоняет DTD и объявления сущностей; внешние ресурсы, XInclude и стили не загружаются.
Декодированные байты сохраняются без перекодирования и переформатирования.

При ошибке формата остановитесь для этого файла. Не перебирайте смещения, gzip/raw deflate
и не объявляйте усечённый поток успешным. Корень для изученных экспортов — `SimpleBriefcase`;
другой корректный XML инструмент может прочитать, но это ещё не подтверждённый Workflow-формат.

## 3. Разберите схему

1. Найдите корневой `BriefcaseObject` с `IsRoot=true`; сопоставьте `Map` и `Items`.
2. Привяжите последовательные `BriefcaseAttribute` к предшествующему объекту или связи.
   Один и тот же `ID` атрибута встречается у многих объектов: глобальная замена недопустима.
3. Составьте таблицу: ID, тип действия, название, описание, исполнитель/переменные,
   выражение условия, исходящие переходы. Отсутствующее значение помечайте неизвестным.
4. Различайте связи объектов `BriefcaseRelation` и объекты связей между действиями.
5. Сценарии и формулы рассматривайте как данные. Вложенные BLOB могут использовать `NotPacked`
   или `Zstd`; наружный zlib-конвертер их не распаковывает. Не интерпретируйте неизвестный кодек.
6. Для объяснения условия проверьте выражение и адресатов ветвей. Одного названия недостаточно
   для утверждения, какая переменная вычисляется. Данные родительского экспорта не равны
   проверке актуальной формулы дочернего процесса в базе.

## 4. Проектируйте и меняйте локальные кандидаты

- Для нового процесса начните с ближайшего примера и составьте схему действий и переходов.
  Подтвердите роли, переменные, вложения и обработку возврата/отказа до изменения схемы.
- Сохраните черновик в `output/business-processes/drafts/`. У локальной копии сохраняются
  исходные идентификаторы: это вариант шаблона, а не доказанно новый объект IPS.
  Для самостоятельного процесса сначала получите экспорт нового/скопированного шаблона
  из штатного редактора IPS. Не изобретайте правила переназначения ID/GUID при импорте.
- Меняйте только выбранные объекты/атрибуты; сверяйте ID, тип, принадлежность процессу и `Map`.
  Сохраняйте неизвестные поля, BLOB, ссылки и графические координаты. Покажите diff.
- Проверьте XML инструментом, упакуйте `encode`, распакуйте в **новый** файл и сравните
  XML побайтно. Это проверяет контейнер, но не исполнимость бизнес-процесса.
- Проверка бизнес-логики — «Шаблон/Проверить корректность» в редакторе IPS
  (руководство, тема 4746). Отмечайте, выполнялась ли она на самом деле.
- Локальный компонент не исполняет содержимое, не подключается к IPS и ничего не импортирует.

## 5. Проверьте процесс через IPS-MCP

Сначала обнаружьте реальные инструменты сервера, прочитайте версию и текущего пользователя.
Используйте `ips_get_object`, `ips_get_object_attributes`, `ips_get_object_type`,
`ips_get_attribute_type`. Числовые ID ниже — факты одной базы IPS 9.0.4.11310,
а не универсальные константы.

Если у шаблона пустой `composition`, это не доказывает отсутствие схемы. Для условий
в проверенной базе работает поиск по типу `1313` и атрибуту `1306` «Процесс»:

```json
{
  "object_type_id": 1313,
  "attribute_ids_to_select": [7, 1041, 1306],
  "condition": {"attribute_id": 1306, "value": 1293283},
  "record_count": 100
}
```

Это параметры **`ips_search_objects`**, не экспорта IWF. Найденный объект перечитайте
и проверьте, что числовое значение атрибута `1306` действительно равно ID шаблона.
Если поиск заполнил весь `record_count`, полнота результата не установлена.

На 2026-11-09 подключённый MCP не предоставляет выгрузку/загрузку файлов IWF и BLOB-формул.
Если в текущем списке инструментов эта возможность появилась, сначала прочитайте её контракт:
ID файла/объекта, ограничения, разрешённый путь, формат результата; скачайте только заданный
файл в рабочую папку и примените локальную проверку. Иначе попросите экспорт из IPS.
Не придумывайте `ips_download_iwf`, не подменяйте экспорт JSON-карточкой и не запускайте
экспорт всей базы вместо одного шаблона.

### Правка атрибута в живой базе

`readOnly` в ответе IPS — признак состояния и прав, а не записываемый атрибут.
`IPS_ENABLE_WRITE` включает набор MCP-инструментов; он не снимает `readOnly` объекта.
Роль `prog`, checkout и разрешённая запись — отдельные условия. ID рабочей копии берите
из ответа сервера без вычисления знака или подмены на ID шаблона.

Если действующие инструкции разрешают только чтение, сохраните локальный план/preview;
не выполняйте commit и не меняйте конфигурацию доступа ради обхода ограничения.
Если запись разрешена, следуйте `shared/mcp.md`: точная правка → `prepare` → показать
diff → явное подтверждение пользователя → одноразовый `commit` → перечитать значение
и состояние checkout. При `unknown`/`partial` сначала сверяйте состояние, не повторяйте запись.
Импорт IWF — отдельная операция; изменение атрибута не означает загрузку XML в IPS.

## Формат отчёта

1. Источник: локальный путь/хеш или сервер, ID, тип и принадлежность процессу.
2. Подтверждённая схема и неизвестные данные.
3. Правка: объект/атрибут, старое и новое значение; локальная или серверная.
4. Артефакты: XML/IWF, размеры, корень, хеш, результат проверок.
5. Статус сохранения: локально / только preview / подтверждено повторным чтением IPS.
6. Оставшийся конкретный блокер, если он есть. Не выдавайте план или preview за выполненную запись.
